# 241. 工具多时，Agent如何避免选错

> 来源：豆包会话 https://www.doubao.com/chat/38451449744017410 两轮回复。
> 视频：https://www.douyin.com/video/7660693500581885642

## 核心观点

不要只改Prompt或把全部工具平铺给模型。将工具选择设计为召回、重排、约束、验证组成的路由系统。

## 落地步骤

1. **描述规范**：写清适用场景、输入要求、禁止场景及反例，减少相似工具误用。
2. **业务分层**：先识别用户服务、订单履约、知识检索、数据分析等业务域，只提供相关候选工具。
3. **召回与重排**：关键词、Embedding、规则召回一批候选；再用模型排序过滤，降低漏选和选错。
4. **执行前校验**：检查参数、权限及风险。退款、删除、改配置、发邮件等有副作用的操作，按风险增加人工确认及回滚判断。
5. **轨迹复盘**：记录工具调用轨迹，为后续分析与迭代提供依据。

## 示例

用户查询投诉记录，候选可能包括客户档案、工单、订单查询。重排后优先选择工单查询，再做参数和权限校验，而不是直接执行任意候选。

## 面试口述

工具数量多时，我会先规范描述并按业务域分层，再用召回加重排缩小候选池；执行前做参数、权限和风险校验，最后记录调用轨迹用于复盘。工具选择不仅是Function Calling，更是完整的工程路由问题。
