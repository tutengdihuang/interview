## 核心结论

复杂多模态创作不能只串接几个模型接口，需要结构化输入、明确中间资产、可检查的执行步骤，以及反馈与局部回滚闭环。

## 端到端链路

需求解析 → 大纲 → 角色卡/场景卡 → 剧本 → 分镜 JSON → 提示词拼装 → 图片/视频生成 → 配音字幕与合成 → 质量评估。

## 关键工程设计

1. **入口统一 Schema**：提取题材、时长、平台、故事钩子、视觉风格、必须满足和禁止事项。后续节点共享同一份规格。
2. **节点明确输入输出**：剧本、角色、场景、分镜分别产出可保存的中间资产，而不是一次性黑盒生成。
3. **一致性约束**：角色卡固定外貌与服装，场景卡固定风格；分镜控制动作、表情、景别等镜头变量。
4. **结构化评估反馈**：剧本评估关注节奏和冲突，分镜评估关注生成可行性与构图逻辑；失败输出具体修改意见。
5. **局部回滚与循环上限**：只重跑受影响节点，限制最大迭代次数，避免无界循环。
6. **项目状态持久化**：第一轮另提到保存需求、资产、版本、依赖关系、评估报告与重试记录，用于定位故障和增量更新。

## 面试口述

我会把系统设计成受工程约束的多智能体创作管线。入口先将模糊需求转成统一 Schema，再拆成剧本、角色、场景、分镜等节点。角色卡、场景卡和分镜 JSON 约束多模态生成的一致性；评估器输出结构化修改意见，编排层按依赖局部回滚，并限制迭代次数。中间资产和版本持久化，支持恢复、增量更新与复盘。
