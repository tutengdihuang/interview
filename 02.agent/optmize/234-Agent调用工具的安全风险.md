## 核心风险

据豆包回复，工具型Agent会把语言输出变成真实业务动作。风险不只是回答错误，而是不可信外部内容被模型当作指令，诱发发邮件、改数据、删文件或泄密等误调用。

文档、网页和工具结果与系统规则混在同一上下文，是回复强调的间接提示词注入入口。外部内容中的指令性文本应当被当作数据，而非新的授权。

## 四层防御

1. **上下文信任分层**：区分系统规则、用户请求和外部文档；不把网页、检索结果等不可信内容提升为系统规则。
2. **工具最小权限**：按读、写、删除、外发拆分能力，避免万能工具；高危修改及外发动作二次确认。
3. **执行前校验**：模型提出调用参数后，由后端校验参数、用户权限、目标对象和业务状态；查询合同与向外部邮箱发送合同应有不同审批要求。
4. **审计回放**：记录模型所见上下文、工具选择、参数、审批人和返回结果，支撑事故定位。

## 面试口述整理

工具型Agent最大的风险，是将不可信内容转化为真实业务动作。我会从上下文信任分层、工具最小权限、执行前校验、高危动作审批以及全链路审计来设计边界，而不是只依赖提示词或模型自行判断权限。
