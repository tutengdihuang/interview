## 一句话结论

区分关键是**下一步动作的控制权**，不是有没有调用工具。

## 核心对比

| 维度 | Workflow | Agent |
| --- | --- | --- |
| 路径 | 预定义步骤和分支 | 模型结合目标与反馈选择下一步 |
| 模型角色 | 流程中的处理节点 | 受约束的运行时决策者 |
| 优势 | 稳定、可控、可审计 | 灵活处理不确定路径 |
| 典型用途 | 审批、支付、权限校验、受控写入 | 检索、排查、规划、诊断 |

## 咖啡例子

- Workflow：下楼 → 指定店 → 点冰美式 → 付款 → 返回；门店关闭时，只有预设异常分支才能处理。
- Agent：目标是让老板喝上咖啡；发现门店关闭后，按反馈选择外卖、便利店或询问替代饮品。

## 工程选型

主流程与关键动作由 Workflow 控制；局部不确定判断交给受约束的 Agent。例如客服系统中退款和建工单走固定流程，理解诉求与搜集资料允许模型动态决策。

## 面试口述

Agent 和 Workflow 都可以调用工具，区别在于谁控制下一步。Workflow 的路径由程序定义，模型在节点内执行任务；Agent 根据目标、观察与反馈动态选择行动。真实业务通常采用混合方式，让 Workflow 守住主干和安全边界，Agent 处理局部不确定环节。
