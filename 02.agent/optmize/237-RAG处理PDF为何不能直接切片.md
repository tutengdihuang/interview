# 237. RAG处理PDF为何不能直接切片

## 核心观点

PDF解析不只是提取文字，还应保留结构、阅读顺序及来源位置。直接转纯文本并固定长度切片，可能破坏章节归属、表头与数据关系，影响召回与引用。

## 三类文档分流

- **原生文本PDF**：提取文字并保留标题层级、页码、坐标、阅读顺序；避免页眉页脚混入正文。
- **扫描PDF**：OCR结合版面分析，识别标题、正文、图片、表格，关注错字与串行造成的污染。
- **图文混排及复杂表格PDF**：识别表格结构，转换成Markdown或JSON，保留表头和单元格关系。

## 处理链路

1. 按文档类型选择解析方式。
2. 按章节、段落、完整表格等结构与语义单元切片；跨页表格、大图单独处理。
3. 随chunk保存文件名、版本、生效时间、章节、页码、坐标、表格编号、访问权限等元数据。
4. 豆包第二轮还提到关键词与向量混合召回、重排，以及生成时引用元数据出处。

## 元数据的价值

- 为答案提供页码及来源，支持溯源。
- 过滤过期版本。
- 做权限过滤，避免越权召回。

## 面试口述

PDF是版式文件，直接转纯文本容易丢失阅读顺序、章节与表格关系。我会先区分原生、扫描及图文混排文档：原生保留结构与位置，扫描件做OCR和版面分析，表格结构化解析。之后按结构与语义单元切片，保留版本、页码和权限等元数据，支持检索过滤与引用。解析质量是RAG可靠性的基础，不能只关注向量库和Embedding模型。
