# 239. 并行采样与束搜索：按任务目标选解码策略

## 核心区别

- **并行采样**：同一输入独立生成多份完整候选，在答案层面获取多样性。适合创意文案、脚本、开放问答和方案构思；候选质量不齐，需配合筛选或重排。
- **束搜索（Beam Search）**：逐 token 扩展、保留若干高分路径。回复将其定位为偏稳定的搜索方式，用于翻译、摘要和结构化任务；候选可能相似，表达偏保守。
- **贪婪解码**：每一步只取最高概率 token，可理解为束宽为1的情况；回复强调其速度优势及多样性不足。

## 选型与落地

1. 先判断任务更看重多样性还是稳定性，而不是比较技术名字。
2. 并行采样需要明确候选如何打分、筛选；仅生成多份再随机挑选，未必有收益。
3. 创意任务不能只靠加大束宽获得明显不同的思路。
4. 将解码、重排、规则校验一起评估，关注效果、算力成本和延迟。

## 面试口述

并行采样对同一个输入多次完整生成，主要换取候选多样性；束搜索在逐 token 生成时保留高分路径，主要做受控搜索。前者适合开放创意任务，并需要有效筛选；后者偏向稳定表达，但候选可能较为相似。业务上要联合评估重排、校验、延迟与成本。

## 阅读边界

豆包将高概率路径、稳定性、准确性联系起来，并对成本和Reranker必要性作了概括。这些是本次采集回复的表述，不应解读为束搜索必然正确、不会跑偏，或各任务下成本关系已得到实测证明；本次未对这些结论作独立验证。
