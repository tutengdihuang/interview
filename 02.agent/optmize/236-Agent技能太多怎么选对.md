# 236. Agent技能太多怎么选对？

> 来源：豆包会话 https://www.doubao.com/chat/38450871241658882 的两轮回复。
> 视频：https://www.douyin.com/video/7661443844164825946
> 未独立核验原片；以下仅为已取得豆包回复的整理，不视为原片逐字稿。

## 核心结论

技能数量增加后，应把技能选择当作检索路由问题，而不是不断增加提示词。建立“召回—筛选—确认—反馈”的路由链路，先缩小候选范围，再选择技能。

## 工程方案

1. **结构化技能元数据**：适用任务、输入类型、输出格式、前置条件、禁用场景、示例问题。
2. **两级召回**：关键词、标签、规则做粗筛；Embedding或小模型做语义匹配。豆包提醒全量向量召回可能混淆名称相近、能力不同的技能。
3. **记录选择理由**：记录任务所需能力、候选匹配点及最终选择依据，用于可观测性和错误分析。
4. **失败反馈**：把误选样本加入评测集，检查描述、标签、负例及相邻技能边界，避免只临时改Prompt。
5. **按任务域分层加载**：先确定代码修复、文档处理、视频审核、数据分析等任务域，只加载相关技能，降低上下文干扰。

## 面试口述

技能变多后，我会把选择过程设计为检索路由：为每个技能维护结构化元数据和适用边界，先用标签、规则粗筛，再做语义召回与模型选择，保留简要选择依据便于排错。线上把误选样本沉淀成评测集，持续优化技能描述与职责边界，并按任务域加载候选技能，而不是一次暴露全部技能。

## 易错点

- 技能库越大不代表选择越准确。
- 名称相似不能作为功能等价的依据。
- 误选可能来自技能职责重叠，不应一律归咎于模型能力。
