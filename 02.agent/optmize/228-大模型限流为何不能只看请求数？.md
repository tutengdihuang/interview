# 228. 大模型限流为何不能只看请求数？

## 核心结论

同样一次请求，输入长度、输出长度与执行时间可能差异很大。只限制QPS无法充分约束大模型资源占用和成本，应结合Token配额与并发控制。

## 三个控制维度

| 维度 | 主要作用 |
| --- | --- |
| 请求频率 | 限制短时间大量调用，保护入口 |
| Token配额 | 约束输入输出规模与使用成本 |
| 并发槽位 | 限制同时执行的任务，防止长请求持续占用资源 |

短问题和长文档报告都算一次调用，但所需资源并不相同。仅按请求次数限流可能误伤轻请求，却无法阻止少量重请求造成资源压力。

## 输入与输出要区分

- 长输入：影响预填充阶段和上下文内存占用。
- 长输出：增加解码生成工作与等待时间。
- 配套措施：最大输入长度、最大输出长度、用户每日Token额度、高峰动态降额，以及用户等级策略。

## 面试口述

大模型限流不能只看QPS，因为请求次数不能体现上下文长度、生成长度和并发占用时间。同样一次调用，短问答与长文档生成的资源成本差别很大。通常应结合请求频率、Token配额和并发槽位，区分输入与输出Token，再按用户等级和高峰负载调整策略。
