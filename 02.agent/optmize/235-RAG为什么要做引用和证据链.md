# 235. RAG为什么要做引用和证据链？

> 来源：豆包独立会话 https://www.doubao.com/chat/38451106691320834 的两轮回复。
> 视频：https://www.douyin.com/video/7661809103644019675
> 未独立核验原片；以下为取得回复的结构化整理，不保证豆包声称的“完整字幕”与原片一致。

## 核心结论

引用不是答案装饰，而是把关键结论与具体证据片段绑定，使RAG可核对、可定位问题、可自动评估。

## 三类价值

- 用户：核查结论依据。
- 开发：区分检索、重排与生成阶段的问题。
- 系统：用证据检验召回、忠实度及结论覆盖情况。

## 四个工程环节

1. **保留元数据**：chunk附带文档名、页码、章节、时间、权限标签，不能只存文本。
2. **筛选证据**：选择相关、不冲突、粒度清晰的片段，避免把全部召回内容塞入上下文。
3. **答案与证据对齐**：每条关键结论对应具体片段，避免先生成结论再随意挂来源。
4. **引用辅助评估**：检查是否召回所需内容、答案是否忠于原文、证据是否覆盖结论，用于定位链路故障。

## 面试口述

RAG做引用，是为了把生成结果与检索证据绑定，而不只是让答案看起来可信。切片时保存来源元数据，重排后筛选有效证据，生成时约束关键结论与片段对应，再借助引用评估召回和忠实度。这样用户能核查，开发者能定位问题，系统也能进行自动评估。

## 易错点

- 引用几个链接不等于形成证据链。
- 有来源不意味着来源实际支持结论。
- 制度、合同、医疗等场景中，缺少具体证据会增加错误定位难度。
