## 核心结论

长对话、高并发时吃掉显存的不是模型权重，而是 **KV Cache**。它的本质是“用显存（空间）换算力（时间）”：历史 token 的 K、V 在因果掩码下永远不变，可以缓存复用，新 token 只算自己这一步。代价是显存随上下文长度线性膨胀，并把推理瓶颈从算力推向显存带宽。

## 为什么需要 KV Cache

Decoder-only 模型是自回归生成：没有缓存时，每生成一个新 token 都要把整段历史重新跑一遍前向传播。

- 例子：提示词 3 个位置，生成 3 步分别处理 3、4、5 个位置，共 12 次位置计算，而真正新增的只有 3 个词。
- 放大到 1000 token prompt 生成 1000 token：朴素做法累计约 1,499,500 次位置计算，而只算该算的不到 2000 次，即 **99% 以上算力花在重算历史**。
- 自注意力单次复杂度是序列长度的平方，逐步重算全序列会让总计算量恶化为三次方级累加。

## 为什么历史可以缓存（复用依据）

关键不是“Transformer 没有循环隐状态所以不能只喂新词”，而是**因果掩码**：注意力矩阵右上三角被置为 −∞，每个位置只能看到自己和之前的词。

只要模型权重固定、前缀文本不变、位置编码规则确定，历史位置在每一层的输出就**具有时间不变性**，未来生成再多 token 也不会改变它。因此历史结果可以原样复用。

## 为什么只存 K、V，不存 Q

`Attention = softmax(QKᵀ/√d)V` 中三者职责不同：

- **Q**：当前位置发起的查询请求，只服务当前这一步，用完即抛；历史位置的 Q1/Q2/Q3 在各自生成时刻已完成使命，存下来只浪费显存。
- **K**：每个位置对外供匹配的标签；**V**：每个位置真正贡献的内容。新词的 Q 要与**全部历史 K** 打分、再对**全部历史 V** 加权，所以 K、V 是跨时间步被反复读取的资产。
- 也不能缓存注意力权重矩阵：换了新的 Q，点积结果整组不同，权重必须实时重算。

## Prefill 与 Decode 两阶段

| 阶段 | 输入规模 | 做什么 | 瓶颈 |
|---|---|---|---|
| Prefill | 整段 prompt（成百上千 token） | 并行算完，预测首个新词，并把每层 K/V 写入显存建立初始缓存 | 算力受限 Compute Bound |
| Decode | 每步 1 个 token | 只算该位置的 Q/K/V，K/V 追加到缓存末尾，用 Q 读全部历史 K/V，输出一词 | 访存带宽受限 Memory Bandwidth Bound |

有了 KV Cache，上例变成 1 次 prefill 处理 1000 位置 + 1000 步 × 1 位置 ≈ 2000 位置，计算量下降近三个数量级。

## 显存账（以 Llama2 70B 为例）

单 token 字节数 = 2 × 2 × 层数 × KV 头数 × 头维度（第一个 2 是每层存 K 和 V，第二个 2 是 FP16/BF16 每数 2 字节）。

- 标准多头：2×2×80×64×128 = 2,621,440 B ≈ **2.5 MB/token**。
- 4096 token 上下文 ≈ 10 GB；50 并发 ≈ 500 GB，仅 KV 就需要 7 张 80GB A100（不含权重）。
- 128k 上下文单用户可膨胀到约 320 GB。
- 正因如此，真实 Llama2 70B 用 **GQA**：每 8 个查询头共用一组 K/V，KV 头数 64→8，单 token 降到约 0.31 MB。

Decode 阶段每搬 1 字节约做 1 次计算，而 A100 需要约 150 次/字节才能喂饱计算单元，所以单卡本地推理“算力看着高、吐字上不去”，卡点是搬数据。

## 优化路线分层记忆

- 架构层：MQA / GQA 共享 K/V；DeepSeek MLA 低秩压缩。
- 系统层：PagedAttention（vLLM 核心），像 OS 内存分页那样把 KV Cache 切成块分配，减少碎片、提升并发吞吐。
- 算法层：KV 量化（FP16/BF16 → INT8/INT4）、FlashAttention/FlashDecoding、前缀缓存、滑动窗口注意力、投机采样。
- 目标统一：有限显存承载更长上下文、更多并发。

## 面试口述

自回归生成如果不用缓存，每步都要重算全部历史，位置计算量按长度平方级累加、总量退化成立方级，绝大部分算力浪费在重复劳动上。因果掩码保证历史位置各层输出永不改变，所以可以缓存复用。注意力的公式里 Q 只属于当前这一步、用完即抛，历史的 K 和 V 会被后续每一步反复读取，因此只缓存 K、V，叫 KV Cache；注意力权重也不能存，因为换了新 Q 权重就全变了。工程上分 Prefill 与 Decode：Prefill 并行建立缓存、算力受限；Decode 每步一个 token、要搬全部权重和 KV Cache，转为访存带宽受限。代价是显存随上下文线性增长，Llama2 70B 标准 MHA 约 2.5MB/token，4096 上下文就近 10GB，所以用 GQA/MQA/MLA 压缩头共享、PagedAttention 分页管理、KV 量化与投机采样来优化。一句话：KV Cache 是大模型推理的短期记忆，用显存换算力，是推理优化的共同出发点。
