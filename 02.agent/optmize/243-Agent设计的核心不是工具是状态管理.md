## 核心结论

工具提供动作能力，状态管理保证多轮任务连续推进。系统需要知道目标是否变化、步骤进度、信息是否过期、外部操作是否真实成功。

## 四类状态的职责

- **会话状态**：当前提问、判断与临时约束，仅服务当前会话；一次性口吻要求不自动变成长期偏好。
- **任务状态**：记录多步骤进度、尚未执行的工具、等待确认及结果生成情况，避免每轮从头推理或遗漏步骤。
- **用户状态**：身份、权限、客户等级、长期偏好、默认输出格式等结构化保存、确定性读取，不依靠聊天历史猜测。
- **外部系统状态**：付款、库存、数据库写入、邮件发送等事实，通过工具查询；关键决策不能依赖旧上下文。

## 写入规则

分别明确哪些状态可以由模型写入，哪些以工具返回为准；哪些仅本轮有效，哪些长期持久化；何时允许覆盖旧值。重点防止临时约束误入长期记忆，以及失效信息继续参与决策。

## 面试表达

Agent 首先是状态驱动系统，而不只是工具调用器。我会拆分会话、任务、用户和外部系统四类状态，为它们定义生命周期、读写权限及校验方式；任务状态跟踪执行进度，用户信息结构化读取，外部事实通过工具实时确认。
