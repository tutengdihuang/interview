一、核心误区：变脸不是 Prompt 写得不够细
很多人遇到 AI 短剧人物变脸，第一反应是把 Prompt 里面貌描述写得更详尽，但这是错误思路。
哪怕 Prompt 描述再细致，如果每次生成时给到模型的参考图片不一样，模型就会画出完全不一样的人物。问题根源不在提示词，而是角色素材、资产管理链路出问题。
这道面试题表面考察 Prompt 编写能力，实际考察是否懂得多模态角色资产工程化管理。解决核心思路：给每个角色做版本快照锁定，每一集生成都调用同一套审核完成的版本素材，而不是临时从文件夹随便找图使用。
二、三大核心解决步骤
1. 角色资产版本化（源头控制）
短剧是多集连续生产，同一个角色反复出场。
将角色全部视觉资产打包成版本包：外貌参考图、服装设定、表情素材、场景光照参考等全部收纳；
采用版本命名，例：角色A_v1.2_时间戳；
生成画面时，Prompt 不再手写一堆外貌文字，直接引用角色版本号，例如：“根据角色 A_v1.2 的参考素材生成画面”。
保证无论生成第几集，模型读取的是同一套角色素材，从源头减少变脸风险。
2. 入库前一致性校验（提前排雷）
就算素材打包，如果打包进来的图片本身形象就互相冲突，后续依旧会变脸。
美工海报、截图、网络参考图等不同来源图片，入库前做视觉相似度比对；
技术方式：抽取图像特征向量，计算向量距离；
规则：相似度低于设定阈值，系统直接拒绝素材入库，标记冲突，交给人工复核。
作用：在素材入库阶段就拦截形象不一致的图片，避免问题埋到后续生成环节。
补充：向量相似度检索的工程实现，可以参考 RAG 检索增强生成的相关方案，包含特征抽取、阈值设定等内容。
3. 生成产出闭环回验（生成后质检）
单集短剧全部生成完成，不能只看画面好不好看，必须增加角色一致性质检：
将新生成画面，和角色版本快照里的基准图再次做特征向量相似度比对；
如果形象偏差超过阈值，自动回退，重新生成画面，直到达标才算完成该集内容生产。
三、完整面试答题模板（4 步标准答案）
给每个角色建立资产版本目录，把参考素材打上版本标签入库；
新增素材入库前，和版本基准图比对特征向量距离，做一致性校验；
生成画面时，Prompt 直接引用角色版本号，而不是直接手写大量外貌描述；
剧集生成结束，回验角色相似度，不达标自动回退重生成。
面试加分追问应答
面试官提问：第一集没有统一参考素材怎么办？
回答：挑选第一集效果最好的一张画面，作为v1.0基准锚点；后续所有集数全部锁定这个版本；已经产出的第一集可以回头翻修对齐基准形象。
四、工程避坑点
❌ 错误方案：直接用余弦相似度逐帧全部比对，短剧产出量大，速度慢，无法落地。
✅ 正确方案：预计算图像特征向量，建立向量索引，比对只查询向量距离，做到毫秒级校验速度。
五、核心结论
Prompt 只负责风格约束；角色身份、长相一致性，靠角色资产版本管理 + 向量校验整套工程体系保障，而不是单纯依靠提示词文字描述抖音。

一、开篇面试场景案例（视频模拟面试官场景）
面试提问场景：面试官提问：AI 短剧角色总变脸，问题到底出在 Prompt，还是素材与资产管理？
错误考生回答：是 Prompt 没写好，把角色外貌特征写得更详细就可以解决。
视频模拟面试官反应：摘下眼镜擦镜片，戴上后沉默两秒。暗示该回答是错误答案。
底层真相案例：即便 Prompt 写得再细致，如果给模型输入 3 张不一样的角色参考图，同一个角色就会被画成三个人；单纯文字 Prompt 无法抵消参考素材不一致带来的变脸问题。
面试题考察本质：表面考察 Prompt 提示词颗粒度；实际考察候选人是否理解多模态角色资产完整工程管理体系。
总纲领结论：要对每个角色参考素材做版本快照锁定；每一集生成，调用的必须是同一套经过审核的版本快照素材，不能临时从零散文件夹随便挑选素材。
二、第一大核心步骤：角色资产版本化（源头阻断变脸）
背景前提：AI 短剧是多集连续生产，同一个角色会反复在多集出现，不能一集一套素材孤立处理。
资产打包范围（全部视觉资产）
外貌参考图
服装设定资料
表情集素材
场景光照参考素材
将以上全部资料打包为一个角色版本包。
命名规则示例：角色A_v1.2_202##20608#10，格式：角色名_版本号_时间戳。
Prompt 使用规则（重要例子）
❌错误做法：在 Prompt 内部手写一大段外貌文字描述；
✅正确做法：Prompt 不再写外貌描述，直接引用角色版本号。
示例 Prompt 语句：请根据角色 A_v1.2 的参考素材生成该角色的新画面。
本步骤达成效果：无论生成到短剧第几集，模型读取的都是同一套角色素材，从源头切断变脸诱因。
三、第二大核心步骤：入库前的一致性校验（特征向量距离，提前排雷）
痛点现象：就算素材打包完成，如果打包进来的多张图片本身形象就互相冲突，后续生产依旧会变脸。
冲突素材来源实例：美工组产出海报图、后期组剪辑截图、网络下载的低清参考图；三份素材名义是同一个角色，但人物长相存在差异。
校验技术逻辑
1）素材入库前，做视觉相似度比对；
2）计算待入库图片，和版本包内部基准图之间的图像特征向量距离；
执行规则：如果图片相似度低于预设阈值 → 系统直接拒绝入库，标记素材冲突，流转给人工复核。
该步骤的价值定位：不是等生成之后再修复变脸；在素材入库环节就把隐患拦截掉，不让错误素材进入生产链路。
课程相关补充信息：这套特征向量距离校验、相似度比对的工程实现方案，在 RAG 检索增强生成章节完整覆盖；包含图像特征抽取、阈值如何设定，可直接拿来搭建工程系统。
四、第三大核心步骤：生成产出的闭环回验（生成后质检环节）
痛点：一集短剧生成完，很多人只看画面好不好看，不校验角色长相一致性。
回验操作流程
短剧单集全部生成完毕后，拿新产出的生成画面，和角色版本快照内部的基准图再次做相似度比对。
执行规则：如果新画面角色形象和基准图偏差超过阈值 → 直接回退，重新生成画面，校验通过才算该集生产完成。
定位：相当于为每一集短剧增加一道强制的角色一致性质检关卡。
五、完整面试答题模板（4 步标准答案，视频直接提供可背诵）
第一步：为每一个角色创建独立资产版本目录，所有参考素材打上版本标签，完成入库。
第二步：任何新增素材入库之前，必须和该版本基准图比对特征向量距离，做一致性校验。
第三步：画面生成阶段，Prompt 直接引用角色版本号，不在提示词裸写大量外貌描述。
第四步：每一集全部生成完成，执行相似度回验；指标不达标，自动回退重生成。
六、面试追问场景：面试官问 “第一集就没有统一素材怎么办？”
标准加分回答：优先从第一集已产出画面里挑选效果最好一张，定为v1.0 基准锚点；后续全部剧集统一锁定使用这个 v1.0 版本；已经产出的第一集内容，可以回头翻修对齐这个基准锚点形象。
面试价值：答出这一点属于加分项，体现处理历史存量剧集的工程思维。
七、工程实现避坑（错误方案 vs 正确方案，带性能理由）
❌错误方案：直接使用余弦相似度 cosine similarity 做逐帧比对。
缺点理由：短剧整体生成数据量大，逐帧完整比对运算速度很慢，线上生产环境跑不动，无法落地。
✅正确工程方案：预先计算图像特征向量，建立向量索引；比对的时候只查询向量距离。
性能结果：毫秒级就可以完成一次相似度校验，可以支撑大批量短剧生产。
八、全部最终结论汇总
AI 短剧角色变脸，核心根源大多不是 Prompt 描述不够细致，而是角色素材与资产管理流程缺失。
Prompt 更多负责画面风格约束；角色长相、身份的一致性，依靠角色资产版本管理 + 向量相似度校验整套工程链路保障，而不是单纯依靠文字提示词。
完整链路分为三段：入库前校验（防坏素材进库）→ 生产时引用固定版本快照（生产输入可控）→ 生成完成闭环回验（产出结果质检拦截）。
面试该题，如果只回答优化 Prompt，属于认知片面，不是合格工程解法。
