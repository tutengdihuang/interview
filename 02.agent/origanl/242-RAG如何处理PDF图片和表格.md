5 个关键处理步骤
判断 PDF 类型
原生文本 PDF 直接提取文本；扫描 PDF 走 OCR；图文混排做版面解析；图表、截图调用视觉 / 多模态模型，不同 PDF 不能用同一套流程。
版面还原
修复阅读顺序，解决多栏排版左右栏乱序问题；清洗页眉页脚避免污染切片；还原标题、章节、段落、列表、脚注、页码，切片要保留文档原有结构。
表格结构化
不能把表格直接转成杂乱普通文本；保留表头、行列名、单位、合并单元格；像财报数字，要绑定年份、科目、币种，否则数字没有业务含义。
图片与图表理解
流程图、柱状图、截图不能直接丢弃；调用多模态模型生成图片文字描述，提取实体、关系；把页码、图片位置、图注存入元数据 metadata；复杂场景封装看图工具，查询时按需调用视觉模型分析图片。
证据溯源引用
输出答案必须带上页码、章节、表格编号、图片位置。业务场景中，就算答案通顺，没有来源溯源就不可信；评测不只看答案对错，还要校验证据片段、页码、表格解析准确度。

第一步是判断 PDF 类型，原生文本 PDF 可以抽文本，扫描件要 OCR，图文混排要结合版面解析。如果有图表和截图，还需要视觉模型或专门的图表解析工具。不同 PDF 类型不能用同一套流水线。
第二步是版面还原，PDF 里的阅读顺序很重要。多栏排版如果按坐标直接抽，可能把左栏和右栏混在一起。页眉页脚如果不清洗，会污染每一个 chunk，所以要还原标题、段落、页码、章节、列表和脚注，让切片保留原文结构。
第三步是表格处理，表格不能只转成一段乱序文本，表头、行名、列名、单位、合并单元格都要保留。比如财报里的一个数字，必须知道它属于哪个年份、哪个科目、哪个币种，否则模型只看到数字没有意义。
第四步是图片和图表理解，流程图、架构图、柱状图、截图不能简单丢掉，可以给图片生成描述，抽取图中的关键实体和关系，再把图片位置、页码、说明文字一起写入 metadata。复杂场景下还可以把看图封装成工具，按需调用多模态模型。
第五步是证据引用，PDF RAG 的答案一定要能追溯到页码、章节、表格编号或图片位置，否则模型说的再顺也很难让业务方信任。评测时也不能只看答案对不对，还要看证据片段是否命中，页码是否正确，表格是否解析准确。
