抖音视频《面试题：AI 写周报总编数字怎么办？》内容详细总结
视频是一道大模型 / Agent 开发的程序员面试题讲解，核心主题：AI 自动写周报出现编造虚假数字（幻觉），只靠修改提示词（Prompt）是错误解法，考察的不是提示词工程，而是真实数据工作流、事实来源、计算链路、输出约束的工程落地思维。
一、面试题的坑点
面试官提问：AI 写周报总是编造数字，你是改 Prompt 还是改数据？
如果回答只在提示词加上 “禁止编造数字、不要幻觉”，面试官就会判断候选人没有真实项目经验。
周报里面的收入、完成量、环比等数值，不能交给大模型记忆、估算、脑补生成，必须来自结构化数据源做确定性计算，模型只负责组织语言文字。
二、核心设计思想：数字生产与文字表达彻底分离
代码 / 数据服务负责：取数、过滤时间、计算指标、产出证据；大模型只负责解释已经确认好的数据。所有关键数字可追溯原始记录。
模型只拥有 “文字表达的创造力，不能拥有发明事实、生成新数字的权力”。
三、完整落地步骤
1. 先建立严格的指标口径定义
明确每一个指标的计算规则，例如 “新增客户”：是按创建时间、首次付费时间、还是企业去重数量，全部书面定义。
传给大模型的不是原始表格，而是结构化信息：指标名称、数值、统计周期、计算公式、数据版本、异常标记，而不是一堆原始文本。
2. 限制大模型自由度
要求模型输出结构化周报对象，引用指标 ID；禁止生成输入里不存在的全新数字。
生成文字之后，由程序扫描整篇周报正文，把文中数字和结构化指标逐项比对；一旦不一致直接退回重写，阻断发布，不能直接输出。
3. 异常、失败场景的处理（面试高频追问点）
数据源临时不可用、接口返回空值：系统降级，标记待补数据，保留已经确认的指标，禁止模型拿历史数据自行填空补数；显示数据版本、生成时间，不能静默生成一篇看似完整的周报。等数据恢复后重新生成，对比新旧版本差异。
报告已经对外发送：不能偷偷修改覆盖，要使用版本号，发布更正通知。
数据存在延迟快照：必须把数据新鲜度信息传给模型，防止模型把 “截至昨天的数据” 写成 “截至今天”。不同指标设置不同容忍延迟：订单库存需要实时，趋势分析可以接受小时级延迟。
指标环比变动异常：设置数字变动阈值，异常自动标记；业务原因分析不能由 AI 瞎编，必须引用工单、运营备注、日志。
四、线上环境两个常见坑
查询接口返回成功，但时间区间出错，模型流畅输出，但是把月度数据当成周度数据。
接口返回空数据，大模型为保证文章完整度，自动脑补一个看起来合理的虚假数字。
空、延迟、异常数据必须显性标记，不能用 0 或者模糊自然语言掩盖问题。
五、面试高分参考回答话术
“我不会只修改提示词。首先定义好指标口径，程序从可信数据源完成计算并保留证据；再将结构化的计算结果交给大模型生成文字；最后做程序数字一致性校验，搭配人工抽检拦截错误。让模型只做表达，不发明事实。”

面试原题：AI 自动写周报时总会编造数字，你是先改 Prompt 还是先改数据？
一、题目的本质与误区（视频开篇）
常见错误回答：只修改提示词，在 prompt 增加 “不要幻觉、禁止编造数字” 这类话术。
面试官判断：这么回答，代表候选人缺少真实数据工作流项目经验。
题目考察点：表面考提示词工程，实际考察事实来源、计算链路、输出约束的工程思维。
核心认知：周报中的收入、完成量、环比等数字，不能交给大模型靠记忆、脑补生成；必须由结构化数据做确定性计算，大模型仅负责组织语言文字。
底层结论：只依靠提示词口头约束模型 “不要编数字”，并没有建立事实边界；系统可信度来自数据契约，不是模型语气。
二、总体核心方案（总纲领）
把数字生产和文字表达彻底分开：代码 / 查询服务负责取数、过滤时间范围、计算指标、生成证据；大模型只负责解释已经确认好的数据。每个关键数字都必须可以追溯到原始记录。
口诀：代码算数、模型表达、程序复核。
三、步骤 1：建立严格、书面化的指标口径
问题背景：同一个业务名词，会有多种统计方式，如果没有明确定义，会产生错误。
视频举例：指标「新增客户」，要明确：是按账号创建时间？首次付费时间？还是去重之后的企业客户数量？必须写进指标定义文档。
传给大模型的输入内容要求：不要直接丢原始数据表给模型。要传入结构化字段集合，包含：
指标名称
指标数值
统计周期
计算公式
数据版本
异常标记
目的：模型拿到的是加工完毕、带定义的指标，不是一堆杂乱原始数据，避免模型自行解读口径。
四、步骤 2：限制大模型自由度 + 程序校验拦截
约束模型输出形式：要求模型输出结构化周报对象，写作时引用指标 ID。
硬性规则：禁止模型生成输入里面不存在的全新数字。模型不能发明事实，创造力只允许用于文字表达。
后置程序复核流程：
模型产出周报正文之后，程序扫描提取正文全部数字；
和前面传入的结构化指标逐项比对；
一旦发现数字不一致，直接退回重写，阻断发布流程，不允许直接对外输出。
五、线上环境两大高频踩坑案例（真实生产坑）
坑 1：数据查询接口返回成功，但是时间区间出错
现象：模型输出文字非常流畅通顺，但错误的把月度统计数据当成周度数据写进周报。
坑 2：接口返回空值，大模型为了保证文章完整度，自动脑补生成一个看起来合理的虚假数字
针对两个坑的统一结论：空数据、延迟数据、异常数据，必须显性标记出来；不能用数字 0，也不能用模糊自然语言掩盖数据缺口。
六、各类异常场景处理（面试官高频追问：数据源临时不可用怎么办？）
场景 1：数据源故障、接口返回空、拿不到指标数据
处理逻辑：系统降级，进入待补数据状态；保留已经确认成功拿到的指标。
禁止行为：绝对不允许模型拿历史旧数值自行填空补齐报告。
输出要求：页面 / 报告上展示数据版本号、系统生成时间。
后续动作：等数据恢复完成之后，重新生成周报；并且对比新旧两个版本之间的差异。
场景 2：周报已经对外发送完成，后续发现数据错误
禁止：不能静默替换、偷偷修改已经发出的报告。
正确做法：使用版本号管理，发布更正通知。
场景 3：接口返回延迟快照（数据不是实时最新）
处理逻辑：把数据新鲜度信息一并传给大模型。
反例：不能让模型把 “统计截至昨天的数据” 写成 “统计截至今天”。
不同指标设置差异化允许延迟阈值：
库存、订单类指标：要求实时；
趋势分析类指标：可以接受小时级别的数据延迟。
场景 4：指标环比发生巨大异常波动
方案：设置数字变动阈值，系统自动标记异常。
禁止：不让大模型自行编造业务解释理由。
硬性规则：业务原因分析，必须引用日志、工单、运营人员手写备注，模型不能凭空分析原因。
七、面试可以直接口述的完整高分标准答案
“我不会只修改 Prompt。首先定义好指标口径，程序从可信数据源完成计算并且保留证据；再将结构化的计算结果交给大模型生成文字；最后做程序数字一致性校验，搭配人工抽检拦截错误。让模型只做表达，不发明事实。”
八、最终整体结论
一份可靠的 AI 自动周报系统，必须做到：每一个数字都要有来源、有口径、有校验。
