抖音视频详细总结：大厂面试‑Agent 如何判断生效制度
视频是一道大模型工程高频面试题解析：知识库同时召回新旧两版制度，Agent 如何判断哪一版是当前生效版本。核心观点：制度生效不能依靠语义相似度做判断，是元数据、发布时间、适用范围、废止替代关系共同决定的状态判断，不是单纯向量检索问题，是整套知识库工程治理问题。
一、题目的底层考察点
题目看上去问怎么选版本，实际考察企业 RAG 落地能力：
向量召回只看语义相似度，新旧制度文本很相似，会同时被召回；模型容易直接融合文本内容，不会自动识别业务层面的生效、废止、替代关系。不能只靠大模型 prompt 去猜版本，需要入库、查询、校验、兜底整套链路设计。
二、工程方案：入库与查询分离治理
1、入库阶段（知识治理，提前打元数据标签）
解析原始文档，还原标题、条款、表格、附件之间关联关系；
给每一个文档切片打上完整元数据：文档 ID、页码、版本号、发布日期、生效日期、废止日期、适用组织、权限标签、版本替代关系；
记录制度的过渡期场景（例如差旅制度，发布日、正式执行日、废止日中间存在过渡期）。
高频坑点：不能简单拿上传时间当作生效时间。上传最新的文档可能是试行稿、补充通知，不一定是正式现行制度，会造成版本判断错误。
2、查询阶段（先过滤，后召回）
解析用户问题，拆解出：主体、动作、业务条件、时间信息；
优先做元数据硬过滤：用生效时间、适用组织、废止状态做前置筛选，再执行关键词 + 向量召回；
好处：精确编号、时间、否定词不会被纯语义相似度淹没；业务口语、别名可以单独做改写处理。
逻辑顺序：元数据过滤在前，向量语义召回在后，而不是召回完全部内容再交给模型判断。
三、召回完成之后：证据充分性与冲突裁决
召回很多片段≠证据足够，要校验片段是否覆盖用户问题全部条件；
证据冲突处理规则：
优先对比：权威来源、制度版本、生效时间、适用范围；
如果多份文档对比后依旧无法裁决，不能让模型强行编造答案，需要做追问或者拒答；
输出闭环：最终答案每一条结论，必须绑定原文出处（文档 ID、页码、版本），实现答案可溯源。
评测指标需要拆分：切片完整性、召回率 Recall、重排命中效果、引用准确率、内容忠实度，不能只看最终生成文本好不好。
四、故障排查、降级兜底策略
排查问题时完整保留：输入、配置、模型版本、中间链路结果；定位第一个出现错误的节点；
不要简单重试让模型重新猜；根据出错节点选择调整参数、重试、降级、人工接管；
系统要明确边界条件：证据不足、版本状态不明、指标异常时，要有追问、降级、回退、人工接管机制，明确什么时候不能自动给出答案。
五、上线之后的验证与回归测试
修改方案必须做对照实验：固定输入、数据、模型版本，只改动一个变量，观测正确性、延迟、显存 /token 成本、风险变化；
链路要完整可追溯：检索、工具调用、状态、最终答案全部绑定请求链路 ID；
线上监控：关键指标、文档版本放在同一时间线，区分错误来源：输入分布变化、配置改动、模型升级、外部依赖问题；
修复完 bug 后，把该案例加入回归测试集，同时检查相邻业务场景，避免单点优化，造成其他场景效果退化。
六、面试答题的四步标准回答框架
给出核心判断：生效判断不靠语义相似度，由元数据、时间、适用范围、废止替代关系共同决定；
讲完整链路：入库打元数据标签→查询元数据前置过滤→向量召回→证据校验→绑定原文引用输出；
说明坑点与边界：讲常见错误（直接取上传最新文档）、冲突场景、过渡期怎么处理、什么时候需要降级 / 人工；
讲评测验证：说明评测指标、对照实验、回归测试、故障排查手段。
面试官追问方案取舍时：先讲业务目标与约束条件，再解释方案选择理由，同时说明这套方案的适用边界，什么场景该放弃自动执行。
七、总结
企业级 RAG 的高级能力，不是保存一份静态标准答案；而是每次回答，都能够解释清楚：为什么这份制度在当前时间、当前业务场景下是生效的，做到结果可验证、可追溯。

0、面试原题
题目：知识库召回的时候，新旧两个版本的制度都被召回出来了，Agent 怎么判断哪一版才是当前生效的？
1、开篇核心总论点（视频第一句结论）
制度是否生效，不能依靠语义相似度判断；生效判断是元数据、发布时间、适用范围、废止替代关系共同决定的状态判断，不是向量检索问题，本质是企业知识库治理工程问题。
面试官考察本质：不是问你怎么写 prompt 让模型选，考察你有没有做过企业落地 RAG，懂不懂知识库版本治理、冲突裁决、链路可控。
底层痛点：新旧制度文本高度相似，向量相似度很高，向量检索天然会把新旧文档一起召回；大模型很容易直接融合两份文本内容，自己脑补合并，不会自动识别业务上 “废止、替代、失效” 关系。
2、核心原则：入库链路、查询链路必须分开治理（工程分工）
2.1 入库阶段（知识治理环节，前置处理，是整套方案根基）
原始文档解析：先还原文档内部结构，还原标题、独立条款、表格、附件之间的关联关系，不能粗暴直接按固定长度切片。
每一个切片绑定全套元数据标签（视频列出全部标签）
文档唯一 ID
页码
版本号
发布日期
生效日期
废止日期
适用组织 / 适用主体
权限标签（哪些角色可以查看这条制度）
版本替代关系：哪份文档替代哪份文档、被哪份文档替代
必须单独记录过渡期场景
✅【视频案例：差旅制度】
一份差旅制度有三个时间点：发布日、正式执行生效日、废止日。发布之后、正式生效之前属于过渡期，过渡期内旧制度仍然有效，新制度暂不生效；等到生效日之后新制度启用、旧制度废止。
案例结论：不能只看一个时间戳，业务上普遍存在过渡期，是高频坑。
入库环节最大坑点（视频重点强调）
❌ 错误做法：直接拿文件上传时间当成生效时间。
❌ 风险：最新上传的文档有可能只是征求意见稿、试行稿、补充通知、答疑文件，不一定是正式生效版本，会直接导致版本判断完全错误。
结论：上传时间 ≠ 生效时间，二者解耦。
2.2 查询阶段（检索链路，顺序硬性规定：先过滤，后召回）
第一步：解析用户 query，拆解查询要素：主体、动作、业务条件、时间信息
第二步：优先元数据硬过滤（数据库层面过滤），再做关键词检索、向量召回
过滤条件：生效时间、废止状态、适用组织、权限标签
含义：先把在当前时间已经废止、不适用于当前用户主体、无权限查看的文档直接筛掉，再在剩下候选集里面做向量召回
视频明确顺序：元数据过滤在前，向量语义召回在后；不能先召回一大堆再交给模型去猜哪个有效。
补充处理：口语别名、业务俗称单独做 query 改写层，不要交给向量相似度兜底。
3、召回完成之后：证据校验 + 冲突裁决模块
基础校验：召回出来的片段数量多 ≠ 证据充分。要校验召回片段集合能不能完整覆盖用户问题里全部业务条件；缺条件就是证据不足。
多文档冲突裁决优先级（视频给出固定裁决顺序）
① 权威来源优先级
② 版本替代关系（A 明文废止 B，则 A 优先）
③ 生效时间、废止时间
④ 适用范围匹配度
冲突边界结论：
如果按上面规则比对之后，仍然无法确定哪一份有效，禁止让大模型强行编造答案、强行选一个版本输出。
两个兜底动作二选一：向用户追问补充信息；直接拒答，说明证据冲突无法判定。
输出闭环要求：
Agent 对外输出的每一条结论，都必须绑定原文出处：文档 ID、页码、版本号，做到答案可溯源、可核验。
4、评测指标拆分（视频原话，不能只用生成文本好坏评测）
评测指标拆成独立维度：
切片完整性
召回率 Recall
重排命中效果
引用准确率
内容忠实度
结论：不要只看模型输出文字通顺与否，企业 RAG 评测重点看引用和溯源正确性。
5、故障排查、降级、兜底策略
排查日志必须全链路留存：原始输入、配置参数、模型版本、每一步中间节点结果
定位方法：找到整条链路里第一个偏离预期结果的节点
如果错误出在入库打标阶段：修正元数据，重新入库
如果错误出在过滤 / 检索阶段：调整检索参数、过滤规则
如果错误出在模型推理阶段：调整 prompt、重排策略
❌ 禁止简单粗暴方案：直接重试一遍，让模型重新猜
系统必须预设分级兜底动作集合：参数调整、可控重试、降级输出、人工接管
明确边界：证据不足、版本状态矛盾、指标异常时，不能自动给出确定性答案，必须走人工复核通道。
6、上线验证、回归测试、线上监控
修改方案之后验证方式：对照实验
固定输入样本、固定数据集、固定模型版本
只改动一个变量，单一变量对照
观测指标：正确性、延迟、显存消耗、token 成本、风险变化
链路可追溯：检索、工具调用、状态判断、最终答案全部绑定同一个请求链路 ID
线上监控维度拆分，区分错误根因：
用户输入分布变化
配置改动引发
模型版本升级引入
外部依赖（向量库、数据库）问题
Bug 修复闭环：出错样本加入回归测试集；同时检查相邻业务场景，避免单点优化，造成其他场景退化。
7、面试标准口述四步框架（视频给的面试答题模板，完整四条）
先抛出核心判断结论：生效判断不靠语义相似度，由元数据、时间、适用范围、废止替代关系共同决定。
讲完整工程链路：入库打全套元数据标签 → 查询阶段元数据前置过滤 → 向量召回 → 证据校验、冲突裁决 → 绑定原文引用输出。
讲坑点 + 边界场景：重点讲上传时间≠生效时间、过渡期案例；冲突无法判定时禁止模型硬编，支持追问 / 拒答、人工兜底。
讲评测、验证、故障排查手段：指标拆分、对照实验、回归测试、链路日志定位。
8、面试官追问应对思路（视频补充）
面试官问方案取舍的时候：
先讲清楚业务目标、约束条件（延迟、成本、合规风险），再说明方案选择理由；同时主动讲这套方案的适用边界，什么场景下不适合自动 Agent 处理，应该交给人工。
9、视频收尾最终总结结论
企业级高级 RAG/Agent 知识库，不是存一份静态标准答案；它的核心能力，是每一次回答，都能够解释清楚：为什么这份制度，在当前时间、当前业务主体场景下是生效版本，做到结果可验证、可追溯。
