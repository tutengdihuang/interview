视频内容详细总结
视频是一道大模型 RAG 开发的经典面试题讲解：合同明确写 “不得退款”，但 RAG 检索经常召回、输出支持退款的结果，指出只做简单否定词过滤是很浅的回答，讲清楚向量检索底层缺陷、问题根源、解决方案，还给了面试答题思路模板。
一、面试题背景
面试官问题：知识库合同文本写着 “不得退款”，用户问能不能退款，RAG 却容易输出支持退款的结论，是什么原因？怎么解决？
⚠️ 避坑提醒：如果只回答 “加否定词过滤”，面试基本不占优势，这道题考察的不是简单关键词过滤，而是稠密向量检索本身的语义盲区。
二、问题根源：稠密向量（Embedding）的天然缺陷
向量检索依靠语义相似度做召回，“不得退款”、“支持退款” 都围绕 “退款” 这个核心主题，描述同一业务话题；二者向量空间距离很近，余弦相似度很高。
稠密向量对否定语义编码能力弱：向量擅长识别 “话题是否相关”，但很难区分「肯定」和「否定」的极性。
现象：查询 “是否支持退款” 时，向量库会把 “不得退款” 这种意思完全相反的文本当成高相似度结果召回，送入大模型上下文。大模型在一堆 “退款” 相关文本干扰下，容易忽略否定限定，输出错误答案。
简单的否定词过滤治标不治本：否定句式复杂，存在例外条件、双重否定，单纯关键词过滤很容易误杀正常文档，也无法识别隐藏否定。
三、视频给出核心解决思路：知识图谱 + 实体级断言抽取 + 实体级精排
不能完全依赖向量相似度，引入实体关联图谱做增强：
入库阶段：提取断言（事实）
对合同文档做解析，抽取实体、关系，区分肯定断言、否定断言。
例：实体 = 退款；断言：【禁止退款】（否定）、【允许退款】（肯定），把业务事实结构化存入知识图谱。
检索链路改造：向量召回 + 图谱实体断言做精排
第一步向量召回：先召回所有和退款话题相关的原始 chunk（保证召回广度）；
第二步实体级精排：调用知识图谱识别每个召回片段的断言极性（允许 / 禁止 / 条件允许）；
根据用户查询意图，对召回结果重新排序，把匹配极性的片段优先给到 LLM，把语义相关但是语义极性相反的片段降权、过滤。
核心逻辑：向量负责找 “话题相关材料”，知识图谱负责分辨 “材料是赞成还是反对这件事”，弥补向量分不清否定语义的短板。
四、三层逻辑拆解（视频核心三层逻辑）
第一层：认清向量检索的盲区
向量 = 话题相关性，≠事实正确性。相关≠符合事实。同样是讲退款，允许退款、禁止退款、有条件退款，向量相似度很高，但业务含义完全相反。RAG 出错不一定是没搜到原文，而是把语义相近但立场相反的内容混入上下文。
第二层：引入知识图谱做断言抽取
把非结构化合同文本，拆解成结构化事实断言：实体 + 动作 + 极性（肯定 / 否定 / 条件）。
不再只靠文本 chunk 的向量，而是提取业务事实存入图谱，把 “否定” 从文本层面提升到事实断言层面，机器能明确知道某一条条款是禁止退款，而不是只看到 “退款” 这个词。
第三层：检索链路增加实体级精排环节
传统链路：用户 query → 向量化 → 向量库召回 → 直接丢给大模型生成。
优化后链路：
用户 query → 向量召回粗筛（拿到相关文档）→ 图谱实体断言识别，判断每段文本的立场极性 → 实体级精排，压制反向极性片段 → 将筛选后的证据交给大模型生成答案。
五、面试标准回答模板（视频提供）
面试官提问：合同写了不得退款，RAG 为什么会召回支持退款？怎么解决？
答：
这个问题本质是稠密向量检索的短板：向量擅长衡量话题相关性，但对否定语义的区分能力不足。“不得退款” 和 “支持退款” 都围绕退款主题，向量相似度很高，会被一起召回；大模型拿到包含反向立场的上下文，容易忽略否定条件输出错误结果。
如果只做简单否定词过滤效果有限，复杂合同存在例外、条件句式，容易误杀或者漏判。
工程上可以结合知识图谱优化：
文档入库时做断言抽取，提取实体和事实极性，区分肯定、否定、有条件约束的业务事实，构建实体关联图谱；
检索阶段先用向量做粗召回，保证相关片段不漏；再基于图谱做实体级精排，识别每段证据的立场，把和用户查询语义极性冲突的片段降权过滤；
最后将经过极性校验后的证据交给大模型做回答，以此解决向量分不清否定语义的问题。
六、补充工程提醒
知识图谱方案适合合同、法规、风控这类高风险垂直业务；普通简单 FAQ 场景不一定需要这么重的方案。
即使引入图谱，也不能完全放弃向量检索，二者是粗召回 + 精排的互补关系，不是直接替换向量库。
评测的时候，需要专门构造大量否定条款、例外条款的 bad case 做测试，不能只用正向样例测试 RAG 效果。

一、开篇：面试题的考点定位（视频第一个要点）
❌ 误区：很多求职者以为考点是关键词过滤、调 topK、切 chunk
✅ 真实考察点：语义相似度 和 事实极性判断之间的断层，垂直高风险知识库（合同、法务、风控、保险条款）RAG 的核心缺陷
面试官真实想听到的：不能只说加否定词，要讲清楚 Embedding 本身的短板、边界、工程链路改造方案
二、问题现象 + 配套例子（视频全部示例）
示例合同片段（知识库内同时存在多条）：
A：本产品一经售出，不得退款
B：仅在商品存在质量缺陷的情况下，支持退款
C：收货超过 7 个自然日，不予退款
D：套餐内附属配件，不单独办理退款
用户 Query：我能不能申请退款？
现象：
向量检索算相似度，A/B/C/D 全部围绕 “退款” 这个主题，它们在 Embedding 向量空间里面距离很近、余弦相似度都很高；topK 召回的时候，A（禁止退款）、B（允许退款）会被一起捞出来，全部塞进 LLM 上下文窗口。
大模型拿到一堆混杂正反立场的上下文，很容易丢失原文里的否定限定、前置条件，最后输出 “可以退款” 这种和主合同冲突的错误答案。
视频重点强调：不是没召回 “不得退款”，而是正反结论的 chunk 一起被召回，上下文互相干扰
三、根源拆解：稠密 Embedding 向量检索的天然短板（分 3 小点）
稠密向量擅长捕捉主题、话题、语义主题是否相关；它对否定词、限定修饰、条件约束、极性（肯定 / 否定）编码能力弱
向量只能回答：这段文字和用户问题是不是在聊同一个事；向量没有能力识别这件条款是允许这件事，还是禁止这件事
补充例子：“禁止退款”、“允许退款”、“有条件退款”，话题中心词都是退款，向量很难自动区分立场相反的断言
四、方案 1：简单否定词过滤（视频重点批判的方案，完整讲它为什么治标不治本）
这个方案怎么做：
写规则，正则 / 关键词匹配，只要 chunk 里面出现 “不得、不予、禁止、不支持” 这类否定词，直接过滤掉或者降分。
视频列出它所有缺陷（逐条）
句式复杂，否定不是简单 “不 + 动词”：存在条件否定、例外条款、双重否定、倒装、长修饰从句，关键词匹配识别不准
例子 1：“除非质检不合格，否则不得退款”—— 里面有 “不得退款”，但是存在前置例外条件；直接过滤会把带例外规则的有效条款删掉
例子 2：“并非所有订单都不支持退款”（双重否定），关键词很容易误判
容易误杀：很多正常业务文本包含否定词，但它不是针对当前 query 的断言
例子：“本合同不支持换货，但支持退款”，如果无脑过滤带 “不支持” 的片段，会把这条正向有效条款删掉
漏判：否定语义藏在从句、后置限定，否定词不在紧邻退款的位置，关键词抓不到
结论：否定词规则过滤只能做辅助，绝对不能作为主方案；高风险合同 RAG 只靠这个方案过不了线上 bad case
五、视频主推方案：入库断言抽取 + 知识图谱结构化 + 检索链路增加【实体极性精排】（整套链路完整拆解）
核心思路：向量负责 “宽召回，不漏相关内容”；知识图谱 / 结构化断言负责 “判断立场极性、适用条件”，二者互补，不是互相替代
阶段一：文档预处理、入库阶段（离线流程）
不再只把文档切成纯文本 chunk 向量化入库
调用 LLM 做断言抽取（fact extraction），对每一条合同条款，抽结构化四元组：
实体：退款（业务动作主体）
动作：退款
极性三分类（视频明确三分，不是二分）：✅允许、❌禁止、⚠️条件允许
约束条件：触发这条规则的前置边界（7 天内、质量问题、虚拟商品、已核销等）
把抽出来的结构化断言存入知识图谱，建立【实体 - 断言 - 极性 - 条件】索引
示例抽取结果：
断言 1：退款｜极性：禁止｜约束：无例外（本产品一经售出不得退款）
断言 2：退款｜极性：条件允许｜约束：商品存在质量缺陷
断言 3：退款｜极性：禁止｜约束：收货超过 7 天
原文 chunk 和结构化断言做绑定：图谱里每一条断言，保留对应原文片段引用，方便溯源、引用举证
视频一句话重点：把藏在自然语言里的 “否定 / 条件”，从文本层面提升到机器可识别的结构化事实层面
阶段二：在线检索链路改造（改造后的完整链路，对比传统链路）
✅ 传统旧链路（踩坑链路）
用户 Query → Query 向量化 → 向量库 topK 召回 chunk → 全部上下文直接丢 LLM 生成答案
✅ 改造后的新链路（视频推荐链路，四步）
向量粗召回：放宽召回数量（topK 可以比原来更大），把所有和退款、售后、解除、违约金相关的 chunk 全部捞出来；目标：保证不漏任何相关条款，召回广度优先
断言识别：对每一个召回出来的 chunk，关联图谱，读出它对应的【动作实体、极性、约束条件】
实体级极性精排（最核心新增环节）
识别用户查询的意图极性：用户问 “能不能退款”，意图是想知道【是否允许退款】
精排规则：
和查询意图极性匹配、且约束条件匹配当前场景的片段，优先置顶
极性相反的片段（禁止退款，且无匹配例外条件）大幅降权、屏蔽
条件类断言保留，但必须带上它的前置条件，不能单独拿结论
筛选、裁剪后的证据集送入 LLM，同时强制 LLM 输出时引用原文条款、标注约束条件
例子演示精排效果：用户普通无质量问题申请退款
召回池里三条：A 禁止退款、B 质量问题可退、C 超 7 天不退
精排之后：A 优先；B 保留但是标注【仅质量问题时生效，当前场景不满足】；C 降权。模型不会单独拿 B 来回答用户
六、三层逻辑总结（视频反复强调的三层理解框架，面试可以分层讲）
第一层：向量只解决相关性，相关 ≠ 结论一致，这是根源
第二层：合同这类文本，事实不是藏在词，而是藏在断言极性 + 适用条件；必须结构化抽取
第三层：检索不能一步到位只靠相似度排序；必须粗召回 + 基于业务事实的二次精排
七、视频给出的标准面试口述回答原文（完整版本）
面试官：合同写了不得退款，RAG 为什么会召回支持退款？怎么解决？
答：
这个问题本质是稠密向量检索的短板：Embedding 向量擅长衡量话题语义相关性，但是对否定语义、条件约束的极性区分能力很弱。“不得退款” 和 “支持退款” 都是围绕退款这个主题，向量相似度很高，粗召回阶段会被一起捞出来，混在同一个上下文里面。大模型在正反立场混杂的证据里，很容易忽略原文的否定、前置限制条件，输出错误结论。
如果只做简单否定关键词过滤，方案局限性很大。合同里面大量存在条件否定、例外条款、双重否定，关键词很容易误杀有效条款，也抓不到藏在长从句里的否定约束，只能做辅助手段，不能作为主方案。
工程上推荐向量检索结合断言抽取与知识图谱做增强：
第一，文档入库离线阶段，对合同条款抽取结构化断言，区分允许、禁止、条件允许三种极性，同时绑定每条规则的适用约束条件，存入知识图谱，并且绑定原始文本证据；
第二，在线检索时先用向量做宽范围粗召回，保证相关条款不漏；再基于图谱里的断言极性做实体级精排，把和用户查询意图极性冲突、且条件不匹配的证据降权过滤；
第三，最后交给大模型的证据是经过极性校验的，同时要求模型回答时引用原文、带上约束条件，避免模型脱离条款乱生成。
另外补充边界：这套方案成本更高，适合合同、法务、保险、风控等高容错低的垂直场景；普通 FAQ 知识库不需要这么重的图谱方案。
八、工程落地边界、取舍、补充结论（视频后半段补充要点，容易漏掉）
不是用知识图谱替代向量库：向量粗召回 + 图谱精排是互补关系，不能二选一；直接抛弃向量全靠图谱检索，召回率会崩盘，很多相关条款找不到
方案适用边界（视频明确）
✅ 适合：合同、法务、保险、金融风控、资质条款 —— 高风险，一句话错了就会造成业务损失
❌ 不适合：普通 FAQ、闲聊知识库、简单产品介绍 —— 太重、成本高、收益很低
评测要求：不能只用正向样例做评测；必须专门构造一批否定条款、例外条件、双重否定、条件反转的 bad case 集持续回归测试，不然上线后隐性错误很多
额外防护层（视频补充的兜底校验）：LLM 生成答案之后，可以再加一层独立的事实校验器，拿着模型输出结论去图谱查询断言极性，做二次拦截；结论和图谱断言冲突时拒绝输出、提示无法确认，而不是直接返回错误答案
回答话术规范约束：强制模型不能脱离证据直接给结论；当存在条件条款的时候，模型必须说明 “该条款生效的前提是什么”，不能单独截取半句结论
九、面试额外加分提醒（视频结尾提醒）
不要一上来就直接说上知识图谱，要先讲清楚向量的缺陷、否定过滤方案的缺陷，递进引出图谱方案；直接上来就说图谱，面试官会认为你不懂底层，只会堆方案
区分清楚：极性是业务事实属性，不是文本字面属性
