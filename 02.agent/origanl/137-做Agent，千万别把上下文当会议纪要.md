视频详细内容总结：做 Agent，千万别把上下文当会议纪要
这个视频面向大模型 Agent 开发者，核心主题是Agent 的上下文压缩，纠正一个常见误区：不要把上下文压缩等同于写会议纪要，压缩的目标是保存可执行状态，而不是输出流畅优美的聊天回顾。
一、常见错误现象
很多 Agent 生成的上下文摘要文笔流畅，但会丢失关键业务信息：订单号、否定约束条件、未完成的工具调用动作全部遗漏。就像记性差的文科生，只复述聊过什么，丢掉支撑后续执行的硬核信息，直接导致 Agent 后续任务执行出错。
核心认知：上下文压缩≠会议纪要，本质是给 Agent 做游戏存档，保存可执行状态，服务于下一轮决策，不是给人看的聊天回顾。
二、合格 “存档摘要” 必须保留 4 大类核心信息
压缩后的上下文，必须死死守住四类内容，缺一不可：
目标：用户原始需求，用户到底想要什么；
事实：已经确认好的客观事实；
进度与待办：已完成的工作、后续计划、还没有干完的事情；
约束与工具结果：不可触碰的红线约束条件，工具返回的关键结果以及结果来源。
重点提醒：硬核数据严禁意译
数字、精确时间、文件路径、专有实体、权限条件这类硬核数据，不能让大模型转述改写，意译很容易失真出错，必要时直接保留原文，一字不动。
三、不同类型信息，分层处理策略（不能一锅炖全部摘要）
针对不同信息，要用差异化压缩手段：
反复拉扯的普通对话：可以正常摘要，提炼中心思想即可；
大段日志、代码（几千行）：不要塞进上下文占用 token，落地存储，上下文里面只保留索引 / 文件路径；
工具调用轨迹
已经执行完毕：只保留结果 + 证据编号，舍弃中间过程；
正在等待返回的工具调用：必须完整保存调用 ID、当前状态，一旦丢失任务直接断线；
系统底层提示词、安全规则：绝对不能和普通历史记录一起被摘要压缩，需要单独隔离保护，防止被改写抹除。
四、上下文压缩的触发策略
不要等到 token 窗口快要爆满才紧急删减，临急压缩极易出错。
可以基于token 预算、任务阶段、信息类型做分层压缩，提前触发。
五、压缩完成后的校验环节
压缩完不能直接使用，要走检查清单校验：关键实体信息、未完成动作是否还存在，确认关键信息没有丢失才算压缩合格。
六、优秀上下文摘要的评判标准
一份高质量的 Agent 上下文摘要，不需要文采。假设换一个全新接班的 Agent 读取这份摘要，要能瞬间回答 3 个关键问题：
用户的目标到底是什么？
前面已经完成到哪一步？
依靠什么线索继续往下执行任务？
能清晰回答这三个问题，这份上下文压缩才算合格。
简单概括：Agent 上下文压缩优先保证机器可执行，而不是人类阅读体验，重点保护原始关键数据、任务进度、约束条件，做分层处理，设置提前触发机制，压缩后校验关键信息。

一、开篇提出行业现实问题（现象）
糟糕摘要的表象：很多 Agent 生成的上下文摘要读起来文笔流畅通顺，但业务执行会出问题。
具体故障例子：
丢失业务关键信息：订单号不见了；
遗忘约束：千万不能碰的否定条件被丢掉；
丢失执行链路：正在排队、尚未执行完毕的工具动作全部遗漏。
形象类比：这种错误摘要就像一个记性不好的文科生，只会复述 “刚才大家聊了什么”，但丢掉支撑后续干活的关键信息。
核心误区点：上下文压缩 ≠ 写会议纪要。很多开发者踩坑，把压缩做成了给人阅读的聊天回顾。
二、上下文压缩的本质（核心定义 + 比喻）
本质：上下文压缩的目标，是为 Agent下一次决策保存一份可执行状态，不是做优美的聊天总结。
通俗比喻：等价于打游戏的存档。存档不是复述刚才发生了什么剧情，而是保存你当前的游戏状态，方便下次接着玩。
三、这份 “存档” 必须死死守住 4 大类信息（硬性必保内容）
做压缩的时候，这四类信息不能丢失，缺一不可：
目标：用户到底想要什么（原始用户需求）。
事实：已经确认的客观事实（视频原文叫 “已经确认了哪些死理儿”）。
进度与待办：接下来的执行计划，还有哪些事情还没有干完。
约束与工具结果：绝对不能触碰的红线约束条件；关键工具返回的结果，以及工具结果的来源。
重点警告：硬核数据严禁意译改写
哪些属于硬核数据清单：具体数字、精准时间、文件路径、专有实体、权限条件。
风险：交给大模型自由转述、意译改写，一定会出问题。模型改写很容易把精确业务信息失真。
处理手段：必要场景，直接原封不动保留原文，一个字不动，不要概括。
四、不同类型信息分层处理策略（禁止一锅炖全部做摘要）
不能所有历史全部丢给大模型统一摘要，不同信息用不同处理方式：
反复拉扯的普通日常对话
处理方案：可以大胆摘要，提炼中心思想即可。
几千行大段日志、代码
处理方案：不要塞进上下文占用 token；把原始内容落盘保存到硬盘；上下文里面只保留索引或者文件路径。
工具调用轨迹（分两种状态）
①已经跑完、执行完毕的工具调用：舍弃中间执行过程，只保留结果 + 证据编号。
②正在等待返回结果的工具调用：必须完整保存调用 ID、当前状态；一旦丢失这条信息，整个任务直接断线。
系统底层提示词、安全规则
处理方案：绝对不能跟普通对话历史混在一起做摘要压缩；必须单独隔离保护。一旦被摘要改写抹除，Agent 会丢失底层规则。
五、上下文压缩的触发策略（什么时候执行压缩）
错误做法：等到 Token 窗口马上就要撑爆，才紧急删减历史。临到极限再压缩，极易丢失关键信息，容易出错。
正确触发思路：分层压缩，提前触发，不要等到上限才动手。
可以用来触发压缩的依据
Token 预算消耗情况；
当前任务推进到哪个阶段；
信息本身的类型。
六、压缩完成之后，必须做校验检查
压缩操作完成不等于结束，必须拿检查清单核对。
校验要确认两件事：
关键名字、硬核实体信息是否还存在；
还没做完的动作、待办任务是否保留。
只有确认关键信息没有丢失，本次上下文压缩才算真正过关。
七、高质量 Agent 上下文摘要的评判标准
好摘要不追求优美散文文笔，面向机器接班执行。
假想场景：换一个全新接班的 Agent 拿到这份摘要，它要能一秒钟直接回答出 3 个致命问题：
第一个问题：用户（老板）的目标到底是什么？
第二个问题：前面已经干到哪一步（当前任务进度）？
第三个问题：下一步凭什么线索继续往下干？
只要摘要可以干脆利落回答这三个问题，这份上下文摘要才算合格。
八、视频最终完整结论
Agent 上下文压缩，服务对象是Agent 后续执行决策（机器），不是人的阅读体验。
核心工作：保护原始关键硬核数据、任务目标、客观事实、约束条件、未完成动作。
工程手段：对信息做分层差异化处理；设置提前的分层压缩触发策略；压缩结束后执行关键信息校验。
