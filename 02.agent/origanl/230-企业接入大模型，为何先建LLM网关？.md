主题：面试题：企业做 AI 应用，为什么优先搭建 LLM 网关，而不是业务直接调用大模型 API
只回答 “方便管理” 属于浅层答案。
背景
项目初期只有 1 个业务、1 个模型，业务直连接口开发最快；但企业规模上来，十几个业务系统都调用大模型时，直连模式会出现：密钥、重试、超时、限流、日志、模型切换逻辑散落在各个业务代码，权限、成本、审计、稳定性全面失控。
LLM 网关三层核心价值
统一管控与安全审计
把限流、调用配额、请求脱敏、审计日志、权限控制全部收敛到网关层。如果每个业务自己实现一套，各个团队规则不一致，成本、安全风险无法管控。
模型路由 + 故障降级容灾
公有大模型会出现限流、延迟飙升、网络抖动。直连业务会直接报错；网关可以自动切换到备用模型，非核心请求降级到廉价小模型，保障业务不中断。
全链路统一观测
统一采集 token 消耗、首字延迟、耗时、缓存命中、重试、供应商错误码等指标。没有网关的话，成本核算、故障排查、SLA 保障只能靠拍脑袋。
核心结论
LLM 网关本质：把外部的大模型 API，转化为企业内部可治理的基础设施，不仅仅做请求转发，还承载权限、限流、路由、降级、审计、成本统计、可观测整套能力。
视频末尾抛出互动问题：团队做多模型接入，最先失控的是成本、稳定性，还是日志排查？
