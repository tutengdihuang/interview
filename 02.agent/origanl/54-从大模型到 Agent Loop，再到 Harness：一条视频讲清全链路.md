视频标题：从大模型到 Agent Loop，再到 Harness：一条视频讲清全链路，时长约 10 分钟，主讲人小哲，以电商用户申请退款作为贯穿全程的业务案例，系统讲解 LLM、Token、Prompt、Context、Tool、MCP、Agent Loop、Skill、Harness 一系列 AI Agent 核心概念，梳理从基础大模型到可落地业务智能体的完整技术链路。
一、开篇引入：原生大模型的局限
以场景举例：用户提问 “帮我查一下手机的订单是否可以退款”，直接丢给原始大模型无法给出正确答案。
原因：LLM（大语言模型，GPT、Claude、DeepSeek 都属于 LLM）本质能力是接收输入，预测后续生成内容；模型本身没有业务数据库，不知道用户订单、企业退款规则，缺少外部真实信息，不能凭空作答。
二、基础概念讲解
1. Token
Token 是大模型读写文字的基础单位，输入文字会被分词器切割成文字片段，模型处理的是 Token，不是原始汉字。
没有固定对应字数：一个 Token 可能是一个汉字、多个汉字片段、数字片段、英文片段。粗略估算可记 1 汉字≈1Token，但并不精准。
不同模型分词器不一样，同一段文本 Token 数量会不一样。
Token 三大影响：模型单次可读取内容上限、调用 API 计费成本、对话过长时内容删减 / 压缩策略。
精确统计 Token 消耗，不能只数字数，要查看对应模型分词器，或者读取 API 返回的用量数据。
2. Prompt 和 Context
Prompt：交给模型的任务、指令、要求，属于任务指令。例：“你是售后助手，依据公司规则判断订单退款，不要猜测订单信息”。
Context（上下文）：模型单次调用能看到的全部内容，包含系统提示词、用户历史对话、Tool 工具定义、业务资料、工具返回结果等；Prompt 是 Context 的其中一部分。
Prompt 告诉模型要做什么；Context 决定模型这一轮能看到哪些全部信息。
3. Tool（工具）
模型没有办法直接访问数据库，需要 Tool 获取外部真实数据。
案例：get order工具，输入订单号，返回订单类型、金额、签收状态。
关键点：模型不会直接操作数据库，模型只生成ToolCall工具调用意图；上层应用收到意图之后，才真正执行接口查询，再把查询结果放回 Context，重新交给模型继续判断。
Tool 作用：扩展模型能力，让模型可以调用外部系统拿到真实业务数据。
4. MCP
Tool 是具体能力；MCP 是一套标准化调用协议，二者不能混淆。
痛点：企业内多个 Agent（客服 Agent、售后 Agent 等），如果每个项目都重复实现一遍查询订单的 Tool，开发成本高、重复造轮子。
MCP 作用：提供统一连接标准，让不同 AI 应用可以发现、复用同一套外部工具能力，不用每个项目重复开发工具逻辑。
5. Agent Loop（智能体循环）
仅仅调用一次 Tool 不等于 Agent。很多场景拿到工具返回结果后，信息依旧不全，还需要多次调用不同工具，反复判断。
Agent Loop 流程：
模型判断下一步动作；
需要外部信息 → 执行 Tool 调用，工具结果回填 Context；
再次交给模型判断；
循环往复，直到不再需要调用工具，输出最终答案。
正是这个循环，把大模型从单次问答，变成可以持续完成复杂任务的 AI Agent 智能体。
6. Skill（技能）
痛点：业务规则（退款、退货、投诉）越来越多，全部塞到系统提示词，会大量消耗 Context，维护困难。
Skill 本质：封装一类任务的标准化执行流程 SOP。
案例：退款审核 Skill：先查询订单→读取退款规则→结合商品类型、签收时间、订单金额判断；金额大于 2000 元，触发人工审核。
区分：Tool 决定 Agent “能做什么”；Skill 决定 Agent “该怎么做这件事”。Tool 是能力接口，Skill 是业务执行流程说明书。
三、完整案例跑通（电商退款）
用户申请手机退款：
Agent 通过 Tool 查询订单，确认是普通手机，满足七天无理由；
订单金额 3000 元，超过 Skill 设定的 2000 元免人工审核阈值；
遵循 Skill 流程，不直接退款，流转人工处理，任务闭环结束。
四、整体链路串联 & Harness 定义
完整数据流：
用户发出任务→文本切分为 Token 送入 LLM → Prompt、历史消息、Tool 定义、工具返回结果共同组成 Context → 缺信息时模型发起 ToolCall；MCP 实现工具跨应用复用 → Agent Loop 持续循环执行工具、回填上下文、迭代判断 → Skill 约束业务流程 → 输出最终业务结果。
Harness：不是大模型本身，是围绕 LLM 搭建的整套配套系统架构。
LLM 仅负责理解与生成；Harness 就是这一整套体系，包含 Token 管理、上下文管理、Tool、MCP、Agent Loop、Skill 等全部组件，让大模型能够对接真实业务系统、获取真实数据、按照业务规则自动完成完整任务。
核心结论：Agent 应用≠单纯大模型，大模型只是其中一个部件，Harness 才是让模型落地干活的完整工程方案。
五、视频小结
很多人误以为 Agent 能力全部来自大模型本身，实际上真正让 AI 走进真实业务、自动完成复杂业务任务的，是模型外部这一整套 Harness 工程体系。

Tool 的定位结论：Tool 是用来扩展模型能力，给模型接入外部系统、获取真实业务数据的「能力抓手」。

概念 5：Agent Loop（智能体循环，核心重点）
前置问题（视频抛出）：模型调用一次 Tool、拿到一次订单信息，算不算 Agent 应用？视频明确给出答案：不算。
原因举例：拿到订单信息之后，还需要继续读取退款规则、商品类型、签收时间、退款金额等信息；如果信息不够，还需要继续调用别的 Tool。
Agent Loop 完整流程（视频原话）
① 模型判断下一步动作
② 如果缺少信息、需要外部数据 → 执行 Tool 调用
③ 把工具返回结果放回 Context
④ 再次交给模型做新一轮判断
⑤ 循环往复
⑥ 直到模型判断不再需要调用任何工具，输出最终答案
核心结论：正是这个循环，把原本只能单次问答的大模型，变成可以多步骤、自主完成复杂任务的 AI Agent。
