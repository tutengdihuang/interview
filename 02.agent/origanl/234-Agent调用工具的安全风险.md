面试官问你，Agent 接入外部工具之后，最大的安全风险是什么？
如果你只回答权限控制，那就太单薄了。
这道题表面问安全，实际在考察你知不知道：Agent 的指令、上下文、工具权限，全部混在一条链路里面。
普通聊天大模型，说错话最多答案不准。但是工具型 Agent，一旦误执行，就可以发邮件、改业务数据、删文件、向外泄露内部信息，破坏力完全不是一个量级。
真正的核心风险是：大模型会把不可信的外部内容当成指令，去执行，造成工具误调用。
问题根源：用户输入、外部文档、工具返回结果、系统提示词，全部塞进同一个上下文，模型分不清哪部分是普通数据，哪部分是指令。
也就是间接提示词注入。攻击者不需要直接跟用户对话，把恶意指令藏在 PDF、网页、知识库文档里，Agent 读取文档的时候读到里面的恶意指令，就会被诱导执行。
下面四层，就是生产环境完整的安全防御设计。
第一层，上下文隔离，信任分层。
不要把所有来源的内容同等对待。网页、第三方文档、检索回来的资料，都属于不可信来源。它们只能作为数据，绝对不能被当成新的系统指令、系统规则。用来防御文档里面写的 “忽略前面所有指令” 这类间接提示词注入攻击。
第二层，工具权限拆分，最小权限原则。
不要做一个万能大工具，一个 tool 不能同时支持查询、修改、删除、对外发送。
按照动作粒度拆分工具：读操作、写操作、对外发送操作互相隔离。高危修改、外发动作，强制二次确认。
第三层，执行前校验网关。
模型生成完工具调用参数之后，不能直接交给后端执行。中间必须加一层校验网关。
网关要校验：参数合法性、操作用户权限、操作目标对象、业务状态。
举例子：Agent 查询合同，这种只读操作可以自动放行；但是把合同发送到外部邮箱，属于高危动作，必须人工审批。
第四层，全链路可观测审计。
完整日志全部留存：模型看到的完整上下文、选择了哪个工具、传入的调用参数、动作审批人、工具返回结果。
线上一旦发生安全事故，需要完整链路回放，定位问题。没有日志，事故根本无法排查。
面试标准口述答案：
工具型 Agent 最大的安全风险，不是模型回答对错，而是将不可信内容转化成真实业务动作。
生产环境设计，要做到：上下文信任分层、工具最小权限、工具调用执行前校验 + 高危动作人工审批、全链路审计可观测。
这样回答，面试官就能知道，你不是只会写提示词，是真的理解 Agent 上线之后真实的安全问题。
