视频《如何设计全自动 AI 短剧 Agent 架构》核心内容总结
这是一道系统设计 / AI Agent 面试题讲解视频，题目：设计全自动 AI 漫剧 / 短剧创作 Agent，用户只输入一句话，系统自动产出完整短剧，还可以自查、自我迭代优化。视频核心观点：不能只靠写 Prompt 调用大模型，要做成可规划、可检查、可回滚的工程流水线。
场景举例
用户输入：“帮我做一个都市修仙短剧。男主被退婚以后觉醒系统，第一集要有爽点”，系统要自动产出剧本、角色、分镜、图片、成片视频，并且自我检查、自我修改。
5 层架构设计思路（面试答题要点）
1. 需求解析 Agent：把用户一句话转为结构化需求规格
用户输入往往信息残缺，不能直接拿去生成内容。
由需求解析 Agent 提取结构化字段：题材、目标平台、时长、受众、世界观、主角设定、剧情钩子、画风、交付格式、内容限制。
目的：后续所有环节统一依据这份规格，避免剧本、分镜、画面各自理解跑偏，成片风格混乱。
2. 拆解长链路，多角色 Agent 分工，产出明确中间资产
拒绝 “一个模型一次性生成全部内容” 的黑盒模式，拆出完整生产链路：
需求解析 → 故事大纲 → 角色设定 → 场景设定 → 剧本 → 分镜拆解 → 图像提示词 → 图片生成 → 视频生成 → 配音字幕合成成片
每个 Agent 有明确输出产物：
Script Agent：剧本、人物对白
Character Agent：角色卡（固定外貌、服装、气质）
Scene Agent：场景卡（地点、光影、氛围）
Storyboard Agent：分镜表（人物、动作、景别、情绪、镜头时长）
每一步都有输入输出边界，不是大模型自由发挥。
3. 资产一致性约束，解决漫剧最头疼的 “人物画风漂移”
最大痛点：上一镜女主红衣，下一镜蓝衣；上镜黑发，下镜银发，角色、场景前后不一致，观众出戏。
解决方案：角色卡、场景卡作为强约束。
每一轮生成图片 / 视频的提示词，都强制引用这套固定设定；镜头只允许改变动作、表情、景别，不能随意修改人物基础外观、场景基础风格。
4. Evaluator 评估器 + 局部重做（真正体现 Agent 智能，区别普通自动化脚本）
设置多类评估器，对产出做自检，发现问题只回退对应环节局部重跑，不全部从头再来。
Script Evaluator：检查剧本钩子、爽点冲突、对白是否冗余
Storyboard Evaluator：检查分镜是否可被文生图 / 视频模型执行、镜头逻辑连贯
Visual Evaluator：校验图片，角色长相服装一致性、画风、画面畸形问题
Video Evaluator：校验视频动作流畅、无抖动、音画字幕对齐
例：剧本钩子弱就回剧本模块；某张图片人物崩坏，只重拍该镜头，不用重新跑完整剧本。
5. 项目状态持久化管理（工程落地重点）
把全部中间产物存项目状态存储：结构化需求、大纲、角色卡、各版本剧本、分镜、素材、评估报告、重试记录，保存版本号与依赖关系。
带来 3 个工程收益：
故障定位：快速定位是哪一个环节出错
增量更新：用户修改需求，只重跑受影响节点，不用全流程重算，节约成本
复盘沉淀：统计不同提示词、模型组合效果，迭代系统本身
视频最终总结
全自动 AI 漫剧 Agent 本质：把不可控的多模态创作，转化为一套可规划、可执行、可评估、可回滚的工程流水线。
面试不要只回答调用 LLM、文生图接口；讲清楚上面五层，才能体现落地级的 Agent 架构思维。

面试官突然问你：\"如果让你设计一个全自动 AI 漫剧创作 Agent，用户只输入一句话，比如 ' 帮我做一个都市修仙短剧\"，系统就要自动生成剧本、角色、分镜、图片和视频，最后还能自我检查和迭代，你会怎么设计架构？
如果你一上来就回答：\" 先写个 Prompt 调大模型生成剧本，再把剧本喂给文生图和文生视频接口 '，那面试官基本上就可以送客了。
我是小哲，点赞收藏加关注，我们马上开始！想系统学习 Agent 开发的同学可以查看橱窗！这道题表面上在问你怎么调用多模态大模型，但实际在考的是你有没有复杂大模型应用落地的工程能力，也就是怎么把一个极度不可控的多模态创作任务拆解成一个可规划、可执行、可评估、可回滚的工业级 Agent 工作流水线。
先给一个核心答案：全自动漫剧创作 Agent 的本质不是靠单模型一干到底，而是通过多智能体协同编排，在底层建立标准化的输入结构和资产状态机，并通过剧本与分镜评估器的双重反馈机制实现自动迭代优化。
首先是输入结构化，这是整条流水线的基石。用户给的输入通常非常模糊，比如 \" 我要一个古风虐恋漫剧，前三秒要吸引人 '。我们不能把这句原话直接传给后续模型，必须先用一个需求解析 Agent，把自然语言提炼成包含题材、时长、目标平台、故事钩子、视觉风格、以及必须满足和严禁触碰的限制字段的结构化 Schema。后面所有的剧本、分镜 Agent 都只依靠这份结构化需求，否则每个 Agent 自行理解一遍，角色和画面风格瞬间就会跑偏。
其次是把创作过程拆解成流水线，并保证角色一致性。漫剧创作是一条极长的生产链路，需要拆成大纲生成、角色设定、场景设定、分镜拆解、提示词拼装、图文生成等独立节点，每个节点由专用的 Agent 负责。这里面最关键的是分镜拆解，因为图文模型根本吃不下整段剧情。必须先由角色 Agent 生成统一的角色卡，场景 Agent 生成场景卡，再由分镜 Agent 输出 JSON 格式的分镜控制信息，最后拼装提示词，否则上一张图女主穿红衣，下一张变蓝衣，画面一致性就会直接崩溃。
最后是自我反馈和迭代机制，这也是 Agent 架构的核心所在。不能生成一次就结束，必须引入评估器进行质量把关。设计剧本评估器检查故事节奏和冲突，设计分镜评估器校验画面描述的可行性与构图逻辑。如果评估未达标，评估器会输出结构化的修改意见，系统自动将任务回滚到前置节点重新执行，通过限制最大循环次数来防止死循环，从而实现自动纠错和局部迭代优化。
如果面试官问到这题，可以这样组织你的回答：设计这种复杂漫剧创作系统，核心是用 Agent 进行编排和工程约束。
首先在入口层通过解析 Agent 将模糊的用户需求转化为结构化 Schema 奠定标准。其次将创作管线拆解为剧本、角色、场景、分镜等独立步骤，利用标准角色卡和分镜 JSON 确保多模态生成时的角色一致性。最后引入剧本和分镜评估器，通过结构化反馈和局部回滚机制实现全自动质量迭代。
这样回答有流程、有架构、有工程闭环，面试官一听就知道你具备复杂系统落地能力。这类大模型工程化面试题，如果想系统准备可以先关注我，后面继续拆。
