三、核心业务案例：电商售后客服 Agent（视频全程唯一示例，分阶段业务场景 + 问题 + 技术方案 + 对应结论）
项目定位：一套完整前后端、可上线运行的电商售后客服 Agent，不是简单对话玩具 Demo；技术栈：Agent 后端 Python、电商业务后端 Java。
按照项目迭代顺序，4 组业务场景案例：
场景案例 1：初始版本，大模型直接充当客服对话
现象：模型不掌握店铺售后规则、退换货政策，回答容易编造规则、产生幻觉，给到用户错误售后方案。
解决方案：接入 RAG 知识库。
结论：RAG 用来解决静态业务文档、固定规则问答，把售后规范文档入库检索，回答有原文依据，减少幻觉。
场景案例 2：用户提出查订单、查物流信息
现象：RAG 只能读取静态文档，无法获取数据库里实时变化的订单、物流数据。
解决方案：接入工具调用（Function Call）能力。
结论：工具调用负责对接外部业务 API、数据库，拉取动态、实时业务数据。
场景案例 3：用户发起退款、退货申请（资金类高风险操作）
现象：不能放任大模型自主执行退款，存在资金风险；企业真实业务必须设置审批流程。
解决方案：使用 LangGraph 编排完整业务工作流，在流程中插入人工审批节点。
结论：LangGraph 负责多步骤复杂业务流程编排、分支判断、状态流转；高风险动作必须增加人工审核卡点，满足企业风控要求。
场景案例 4：用户混合诉求（同时问售后规则、查物流、提交退款申请）
解决方案：系统协同 RAG + 工具调用 + LangGraph 流程 + 对话上下文记忆共同处理。
结论：企业级 Agent 不是单一技术，是多个能力组件配合完成一条完整业务链路。
