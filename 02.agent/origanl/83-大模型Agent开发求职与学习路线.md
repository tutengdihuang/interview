一、开篇立论（视频第一部分观点）
普遍自学痛点结论：绝大多数自学 Agent 的学习者踩同一个坑 —— 只收集、背诵 JD 上的关键词，只跑通玩具 Demo，不去深挖关键词背后真实要解决的线上工程问题。
面试底层规则结论：面试官面试 Agent 开发岗，几乎不问名词定义默写；面试官的提问逻辑，全部围绕「你在落地这个能力的时候会遇到什么问题、怎么排查、怎么修复」展开。
视频给出的核心学习方法论（整套视频最核心方法）
拿到一份 Agent 开发岗位 JD 之后，不要直接去搜 LangChain、AutoGen、CrewAI 这类框架上手；
对 JD 上每一个技术关键词，强制自问 3 个问题：
这个关键词，本质要解决什么工程问题？
我独立落地它的时候，会遇到哪些异常、边界 case？
效果变差、系统出故障时，我有哪些调优、排查手段？
能回答清楚，才代表真正掌握；只知道概念 = 面试极易被刷。
二、JD 三大高频关键词逐条深度拆解（视频主体讲解，每个都包含【新手误区】【面试官深挖问题清单】【实例】【最终结论】）
2.1 关键词：RAG（检索增强生成）
新手普遍误区：很多人认为 RAG = 把文档切片丢进向量数据库，调用检索拿到结果交给大模型；Demo 跑通，就代表掌握 RAG。
面试官 / 工程层面一定会深挖的全部问题（视频逐条列出）
文档切分策略有哪些？不同切分方案分别适配什么文档类型？（举例：长论文、法律合同、客服手册、代码源码文档，切分方案不一样）
检索召回效果差的时候，完整调优方案有哪些？
如何抑制大模型幻觉？如何做内容溯源、引用标注，保证回答可校验？
召回、重排、生成三个环节故障如何分层定位？怎么判断问题出在向量库、Embedding 模型还是大模型本身？
本小节最终结论：RAG 不是简单调用向量库 API，它是一套完整的文档预处理、检索链路、效果评估、幻觉治理的工程体系。
2.2 关键词：工具调用（Function Calling）
新手普遍误区：认为工具调用就是写好 Function 的 JSON Schema，让大模型成功调用一次函数就算完成。
面试官 / 工程层面深挖全部问题（视频逐条列出）
入参校验如何实现？遇到模型输出参数缺失、参数类型错误、参数格式非法时，如何拦截和容错？
工具调用失败全场景处理：工具接口超时、上游服务报错、返回结果为空、返回脏数据、模型反复循环调用同一个工具（死循环），分别怎么处理？
工具执行完成拿到返回数据之后，如何结构化整理结果回传给大模型，并且设计规则：什么时候继续多轮推理、什么时候判定任务结束？
视频配套举例：计算器工具、数据库查询工具、联网搜索工具，在 Demo 里经常省略异常分支；但是线上生产系统，所有异常分支都必须写处理逻辑。
本小节最终结论：工具调用的难点，不在于「成功调用工具」，而在于异常链路容错、边界控制、任务终止条件设计。
2.3 关键词：Agent 架构
新手普遍误区：认为 Agent 就是套一个 ReAct（思考 - 行动 - 观察）循环模板，写好基础循环，就懂 Agent 架构。
面试官 / 工程层面深挖全部问题（视频逐条列出）
复杂用户需求如何拆解成子任务？业务场景如何判断：该用固定流程 Workflow，还是自主决策式 Agent？
Agent 任务运行状态如何持久化？任务中断之后，如何恢复、续跑？
上下文窗口如何管控？多轮执行下上下文不断膨胀、冗余信息污染推理，怎么治理？
Agent 记忆 Memory 分层怎么设计：短期对话记忆、长期业务记忆、外部知识库记忆三者边界怎么划分？
本小节最终结论：Agent 架构的核心，是任务编排、状态管理、上下文治理，而不是套用现成循环模板。
