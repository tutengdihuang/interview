视频详细内容总结：别再说 Agent 是大模型加工具了
这是面向 AI 产品经理、面试者的科普视频，核心纠正一个常见误区：Agent ≠ 大模型 + 工具调用，重点区分 LLM 大模型、工具调用、Workflow 工作流、Agent 智能体的本质差异，同时给出面试答题思路与工程落地经验。
一、面试题背后考察点
面试提问 “Agent 是不是大模型加工具”，并不是考名词背诵，面试官实际考察候选人能不能分清模型能力和系统工程两层。
如果只回答 “大模型接上 Function 工具就是 Agent”，会暴露只会调用 API，没有真实 Agent 落地经验。
二、LLM（大模型）与 Agent 形象化比喻
LLM 大模型：像一个聪明，但是没有工位、记事本、电话的人。
特点：无状态、无副作用的单次映射。一问一答，回答结束就停止；不会记住完整任务上下文，不能实际操作外部系统（改数据库、发邮件、下单），看到工具返回结果也不会主动继续推进任务。
Agent 智能体：给上面这个聪明人配齐工位，包含三样关键组件：
工具：干活的手脚；
记忆 / 记事本：保存上下文与中间结果；
循环规则：任务没完成，就不能停止工作（核心）。
运行逻辑（ReAct 模式）：想一步→做一步→看工具返回结果→再思考下一步。由 Runtime 运行层完成工具调用、结果记录、判断任务是否结束；未完成就把结果回传给大模型继续决策。
真假 Agent 判断黄金标准
会不会自主启动新一轮思考循环？
只会单次调用工具，执行完直接输出答案 → 只是工具增强版 LLM，哪怕接 20 个工具，也不是 Agent；
能够根据工具返回结果，自主决定继续思考、继续调用工具直到任务结束，才是 Agent。
三、Agent 和 Workflow（固定工作流）的区分
Workflow 工作流：执行路线是代码写死。例如强制流程：先检索、再总结、再调用工具；大模型只是流程里面的一个处理节点，没有自主选择权。
Agent 智能体：执行路线由大模型自己决策：选择什么工具、走什么步骤、什么时候停止任务，全部交给模型判断。
四、工程落地层面的现实差异
Workflow 固定流程：轮次固定，一次输入一次输出；延迟、成本可以预估，容易做兜底、风险可控。优先选择方案：能用 Workflow 解决的，就不要上 Agent。
Agent 动态循环系统：执行步数不确定，任务可能跑 3 轮，也可能跑 30 轮；成本开销波动大，存在卡死、重复调用工具、越跑越偏的风险，复杂度很高。
适用场景：只有任务路径事先无法确定，需要边执行边判断的场景，才值得使用 Agent。
企业级 Agent 比拼的不是底层大模型有多强，而是工程能力：工具设计、上下文记忆管理、异常容错、问题排查能力。大模型决定效果下限，外层工程实现决定实际效果上限。
五、面试标准答题话术
分层定义：LLM 是无状态、单次映射的推理内核，负责做决策；Agent 是在大模型外层封装了工具、记忆、循环闭环的面向目标的完整执行系统。大模型只是 Agent 的内核组件。
抛出两个判断维度：①系统会不会自主开启下一轮思考循环；②任务路径是代码硬编码，还是模型自主决策（参考 Anthropic Agent 工程文章观点）。
补充说明业界口径：行业也有宽松定义，只要包含部分模型决策就被叫做 Agent，面试时可以和面试官对齐定义。
落地视角收尾：Agent 效果不只取决于基座大模型，编排逻辑、记忆模块、容错机制等工程环节起到关键作用。

三、LLM（大模型）的定义、比喻、本质属性
通俗比喻：LLM 就像一个智商很高，但是没有工位、没有电话、没有记事本的人。
优点：你问问题，它回答很漂亮。
短板：一轮回答结束之后，就丢失状态；不能真正执行现实动作。
本质定义：无状态、无副作用的一次映射。
行为特征：
回答完一轮直接停下；
不会因为中途看到工具返回结果，主动改变后续处理流程；
不能实际做操作：改数据库、发邮件、下单这类真实动作做不了。
四、Agent 智能体：比喻、三大必备组件、Runtime 运行层、ReAct 循环逻辑
通俗比喻：给上面那个聪明的人，分配一个工位，额外配齐三样东西：
1）工具 = 干活的手（手脚）
2）记忆 / 记事本 = 保存上下文、中间执行结果
3）核心规则：活没干完，不许下班（循环机制，这是最重要）
分工边界：大模型只负责每一步思考，决定现在该干什么；真正动手执行的是外部 Runtime 运行层。
Runtime 运行层做三件事：
调用外部工具；
把工具执行结果记录回记事本（记忆）；
判断当前任务是否已经完成。
任务未完成的处理逻辑：把工具返回结果重新喂回大模型，让模型继续思考下一步。
这套就是业界 ReAct 模式，通俗概括口诀：想一步、做一步、看一眼，再想下一步。
✅【视频给出第一个黄金判别标准】
会不会自己再想一轮？
如果系统不会自主开启新一轮思考循环：哪怕接 20 个工具，只是工具比较多的 LLM，属于工具调用，不是 Agent。
如果拿到工具返回结果之后，可以自主发起新一轮思考、继续推进任务，这才是 Agent。
五、Agent vs Workflow（固定工作流）完整对比
Workflow（工作流）特征
执行路线是代码写死、硬编码；
举例：代码强制顺序逻辑：先检索、再总结、再调工具；
大模型在整套流程里面，仅仅充当其中一个处理节点，没有自主选择权。
Agent 特征
路线由模型自己决定；
模型自主选择：走哪条路径、调用哪一个工具、什么时候任务停止结束，全部交给模型判断。

六、落地工程视角：Workflow 和 Agent 的成本、风险、适用场景对比
1）Workflow（固定流程）
轮次固定，一次输入对应一次输出；
延迟、token 花费成本可预估；
容易评估效果，方便做兜底容错。
2）Agent 动态循环系统
执行步数完全不确定：同一个任务，有可能跑 3 轮，也有可能跑 30 轮；
开销成本波动很大，不可预估；
工程风险：运行中途卡死、反复重复调用同一个工具、越跑越偏，任务发散失控。
📌视频给出的工程落地重要原则（实操结论）
能用 Workflow 解决的，就不要上 Agent。
只有一类任务才值得承担 Agent 带来的高复杂度：任务路径事先说不清楚，必须边跑边判断的任务。
企业级 Agent 产品竞争关键点
企业做 Agent 产品，比拼的往往不是底层大模型有多强，而是工程层面能力：
工具设计质量
上下文记忆管理
出错之后能不能恢复（容错）
出问题之后可排查、可观测能力
金句：模型决定效果地板（下限），工程决定它能站多高（上限）。
