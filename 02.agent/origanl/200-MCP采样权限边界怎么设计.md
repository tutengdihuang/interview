视频详细总结：MCP Server 反向请求模型采样的权限边界面试解析
这是一道大模型 / 智能体开发的程序员面试题解析，题目：MCP Server 反向请求模型采样时，权限边界该如何设计。视频指出大部分求职者只知道 MCP 是工具调用协议，忽略反向采样带来的信任边界安全风险。核心总原则：采样的控制权必须掌握在客户端，MCP Server 只可以提出请求需求，不能决定权限、数据、输出去向。
一、题目背后真实考察点
不是单纯考 MCP 协议知识点，考察系统信任边界设计。
MCP 常规流程：客户端持有模型，模型调用 MCP Server 提供的工具；
反向采样（sampling）：MCP Server 反过来，向客户端发起请求，借客户端的大模型能力做生成、判断、内容补全；
风险点：MCP Server 不一定是可信服务，如果不加管控，它可以借机拿到用户完整对话、系统提示词、隐私 token、其他工具返回的敏感数据，造成信息泄露、越权攻击；协议标准不等于安全，不能因为 MCP 标准化就取消安全边界。
二、四层标准设计方案（面试答题要点）
1、客户端授权 + 请求可见
MCP Server 不能在后台静默发起采样。客户端必须完全看得见这次采样请求：要看到请求目的、输入摘要、需要的模型能力、预期输出。
普通风险请求至少做到请求透明可查看；
高风险操作，需要人工弹窗确认；
举例：代码索引服务请求模型总结代码片段，不能偷偷带上全部聊天历史，客户端能看到它的诉求是 “总结这份代码”。
2、上下文最小化（数据最小原则）
默认禁止 MCP Server 获取系统提示词、完整对话历史、其他工具返回的敏感内容，只传递完成当前任务必不可少的最小数据。
日历服务生成会议摘要：只传入会议文本，不给用户邮箱、访问令牌；
数据库服务解释数据表字段：只传入表 schema 结构，禁止给到全量业务原始数据。
3、能力隔离与结果校验
MCP Server 采样得到的模型输出，只是中间产物，不能直接升级为系统指令，也不能直接调用高危工具。
客户端要校验采样输出：检查是否越权、是否携带敏感信息、是否符合当前任务；
把外部 MCP Server 当作不完全可信组件，它的结果不能直接流入工具执行链路。
落地优化：给来自 Server 的输出打上来源标签，禁止和系统提示混在一起。
4、完整审计日志留存
全部采样请求都要保存 trace 追踪日志，记录是谁发起采样、目的、传入哪些资源、用户是否授权、模型输出内容，用于事后排查审计。
三、完整面试回答模板（可以直接口述）
我会将 MCP Server 的采样变成一套受控模型调用：由客户端决策是否允许采样、传入哪些最小上下文、选用什么模型策略、采样结果能不能继续进入工具调用链；全部请求留存 trace 审计日志。MCP Server 可以提出采样需求，但不能自主决定可读数据、生成能力、结果流向。
四、工程落地的进阶补充（面试官追问怎么实现时回答）
将 MCP Server 按信任等级划分：可信、半可信、外部第三方。外部 Server 默认只分配最小数据权限。
在客户端实现策略引擎，综合多维度做判断：Server 身份、请求目的、上下文敏感度、用户授权状态。
增加限制：管控 Server 可选模型、token 最大消耗上限、能够访问的资源范围，防止多次循环采样套取隐私上下文。
核心逻辑：协议能力越强，客户端的权限管控就要越精细，不能把权限交给 Server 自身。
五、核心结论
MCP 只是标准化连接协议，不会自动解决安全信任问题。Server 拥有请求模型的能力，不等于继承用户全部权限，所有反向采样行为的决策权必须归属客户端。

采样请求目的
请求输入摘要
需要用到的模型能力
请求的预期输出
