## 视频定位

面向 AI Agent 开发与面试场景。核心问题是：大模型是概率生成，导致 JSON 输出不稳定，线上程序解析报错。

全篇用一个贯穿案例演示：**从一段聊天文本里提取用户姓名、年龄**。

## 一、开篇抛出的真实痛点

很多新手的错误做法：只在提示词里写一句「只返回 JSON，不要多余文字」，或者反复加码强调「绝对不要输出废话」。

底层根本原因：大模型不是确定性函数，是 **token 概率接龙系统**，下一个字符是猜出来的，不是严格执行代码逻辑。

真实环境会出现的各类错误输出：

- 前面加客套说明：`好的，这是提取结果：{"name":"小明","age":18}`，自然语言直接让 `JSON.parse` 崩溃
- 套上 markdown 代码块标记 ` ```json `，解析器读到反引号直接报错
- 使用中文全角引号 `｛＂name＂:＂小明＂｝`，语法非法
- 类型错乱：年龄是数字字段，模型输出成字符串 `"age":"18"`
- 漏引号、漏逗号、多尾随逗号、字段缺失、部分截断
- 内部加注释 `//姓名`，JSON 标准不支持注释

视频观点：只靠提示词属于「软约束」，是提示词玄学，无法 100% 保证线上稳定；面试只回答「改提示词」会被扣分，生产环境就是定时炸弹。

核心思路：**不能依赖模型自觉，要搭多层防线，一层一层降低出错概率，后面层兜底前面层的失败。**

## 二、第一层防线：提示词工程（软引导，基础层）

作用：降低出错概率，但没有强制约束力；长上下文、复杂推理场景依然会失效。

要点：

- 明确写出 **JSON Schema**：字段名称、数据类型、是否必填
- 给出正确输出示例（Few-Shot 少样本），减少模型理解偏差
- 用分隔符把「指令」和「数据」隔开，避免数据里的内容被当成指令

## 三、第二层防线：模型原生结构化输出

优先使用大模型厂商提供的 **JSON Mode / Structured Outputs** 接口。

- 由模型底层约束 token 生成，强制语法、字段符合定义
- 比单纯写提示词更可靠，但仍需业务侧校验

## 四、第三层防线：Prefill 预填续写

在消息末尾预先填入 assistant 的开头 JSON 片段（如 `{"name":`），引导模型顺着继续输出 JSON。

很多 Agent 开发用这个技巧提升稳定性，属于「把模型推到正确轨道上」。

## 五、第四层防线：业务兜底（生产必不可少）

不能完全信任大模型输出：

- **清洗**：剥离 markdown 代码块、修正全角符号
- **校验**：解析捕获异常、校验必需字段与类型
- **重试/降级**：解析失败时重试，或走降级策略，用代码兜住模型的概率性错误

## 核心结论

不要迷信提示词玄学。生产环境要多层防线配合：

> 提示词 → 模型结构化接口 → 底层解码约束 → 程序容错校验

接受大模型输出的概率特性，用工程手段保障稳定性，这是 AI Agent 开发的重点基础工作。
