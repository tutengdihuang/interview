四大核心状态
会话状态（短期）
记录当前这一轮对话：用户提问、当前问题、模型的判断。生命周期只属于本次会话；临时要求（如 “用中文输出”）只在这里生效，不升级为用户长期偏好。
任务状态

哪些状态允许大模型写；哪些必须以工具返回结果为准

视频完整台词原文
面试官问 Agent 怎么设计，千万别只回答 “让它会调用工具”。
工具调用只是 Agent 的动作能力，真正考验工程设计的，是它能不能在多轮任务里管理状态：目标有没有变、步骤完成到哪、信息是否过期、外部动作是否真的成功。
先给结论：生产级 Agent 的核心不是工具列表，而是状态系统。工具只是干活的手，状态才是 Agent 的工作台。
没有状态管理，Agent 工具越多越容易出问题：重复调用同一个接口、忘掉用户刚确认的约束、把失败返回理解成成功、任务中途丢失上下文。
一共四类核心状态：
第一类，会话状态。
记录当前这一轮对话，用户的提问、当前问题、模型刚刚的判断。生命周期仅限本次会话。
比如用户说 “这次用面试口吻回答”，这是本轮临时约束，不需要升级成长期偏好。
第二类，任务状态。
只要任务多于一步，就要记录执行进度。
比如需求澄清完成、资料解锁完成、工具还未调用、等待用户确认、正在生成最终结果。
任务状态的作用：不用每一轮从头重新思考，不会漏掉流程步骤。
举例子，让 Agent 写报告，它需要记住：数据有没有拉取、报表是否生成、结论有没有核对。
第三类，用户状态。
用户身份、权限、客户等级、长期偏好、历史选择。
重点：不能靠大模型从聊天历史里猜，要存在数据库里结构化存储，确定性读取。
比如用户能访问哪些项目、默认输出格式，直接读取，不要靠向量检索模糊推断。
第四类，外部系统状态。
订单是否付款、库存、数据库写入结果、邮件是否发送。
这些事实不在大模型上下文里面。Agent 做关键决策前，必须实时查询外部系统，不能依赖上一轮记住的旧数据。
最后，还要定义状态写入策略，这是工程落地的关键点：
哪些状态允许大模型写入；哪些状态必须以工具返回结果为准；
哪些只本轮会话生效；哪些要持久化长期保存；
什么时候允许覆盖旧状态。
没有这套规则，会出现两类严重问题：
一是把临时指令错误保存成长期记忆；
二是继续使用已经失效的过期旧状态，带入后续决策。
面试回答模板：
Agent 不只是工具调用器，它首先是状态驱动系统。我会拆分成会话、任务、用户、外部系统四类状态。会话状态服务当前对话；任务状态追踪执行进度；用户状态保存长期偏好与权限；外部状态通过工具实时查询。不同状态拥有各自的生命周期、读写权限、校验方式。
