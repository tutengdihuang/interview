主题：大模型 Agent 与 Workflow 的区别（AI 面试考点）
核心观点：区分二者的关键不是有没有调用工具，而是「控制权」—— 下一步动作由谁来决定。
1、Workflow（工作流）
由程序员提前写死全部步骤、分支逻辑，模型只是流程里的一个处理节点，不能自主决定下一步怎么走。
例子：买咖啡固定流程：①下楼咖啡店→②点冰美式→③付款带回；咖啡店关门，没提前写分支就直接卡住。
优点：稳定、可控、可追溯审计。
适用场景：规则明确、风险高、步骤固定任务：审批、支付、权限校验、数据库写入等，不允许模型乱发挥。
2、Agent（智能体）
只给最终目标，不给固定步骤；大模型接收环境反馈，自主判断、自己选下一步行动，循环 “观察‑判断‑行动”。
例子：目标 “让老板喝上咖啡”，发现门店关门，模型自己决策：调用外卖、比价选店；外卖不行再考虑便利店、询问老板换饮品。不需要预先写全所有分支。
优点：擅长处理不确定性，灵活。
适用场景：资料检索、故障排查、方案规划、问题诊断等情况多变的任务。
3、工程实际用法：二者混合使用，不是二选一
生产系统主流架构：
主业务链路用 Workflow：关键操作（建工单、退款、写库、权限校验）走固定流程，保障安全可控；
局部复杂不确定节点交给 Agent：比如理解用户问题、搜集资料、分析故障原因，在受控范围内让模型自主决策。
举例客服系统：退款、建工单走 Workflow；分析用户问题、查找资料交给 Agent。

很多面试都会问，Agent 和 Workflow 的区别是什么。很多人会搞错，以为只要能调用工具就是 Agent。核心判断标准，不是有没有调用工具，是谁掌握下一步的控制权。
先说 Workflow，也就是工作流。
Workflow 是程序员提前把全部步骤、所有分支逻辑，预先写死。大模型只是这个流程里其中一个处理节点，模型没有权力决定下一步往哪走。
举个例子，任务：下楼买一杯冰美式。
Workflow 预先写好：第一步下楼，第二步到咖啡店，第三步点冰美式，第四步付款，第五步拿咖啡回来。
如果咖啡店关门了，而你没有预先写这个异常分支，整个流程就直接卡住，不会自己想别的办法。
Workflow 的优点：稳定、可控，每一步都能留日志，可以审计，风险可控。
适合的场景：规则明确、风险高、步骤固定的任务。比如审批、支付、权限校验、数据库写入。这类场景，绝对不允许模型自己乱发挥。
接下来是 Agent，智能体。
Agent 只给最终目标，不给固定步骤。大模型接收环境的反馈，自己判断，自己选下一步行动，循环：观察、判断、行动，不断迭代，直到目标完成。
同样例子：目标是让老板喝上咖啡，没有写死步骤。
Agent 发现门店关门，它自己做决策，可以调用外卖工具，比价选店；外卖不行，再考虑便利店，甚至询问老板能不能换别的饮品。所有分支不需要人预先全部写出来。
Agent 的优点：擅长不确定性场景，灵活，能应对没有预先想到的异常。
适合场景：资料检索、故障排查、方案规划、问题诊断，这类路径不确定的任务。
很多人踩坑：以为只要调用搜索、API 工具，那就是 Agent。不对。哪怕调用工具，但是每一步顺序都是代码写死，模型无权改变路径，那依然是 Workflow。
工程落地里面，二者不是二选一，主流是混合架构。
主业务链路走 Workflow。关键操作，比如建工单、退款、写数据库、权限校验，全部走固定流程，保障安全可控。
只有局部复杂、不确定的节点交给 Agent。比如理解用户问题、搜集资料、分析故障原因，在受控的范围里面，允许模型自主决策。
举客服系统例子：退款、创建工单这种强合规动作，走 Workflow；理解用户诉求、检索相关资料，交给 Agent。
最后留一个思考题给大家：电商自动客服，更偏向 Workflow，还是 Agent？
补充视频配套总结字幕要点
核心区分：控制权，谁决定下一步动作。
Workflow：预定义步骤分支；稳定可控；弱泛化，未知异常直接卡死；适合高合规、高审计要求业务。
Agent：目标驱动，运行时动态规划；ReAct 循环（观察 - 思考 - 行动）；灵活泛化；缺点：不可控、结果不确定、token 成本更高。
工程最佳实践：外层 Workflow 守住主干与安全边界，局部节点嵌入 Agent 处理不确定判断，也就是 Agentic Workflow。
选型口诀：确定的流程用 Workflow；完全不确定、分支无法穷举用 Agent；大部分业务场景用混合模式。
