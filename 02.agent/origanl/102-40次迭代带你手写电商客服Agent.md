三、项目迭代全过程（视频完整列举的业务痛点例子 + 对应解决方案，按迭代顺序）
每一次迭代，都是先遇到真实业务问题，再增加一项技术能力解决问题：
初始版本：基础大模型对话能力
问题例子：模型可以聊天，但不认识店铺业务规则，回答不准；会编造信息、AI 乱承诺、虚构物流。
解决方案：接入 RAG 检索增强生成
增加 RAG 之后的新问题：用户要查订单、实时物流，这类数据是动态的，静态知识库 RAG 无法拿到实时数据
解决方案：引入 Tool Calling 工具调用
接入工具后的新问题：退款、退货属于高风险动作，不能交给 AI 自动执行，有资损风险
解决方案：使用 LangGraph 编排工作流，增加人工审批节点
后续持续迭代：逐步补齐上下文记忆、安全防护、链路观测、效果评估、成本治理等企业级能力，一直迭代出 40 多个版本。
最终系统可以跑通的完整业务（例子）：
商品、售后规则知识库问答
用户订单查询
物流信息查询
退货、退款业务流程
高风险售后动作流转人工审批
