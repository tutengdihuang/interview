一、分层拆解故障的五大环节（面试答题主干）
1. 文档切片（Chunk 切分）层面
很多系统单纯按照固定长度切割文本，会把例外条件、否定词、适用范围、仅限、除非、脚注切到另外片段。关键约束被割裂，即便召回文档正确，证据也是残缺的。
问题现象：规则前提、限制条件和主体内容分离。
工程改进：切片不能无视语义边界；保留标题、条款编号；可扩展相邻片段，保证完整语义单元，避免把证据切成无意义碎块。
2. 重排与证据可回答性层面
片段相似度高，不等于该片段可以回答用户问题；很多片段只是沾边相关，没有覆盖问题的对象、动作、时间、限定条件。
重排不能只看相似度，还需要评估：证据能不能回答问题、文档权威等级、文档新旧版本。
重要面试加分思路：检索相关性和答案忠实性要分开评估（参考 LlamaIndex 评估思想），召回相关≠输出忠实正确答案。
3. 上下文组装环节
不要直接把 top‑k 检索结果全部无脑塞给大模型。
需要区分主证据、补充证据、互相冲突的证据；
给模型指令，要求输出时引用对应片段来源；
约束模型，禁止用自身内部常识填补证据空白；证据不足时要输出 “不确定”，而不是强行编造结论。
面试答题话术参考：不只看有没有召回正确文档，要看正确证据是否完整、排序位置是否靠前、有没有被噪声淹没、答案是否忠实于引用证据。
4. 生成约束层面
大模型存在幻觉倾向，即使有正确材料，也会自行泛化推理；如果没有强提示约束，模型会把 “有可能相关” 包装成确定结论，忽略条款的限定条件。
5. 后置评估
上线不能只看 demo 样例跑通，需要专门做忠实性评估，检测答案是否脱离检索证据。
二、面试加分点：Bad Case 坏路径样本与工程闭环
上线前要构造坏路径测试样本集，覆盖场景：
条款互相冲突、证据不足；
片段相关但是不能回答该问题；
旧版本文档、权限不足、工具调用异常；
输出格式正确，但业务语义错误的样本。
系统真正的工程能力，不只是正常问题答对；而是遇到不确定情况可以识别、拦截、兜底，不能强行输出答案。
所有 bad case 要回流评测集、线上监控；
修复问题之后，样本要加入回归测试，不能只临时修复单个 case；
涉及修改外部状态的操作，必须做好权限、幂等、确认、审计，纳入回归评测。

正确文档出现在上下文，不等于模型能正确使用证据。切片错误会割裂否定、例外条件；重排只看相似度会混入沾边无效片段；上下文直接堆砌 top‑k 结果，噪声、冲突片段会干扰模型；生成阶段没有约束，模型会用自身常识脑补内容，产生幻觉。

一、完整故障分层排查链路（5 大层级，视频原文顺序）
第一层：文档切片（Chunk 切分）
问题根因：单纯按固定长度做硬切分，不考虑语义边界。
容易被切分开的关键信息：适用范围、例外条件、否定词（不得）、除非、仅限、脚注。
故障现象：关键限制条件被切到另一个切片；哪怕召回文档本身是正确的，但拿到的证据是残缺不全。
工程落地改进要点（视频原文）：
切片不能切成没有语义边界的碎块；
切片时保留标题、条款号；
支持上下文窗口、相邻片段扩展，保证语义单元完整。
第二层：重排与证据可回答性
关键认知：相似度高 ≠ 片段能够回答问题；很多片段只是沾边相关，但无法解决用户问题。
重排不能仅依赖相似度得分，额外需要评估维度：
用户问题里面的对象、动作、时间、条件，是否被该证据片段完整覆盖；
文档权威等级；
文档新旧版本（旧版本文档需要降权）。
面试加分知识点（引用 LlamaIndex 评估思路）：检索相关性 和 答案忠实性，必须分开评估。
检索相关性：文档和问题像不像；
答案忠实性：模型输出是否严格依据证据，不脑补。
第三层：上下文组装
禁止操作：直接把 TopK 检索结果全部一股脑塞给大模型。
需要对检索回来的片段做证据分类：区分主证据、补充证据、互相冲突证据。
提示词层面约束：要求模型输出答案的时候，引用对应的证据片段。
约束模型行为：禁止大模型调用自身内置常识去填补证据空白。
兜底规则：证据不足时，应当输出 “不确定”，或者向用户追问信息，不能强行编造结论。
视频给出面试答题短句：
“我不会只看是否召回了正确文档，而会看正确证据是否完整、是否排在前面、是否被上下文噪声淹没、答案是否忠实引用。”
第四层：生成约束
问题根源：大模型幻觉倾向；即便输入上下文有正确材料，模型依然会做自主泛化推理。
现象：在缺少强提示约束的条件下，模型会把 “可能相关的信息” 包装成 “确定的结论”，忽略条款限定条件。
第五层：后置评估
上线不能只看简单 Demo 样例跑通；
必须做忠实性评估，校验模型输出答案是否脱离检索得到的证据。
