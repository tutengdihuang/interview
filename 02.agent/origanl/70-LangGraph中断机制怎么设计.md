完整交互流程（视频讲的业务调用链路）
启动任务
前端页面展示 Agent 工作流，前端发起run task请求，开启任务。
后端收到请求，调用 Graph 实例的 run () 方法，启动 LangGraph 工作流执行。
触发中断暂停
工作流一路执行，运行到人工审批节点。
Graph 返回带有中断标记的特殊格式响应给到后端，后端再把中断信号透传给前端。
此时 LangGraph 工作流暂停，状态被冻结，不会继续往下跑。
人工介入操作
前端识别到中断标记，弹出弹窗，给到用户操作界面；用户可以做同意 / 拒绝，还可以填写备注建议。
恢复工作流
用户操作完成后，前端发送resume的 POST 请求，把用户的审批结果（同意 / 拒绝、填写的建议）传给后端。
后端收到 resume 请求，再次调用 Graph 相关方法，恢复被暂停的工作流。
继续执行业务
Agent 审批节点读取前端传过来的用户审批信息，拿到同意 / 拒绝、备注建议，接着继续往下执行后续业务逻辑。
视频结尾学习观点
Agent 开发是小全栈能力，不能只懂 LangGraph 底层，还需要懂前端交互、后端接口串联，打通整套链路，知识面要广。

✅ 回答这个问题，不能只讲 LangGraph 库内部逻辑，必须站在前端、后端服务、Agent 服务（Graph 实例）三个端的视角，讲清楚三端之间怎么串联整条链路。
三、完整三端链路分步讲解（视频逐步骤讲的全部流程，顺序不可调换，全程用审批节点举例）
步骤 1：启动任务 run task
前置条件：Agent 工作流是展示在前端页面上的可视化工作流。
前端动作：前端发起一条请求，请求名称：run task，发起之后任务开始运行。
后端动作：后端接收run task请求，调用 Graph 实例的 run () 方法，启动 LangGraph 工作流。
步骤 2：执行到审批节点，触发中断
工作流持续执行，走到人工审批节点。
Graph 输出：返回特定格式的 Response 响应，响应里面携带中断标记。
流转：这个带中断标记的响应返回给后端，后端透传给前端。
状态结果：LangGraph 工作流在这里暂停、冻结，不会自动继续向下跑。
步骤 3：前端弹窗，人工介入
前端逻辑：识别到响应里面的中断标记，立刻弹出交互弹窗。
弹窗提供两个交互能力：
用户选择：同意 / 拒绝
用户输入：可以填写自己的建议、备注文字
步骤 4：前端发起 resume 请求恢复任务
用户操作完成（选同意 / 拒绝 + 写完建议）之后。
前端动作：发起一条 POST 请求，请求名称：resume，把用户刚才填写、选择的数据一起上传。
后端动作：后端收到resume请求，再次调用 Graph 对应的方法，恢复已经暂停的工作流。
步骤 5：流程恢复，读取人工输入，继续执行业务
Graph 恢复运行，流程再次走到这个审批节点。
审批节点读取数据：拿到前端传过来的人工信息：用户的选择（同意 / 拒绝）、用户填写的建议备注。
最终动作：拿到人工输入之后，工作流继续向下执行后面剩下的节点和业务逻辑。
