视频完整内容总结
视频是大模型工程化面试讲解，核心面试题：新模型上线，为什么要做答案差异对账，而不能只看评测分数？
核心观点：就算新模型整体评测平均分更高，也不能直接上线；大模型升级不止是能力变强，还会改变输出风格、拒答边界、工具调用行为，会破坏业务和下游系统，必须做差异对账，这道题本质考察大模型发布治理能力，适用于客服、审批、代码生成、结构化抽取等生产业务场景。
一、什么是差异对账
拿同一套样本，同时跑旧模型、新模型，逐项对比两者输出，不只看总分，重点核对：事实正确性、输出格式稳定性、工具调用、拒答边界、延迟、成本、用户体验。不能只看整体得分高低，要识别哪些场景变好、哪些退化变差。
二、三层差异风险（对账要检查的三个层面）
1. 语义差异（最终答案层面）
新模型总分提升，但局部行为会变：保守回答变成确定断言、简短回复变冗长解释、引用习惯改动。
风险：部分业务场景效果退化，差异会集中在特定用户、文档类型、工具场景中，只看总分看不到局部劣化问题。
2. 契约差异（中间行为 & 下游系统兼容性）
很多场景下模型输出是给程序下游消费（JSON、分类标签、工具参数、抽取字段等）。
升级后如果字段顺序、枚举取值、空值处理、输出格式改变，会直接导致下游程序报错、业务失败。
面试答题要点：不能只做普通离线评测，要重点校验结构化输出契约、工具调用兼容性，要做差异样本回放验证。
3. 灰度与回滚管控（上线流程）
禁止直接全量切换模型。正确流程：先离线对账 → 小流量灰度上线。
灰度阶段需要监控指标：成功率、拒答率、人工纠错率、格式错误率、延迟、调用成本。
发现部分业务场景退化，支持场景级路由回退，不需要把全部流量切回旧版本，实现可控发布，避免上线全靠运气。
三、差异的分类：不是所有不一样都算 bug
新旧输出出现 diff，不能一概而论判定好坏，要对差异分桶人工标注：
事实变差：高风险，必须阻断上线，事实错误、关键信息丢失；
格式变化：高危，会打挂下游系统；
拒答边界、工具调用改变：高风险，会改变 Agent 业务逻辑；
措辞表达变化：低风险，仅属于体验层面，可接受。
输出结果要区分：可接受变化、需要人工复核变化、必须阻断变化，不能凭主观感觉判断能否上线。
四、对账样本集怎么构建（面试官追问考点）
样本来源不能只来自人工标注评测集，三类样本都要纳入：
标准离线评测样本；
线上真实业务抽样、历史线上失败 case；
结构化输出、高风险业务样本。
每条样本完整留存：输入、上下文证据、工具返回结果、旧模型输出、新模型输出、人工对账判定结果。
交付产出不是单纯评测报告，而是退化清单、不可接受差异列表、可接受变化、场景路由建议，提供完整上线证据链。
五、对账报告要产出可执行决策结论
一份有效的对账报告要给出明确的行动选项：
允许直接全量上线
限制部分场景上线
需要修改 Prompt
需要修改下游解析逻辑
需要回滚工具配置 / Schema
长篇评测报告如果不能指导发布决策，就没有价值。
六、面试标准回答话术参考
我会搭建完整模型升级对账流程，使用固定评测集、线上真实抽样样本、高风险业务样本，跑新旧模型做对比，完成差异分类；之后进行灰度上线，分任务类型监控质量、格式、工具调用、拒答率、成本指标。如果出现局部场景退化，就做场景级路由和回滚调整，不会只参考评测总分高低做上线决策。

视频全文逐要点完整整理（原视频：小哲大模型 AI｜面试必考：大模型升级为何要做差异对账）
原题：面试官问 —— 新模型上线，为什么要做答案差异对账，而不是只看评测分数？
视频核心总起句：这个问题表面问模型升级评测，本质考察大模型发布治理能力。大模型不是普通代码包、不是普通依赖；升级不只是能力变强，还会改变输出风格、工具调用习惯、拒答边界，尤其客服、审批、代码生成、结构化抽取这类强业务契约场景，哪怕一处微小输出变化，都可能击穿下游业务。
一、核心定义：什么是答案差异对账（视频原话）
拿同一套输入样本，同时跑旧版本模型、新版本模型，逐项对比两份输出；
对比维度清单（视频明确列出）：
事实正确性
输出格式稳定性
工具调用行为
拒答边界
推理延迟
调用成本
用户体验
结论：不能只看一个综合评测平均分做上线决策。
二、三层风险框架（视频主体三层拆解，附带视频内举例）
第一层：语义差异风险 —— 最终答案层面的变化
描述：总分上涨是全局平均效果，但是局部样本、细分场景会退化。模型会自发改变表达倾向。
视频举例：
旧模型谨慎保守，不确定的内容会说明 “无法确认”；新模型自信化，对不确定信息直接下确定断言 → 事实错误风险上升
旧模型回复简短精炼；新模型偏好大段解释、啰嗦扩写 → 客服话术超长、用户体验变差
旧模型引用资料习惯固定；新模型引用来源、引用片段发生偏移 → 回答依据跑偏
核心结论：平均分是抹平好坏后的均值，局部劣化会被高分掩盖，单看评测分看不见这类问题。
第二层：契约差异风险 —— 中间行为、下游系统兼容性风险（视频重点强调，高危）
描述：大量线上业务，模型输出不是直接给人看，而是交给程序解析消费，存在一份隐式业务契约（Schema）。
视频举例：
结构化抽取场景：约定输出固定 JSON，固定 key 顺序、枚举值、空值写法；新模型输出字段顺序调换、多返回额外字段、空值从null改成""、枚举标签新增不在约定列表里的值 → 下游 JSON 解析代码直接抛异常、业务流程中断
Agent 工具调用场景：旧模型调用工具时参数固定传参格式；新模型参数名、参数结构、可选参数发生变化 → 工具执行失败、Agent 链路卡死
审批分类场景：旧模型只会输出【通过 / 驳回 / 待人工】三个标签；新模型新增【建议复核】标签，下游系统没有这个分支逻辑 → 流程卡住
视频原话重点：格式、字段、工具参数属于业务契约，不属于 “表达润色”，属于高危阻断项，和内容好坏无关。
第三层：灰度与回滚管控风险 —— 上线流程层面的风险
视频明确否定方案：拿到高分评测报告，直接全量切流上线。
视频给出标准流程顺序：
离线差异对账 → 小流量灰度上线
灰度阶段必须持续监控的指标清单：
回答成功率
拒答率
人工纠错率
格式错误率
推理延迟
调用成本
视频核心工程结论：不做一刀切全量回滚；支持场景级路由回退。
举例：模型在订单查询场景效果很好，但在合同抽取场景批量格式报错；不需要把全部流量切回旧模型，只把合同抽取这一类路由切回旧版，其余场景继续跑新模型。实现风险收敛、可控发布。
三、差异分级分类标准（视频明确分桶规则，人工复核判定标准）
新旧输出出现 diff，不等于都是 bug，必须人工标注分三类：
事实变差｜高风险，直接阻断上线
例子：关键信息丢失、事实编造、数据说错、结论颠倒；
格式 / 契约变化｜高危，阻断上线
例子：JSON 结构变动、标签枚举溢出、工具调用参数异常，破坏下游解析；
拒答边界、Agent 调用逻辑改变｜高风险，阻断 / 限制场景上线
例子：原本拒绝回答敏感查询，新版本放开；或者原本稳定调用某个工具，新版本不再调用；
措辞表达变化｜低风险，可接受变化
例子：同义改写、语序调整、语气微调，事实、格式、工具行为全部不变。
统一判定输出：区分【可接受变化、需要人工复核变化、必须阻断变化】，不能靠主观感觉判断。
四、对账样本集构建方案（面试官追问考点，视频完整三类样本）
对账样本不能只用人工标注评测集，三类样本必须全部纳入对账集合：

线上真实业务抽样样本 + 历史线上失败 case（重点！线上真实分布，和评测集分布不一样）
结构化输出、高风险业务专项样本（合同抽取、审批、金融查询这类一旦出错损失大的场景）
样本存储规范（视频原话）：每条样本完整留存：输入、上下文证据、工具返回结果、旧模型输出、新模型输出、人工对账判定结果。
对账交付物不是评测分数表，交付物清单：
退化清单
不可接受差异列表
可接受变化清单
场景路由建议
一句话结论：交付物要提供上线决策证据链。
