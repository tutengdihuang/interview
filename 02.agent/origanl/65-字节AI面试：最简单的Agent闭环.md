一、常见面试误区
很多候选人一上来就讲 ReAct、工具调用、记忆 Memory、Multi‑Agent 多智能体等复杂概念。
面试官问的是最简单的 Agent，如果直接堆砌高级特性，会暴露一个问题：只是会用 Agent 框架，并没有真正理解 Agent 的本质。
二、最简单 Agent 的最小闭环核心
最简单 Agent 的本质是一套循环，只有 3 个基础动作：Observe（观察）、Reason（推理 / 决策）、Act（行动），可以抽象为一个While循环：
Observe 观察：获取当下环境的现状；
Reason 决策：结合目标，判断下一步应该做什么；
Act 行动：执行对应的动作；
动作会改变环境，再次回到 Observe，开启新一轮循环，直到满足停止条件才退出。
重点易错点：最小闭环不需要长期记忆、不需要工具调用、不需要反思、不需要复杂多步规划。工具、记忆、反思、规划都是在这个基础闭环之上，后续叠加的增强能力，不是 Agent 的必备基础。
三、通俗举例：扫地机器人
Observe 观察：传感器检测到前方有墙；
Reason 决策：目标是清扫，前方不能前进，应当右转；
Act 行动：执行右转动作；
右转之后环境已经变化，不能直接结束任务，必须重新感知环境，再次观察有没有障碍物，继续判断下一步。
只有做完动作后重新感知环境，反复循环，才叫 Agent Loop 闭环。
四、Agent 的核心本质
Agent 核心不是会不会调用工具，而是：执行完行动之后，是否会重新感知环境。
如果执行完一次动作就结束，只是单次调用或者固定工作流，不是 Agent；
Agent 是反应式 Agent：只依据当前这一刻的观察结果来决定当下的动作，不需要依赖历史信息。Memory、Tool 调用都是附加增强能力。
面试考察的关键点：框架会迭代变化，但是 Agent 的基础闭环逻辑是不变的。面试官想看你剥离所有库和框架之后，能不能说出 Agent 最本源是什么。
五、面试进阶追问（视频留的思考题）
问题：Workflow 工作流本身也可以写循环不断执行，那 Workflow 循环和真正的 Agent Loop 该如何区分？
视频没有给出完整答案，提示面试会继续深挖这一点：
Workflow：步骤、分支逻辑是预先写死，人提前定义好流程路径；
Agent Loop：每一步的下一步动作，由自身观察环境之后自主决策，路径不是预先固定，环境变了决策就跟着变。
六、面试答题参考话术
最简单的 Agent 本质是持续运行的「感知‑决策‑行动」闭环。Agent 先从环境拿到当前观察，根据目标做出决策，执行动作；动作改变环境后，获取新的观察进入下一轮循环。最简形态不需要记忆、工具、反思；工具、记忆、规划都是在这个最小闭环之上增加的能力。Agent 关键特征是行动之后重新感知环境，自主决定后续步骤。
核心一句话总结
Agent 不是一堆工具和大模型的堆砌，最小 Agent = Observe‑Reason‑Act 循环；行动之后重新感知环境，才是 Agent 闭环灵魂。
