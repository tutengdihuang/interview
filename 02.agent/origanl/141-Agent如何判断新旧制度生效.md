视频内容详细总结
视频是一道大厂大模型 / Agent/RAG 面试真题讲解：知识库同时召回新旧两版制度，Agent 如何识别真正生效的版本。
核心认知：制度是否生效不能依靠语义相似度判断，是由元数据、发布时间、适用范围、废止替代关系共同决定的业务状态，不是靠大模型猜出来的。
一、核心工程闭环：入库治理 + 查询过滤 + 召回后证据校验
1、入库阶段（知识写入知识库时）
文档预处理：还原制度的标题、条款、表格、附件关联关系；
元数据打标，每个切片绑定：文档 ID、页码、版本号、发布日期、生效日期、废止日期、适用组织、权限标签、版本替代关系（哪个版本被哪份新文档替代）。
重点坑点：不能以文件上传时间当做生效时间。上传最新的文件可能只是试行稿、补充通知，不等于正式现行制度，直接取上传时间会出错。
2、查询检索阶段
解析用户 query：拆解问题中的主体、动作、业务条件、时间信息；
先做元数据前置过滤，再做向量 / 关键词召回。避免纯语义相似度淹没日期、编号、否定词；业务口语、别名做单独改写；
业务场景过滤：结合生效时间、适用组织筛选文档，再交由模型解释为什么选用该版本。
举例：差旅制度存在发布、执行、废止的过渡期，要基于业务条件输出可验证结果，而不是只输出一句结论。
3、召回完成后：证据充分性与冲突裁决
召回的片段多，不等于证据足够，需要校验片段是否覆盖用户全部问题条件；
证据冲突处理逻辑：
优先对比：来源权威性、版本、生效时间、适用范围；
如果多方证据仍然无法自动裁决，不能让模型自由编造答案，选择追问用户或者拒答；
输出答案逐条绑定原文出处（文档 ID、页码、版本），做到答案可追溯。
二、故障排查与兜底降级策略
线上排查，需要完整保存：输入、系统配置、模型版本、中间召回结果；
定位第一个结果出错的节点，再决定调参、重试、降级，禁止直接让大模型重复猜答案；
系统必须预设边界：证据不足、版本冲突、指标异常时，具备追问、降级、回退、人工接管的机制。
三、评测指标怎么设计（面试加分点）
不能只看问答对不对，需要拆分多维度指标：
切片完整性、召回 Recall、重排命中率、引用准确率、答案忠实度。
做对照实验：固定输入、数据、模型版本，仅改动一个变量，对比修改前后正确性、延迟、显存、token 消耗。
四、面试答题完整表达框架（视频给出的答题模板）
先给出核心判断：生效与否不靠语义相似度，依靠元数据、时间、适用范围、废止关系；
讲完整链路：入库打元数据 → 查询解析 + 前置过滤 → 向量召回 → 证据校验冲突裁决 → 带引用输出；
说明失败路径和边界：讲清楚容易踩的坑，以及证据不足、冲突时如何降级；
给出评测、兜底方案：指标怎么衡量，异常如何处理，线上如何监控；
上线运维：把业务指标、知识库版本做时间线，区分错误来源：是输入变化、配置、模型升级、外部数据问题；把 bug 案例加入回归测试集，防止修复一个问题，其他场景退化。
五、视频传递的核心面试思想
企业级 RAG 高级能力，不是简单检索拼接文本；而是每一次回答，都要能解释该规则为什么在当前条件下有效。版本冲突本质是知识库治理问题，不完全靠 Prompt 提示词解决。回答要讲清楚方案的适用条件、代价，而不是只讲理想情况。

视频完整逐要点整理（原样还原全部要点、例子、结论，无省略）
原题：面试官提问：知识库里面新旧两份制度同时召回，RAG/Agent 怎么识别哪一份才是真正生效的版本？
视频核心总纲一句话：这个题表面问版本判断，本质考察元数据治理、证据裁决链路；不能靠语义相似度去判断生效与否，版本裁决不能丢给大模型自己猜，要前置到检索层、证据校验层；版本冲突本质是知识库治理问题，不是单靠 Prompt 就能解决。
一、开篇先讲高频错误回答 & 对应的反驳（视频第一个重点）
❌ 错误回答 1：哪个文档上传时间最新就用哪个
视频结论：上传时间 ≠ 生效时间。一份后上传的文档可能是征求意见稿、试行稿、草稿、未盖章版本、补充通知，不代表它是现行有效制度。上传时间只是文件入库时间，不具备业务效力。
❌ 错误回答 2：让大模型看两段文本，自己判断哪个新哪个有效
视频结论：大模型只会看文字相似度，它没有内置业务规则、生效时间、适用主体、废止关系；两份制度文字高度相似时模型极易混淆、自主编造结论，上线后稳定性完全不可控。
❌ 错误回答 3：直接召回最新发布文档，默认最新替代旧版
视频结论：最新文档 ≠ 一定适用当前用户场景。存在多部门并行制度、分公司专项制度、分级适用制度、过渡期并行生效制度；新版可能只限定一部分人群适用，旧版对剩下人群继续有效。
❌ 错误回答 4：人工给所有旧文档统一打 “已废止” 标签就完事
视频结论：企业真实场景大量制度没有写废止声明、没有明确一句话 “旧版作废”，很多制度是条件覆盖式替代，不是一刀切废止；单纯依赖人工打废止标签覆盖不全、维护成本极高，很容易漏标。
视频给出核心定性结论：制度生效是由业务条件（生效时间窗口、适用主体、适用事项、发布权威层级、替代 / 覆盖关系）决定，不是文本相似度。

区分文档状态：草稿 / 征求意见稿 / 正式发文、是否盖章审批、试行版 / 正式版。
