面试官常问的一道大模型工程面试题：为什么线上日志要记录提示词版本，不能只存用户的问题？

很多人会误以为，提示词就是一段普通文案。但在生产环境，提示词本质就是大模型的运行环境，要像代码一样做版本管理。

只保存用户的提问，一旦线上出问题，你根本复现不了当时现场。

一模一样的用户输入，换一套提示词模板、换模型、改推理参数，返回结果会完全不一样。

线上很多故障，并不是模型本身变笨了，而是提示词被偷偷修改。

比如，新增一句 “回答尽量简短”，会把回答里的关键证据压缩丢失；删掉输出格式约束，下游程序直接解析报错。

这种时候你只拿着用户问题，完全还原不了当时现场，定位不了事故根因。

所以，生产环境每一次大模型调用日志，必须完整记录这四类信息：

Prompt 模板版本号

变量填充完成之后的完整 Prompt 原文

模型名称、温度、top_p 等推理参数

调用的工具、知识库版本

这四项合在一起，才构成一次调用的完整上下文，保证问题可复现。

更进一步，工程上不能直接覆盖线上提示词模板，要用提示词灰度发布 + 回滚机制。

新旧两个版本并行上线，做 A/B 对比，统计指标：准确率、拒答率、格式错误率、用户反馈。

新版本一旦效果变差、出故障，可以立刻切回旧版本，思路和后端服务发布是一模一样的。

面试标准回答一句话总结：

记录 prompt 版本，目的是问题复现、改动效果评估、灰度发布、快速回滚。提示词是会改变系统行为的运行配置，不只是一段文字。
