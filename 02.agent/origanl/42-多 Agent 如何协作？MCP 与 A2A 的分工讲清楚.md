一、开篇背景
现在单 Agent 能力已经不足，行业大量做多 Agent 协作系统，面试经常提问：多个 Agent 如何分工、怎么互相沟通。
视频先指出开发面试答题的两个常见误区：
误区 1：把多 Agent 简单理解为多次调用大模型。
只是把流程拆成多步执行，这不叫真正多 Agent。
误区 2：只会说用 CrewAI 这类框架编排 Agent。
框架只解决同一个系统内部编排；一旦要做 A 公司、B 公司跨组织、跨框架 Agent 互通，框架就失效。内部框架不等于跨组织协作方案。
想要答好面试题，必须掌握两个核心协议：MCP、A2A。
二、MCP 协议（Model Context Protocol）
定位：Agent 连接工具与数据的协议，垂直方向，单个 Agent 对接一堆工具。
类比：AI 界的 USB‑C 接口，标准化接口；也可以理解为工具的使用手册。
作用：让单个 Agent 标准化对接各类工具、数据源，给 Agent 扩充做事能力。
简单记：MCP 管 Agent 连工具。
三、A2A 协议（Agent‑to‑Agent）
定位：Agent 和 Agent 之间协作通信协议，水平方向，多个 Agent 互相配合干活。
背景：谷歌联合 50 多家企业（微软、IBM、Salesforce 等）发布，后续移交 Linux 基金会维护，它不是某一个代码框架，是跨厂商的协作标准协议。
核心能力：让不同公司、不同框架开发出来的 Agent，可以互相发现对方、派发任务、交接工作。
类比：团队协作的规则手册，规定一群 “AI 同事” 怎么配合。
A2A 里面两个关键概念（面试加分点）
Agent Card（Agent 电子名片）
每个 Agent 上线对外发布一张名片，写明自身能力、输入输出格式、需要的权限。其他 Agent 读取名片，就知道这个 Agent 能干什么，知道找谁处理任务。
任务生命周期管理
定义任务状态：提交中、运行中、已完成、失败；可以跟踪任务进度，任务异常时支持人工介入。
简单记：A2A 管 Agent 连接 Agent。
四、MCP 与 A2A 的关系（面试标准答案）
二者不是二选一，是互补配合：
单 Agent 内部，靠 MCP 去连接工具、拿数据；
多个 Agent 之间互相派活协作，靠 A2A；
MCP 是垂直：一个 Agent 向下对接工具；A2A 是水平：Agent 之间横向协作。
五、视频结尾延伸
多 Agent 系统跑通之后，下一个核心问题：如何评估 Agent 做得好不好，不能只看流程跑完，要做专门的效果评估。
面试答题简短版（视频给出的背诵话术）
MCP 侧重连接工具，给单个 Agent 对接工具和数据；A2A 侧重 Agent 之间互联，实现跨厂商 Agent 互相发现、派活交接。单 Agent 用 MCP 接工具，多 Agent 协作靠 A2A，两者搭配使用。A2A 有 Agent Card 能力名片和任务生命周期两大核心机制。
通俗比喻
MCP = 给员工配工具、电脑、资料；
A2A = 公司内部的团队制度，规定员工之间怎么找人、派活、跟进进度、交接工作。
