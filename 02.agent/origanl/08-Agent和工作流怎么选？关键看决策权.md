视频详细总结
视频主题：AI 开发中 Agent 与 Workflow（工作流）如何选型，核心判断标准是「决策权归谁」，不只是简单记 “固定用工作流、灵活用 Agent”，解决半固定半动态任务的选型困惑。
一、核心区分：决策权归属
Workflow（工作流）
预先写好全部节点、分支条件、流转顺序，由流程引擎按照预设规则驱动整体流程走向。
大模型可以嵌入在工作流里，负责某一个节点干活（提取信息、生成文本），但整个流程下一步怎么走，还是由预先配置的规则决定，不是大模型决定。
工作流不只是简单直线流程，也支持分支、条件判断，只是所有分支都要提前定义好。
Agent 智能体
只给定最终业务目标，由大模型自己根据实时拿到的信息，运行中动态做决策：要不要调用工具、调用哪个工具、调整执行顺序、重试、提前终止。整套执行路径是跑起来之后才逐步确定的，模型深度参与流程决策。
两者本质差别：工作流的分支规则是提前写死；Agent 让大模型参与执行过程中的路径决策。
二、Workflow 适用场景、优点与缺点
✅优先选 Workflow 场景
任务步骤明确、规则稳定，看重结果一致性、可复现。
举例：固定格式文档结构化提取、信息校验、模板通知生成、顺序化批量数据处理。
优势
每个节点输入输出可控；故障容易定位；链路可复现；token 与资源消耗更低。
劣势
遇到没预先覆盖的新情况，就要新增分支、修改配置；流程写太死板时，输入稍有变化就会节点失败，牵连整条流程。
三、Agent 适用场景、优点与缺点
✅优先选 Agent 场景
最终目标清晰，但中间执行路径没办法提前全部预设，后续动作依赖上一轮返回结果。
举例：开放式问题处理、多轮资料检索、信息交叉验证；上一步查到的内容会直接改变下一步查询方向，穷举所有分支会极度复杂。
优势
可以边收集信息边动态调整执行策略，适配不确定的业务路径。
劣势
大模型会出现判断错误；多轮思考 + 工具调用，耗时、token 开销更高；输出存在随机性。
注意：不要什么任务都丢给 Agent；使用 Agent 需要限制它的决策范围，并且对输出结果额外校验。
四、对半固定、半动态混合任务的方案：Workflow + Agent 组合
遇到一部分流程固定，一部分需要动态判断的任务，不要二选一，采用组合架构：
外层用 Workflow 管控主流程：核心步骤顺序、合规校验这些不能乱跳的逻辑交给工作流，保证整体流程可控。
局部环节交给 Agent：把需要动态查询、灵活探索的子步骤，交给限定好任务边界的 Agent 去执行。
效果：主流程安全可控，局部又保留灵活性；Agent 有明确任务边界，同时预留扩展节点，不用一开始写死全部细节。
五、选型决策的 3 个判断问题（实操判断清单）
做架构选型依次确认三件事：
业务的处理路径，能不能完整提前全部罗列出来？
业务对结果一致性的要求有多高？
执行过程中，有多少判断要依赖运行时才产生的新信息？
路径可提前写清、追求稳定可复现：优先 Workflow
目标明确、中间路径未知、需要运行时动态判断：优先 Agent
两种需求同时存在：两者组合使用
六、视频核心结论
做 AI 应用架构，重点不是给系统贴 “Agent” 或者 “Workflow” 标签，而是分清每一段逻辑的决策权交给谁：确定性逻辑牢牢管住交给工作流；需要探索、动态变化的部分划分清楚交给 Agent，以此设计方案。
