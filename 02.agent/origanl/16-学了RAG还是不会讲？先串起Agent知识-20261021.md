一、开篇抛出普遍痛点（视频开头原话）
很多同学分开零散学习各个大模型知识点：提示词、RAG、Embedding、向量库、LangChain、LangGraph、Function Calling。
单独看每个知识点好像看懂了，网上的 Demo 也能顺利跑起来，但是面试的时候面试官一问项目，就讲不连贯，只能零散蹦出单独概念，串不起完整系统。
【例子 1：高频翻车面试场景】
面试官提问：你来讲一下你做的 Agent 项目。
碎片化学习的求职者回答：我做了 RAG，搭建了向量库，做了文档召回、Rerank 重排。说完就没有下文了。
博主点评（视频原话）：你讲的仅仅只是 RAG 检索链路，它只是 Agent 里面众多环节里的信息获取子环节，并不是完整 Agent。面试官立刻就能判断：你分不清 RAG 和 Agent 的边界，你误以为 RAG 就等于 Agent。
【核心论断 1（视频核心分界线金句）】
RAG 解决的是信息不足的问题：大模型本身不知道私有资料，RAG 负责把外部资料检索出来，相当于给模型提供弹药；
Agent 解决的是任务执行的问题：拿到资料（弹药）之后，自主做任务规划、挑选工具、循环执行、处理报错，持续推进直到整个业务目标闭环完成；
一句话类比：RAG 是子弹，Agent 是战士；只有子弹，没有战术、规划、执行循环，没法独立完成复杂任务。
【例子 2：视频核心业务对比案例（重点）】
业务需求：老板下达任务，整理上季度全部客户反馈，筛选识别带有投诉倾向的反馈内容，归类给对应业务负责人，并且自动给负责人发送通知邮件。
只做 RAG 的系统能做到什么：只能检索客户反馈文档，回答 “哪一条客户消息属于投诉”，它不会拆解任务、不会自动分类归属、不会调用发邮件工具、无法处理中间步骤的失败；它只能回答问题，不能自主执行整套流程。
真正的 Agent 系统会完整走完：
① 读取批量客户反馈文档
② 意图识别、风险判断，标记投诉类内容
③ 按业务归属，分配给对应负责人
④ 调用邮件工具，自动组装邮件正文
⑤ 发起邮件发送
⑥ 如果中间任意一步出错（文档读取失败、工具接口超时、模型输出格式错乱），系统需要感知异常、重试或者降级上报。
