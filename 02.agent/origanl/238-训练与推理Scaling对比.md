视频核心讲训练 Scaling 和推理 Scaling 的本质区别、成本差异、企业落地选择，同时给出算法面试答题思路。
核心结论
训练 Scaling：拉高模型能力天花板；
推理 Scaling：榨干已有能力，减少失误。
两者都叫 Scaling，但一个改变模型本身，一个不改动参数，只是改变生成答案的计算过程。
1. 训练时 Scaling（Training‑time Scaling）
做三件事：加大模型参数、增加训练数据、拉长训练步数。
作用：修改模型权重参数，让模型学会新知识，提升知识、泛化的上限；
例子：7B→70B 模型，训练 token 从几百亿提升到几万亿；
成本：一次性巨大投入，周期几周～数月，门槛高；收益是全部任务通用提升；
局限：模型本身没学到的知识，后续怎么调用都不会。
2. 推理时 Scaling（Inference‑time / Test‑time Scaling）
模型权重已经固定不变，在回答请求阶段多投入算力：多次采样候选答案、重排序、反思校验、工具调用、多路径搜索。
比喻：不是换更聪明大脑，而是给更多草稿纸 + 检查时间；
作用：不会让模型学会新知识，只是减少犯错，稳定发挥已有能力；
成本：灵活，可以只给高价值请求（金融问答、复杂推理、代码）加算力，普通请求不用；
局限：不能补模型本身缺失的知识。

适用团队	基础大模型研发团队	AI 应用开发团队
4. 企业落地怎么选
基础模型团队：重点做训练 Scaling，决定模型能力边界；
应用业务团队（客服质检、合同审查、报告生成）：优先做推理 Scaling，不需要重训底模，靠多候选、校验、工具链优化输出效果。
5. 面试标准答题话术（视频给出）
训练时 scaling 和推理时 scaling 解决的是不同问题。训练时 scaling 通过扩大参数、数据和训练步数，提升模型的基础能力上限。推理时 scaling 则是在模型参数固定后，通过多次采样、搜索、校验和工具调用，把已有能力更稳定地发挥出来。前者提升天花板，后者减少失误率。应用团队通常更先做推理时优化，基础模型团队则更关注训练时扩规模。

面试官高频题：训练 Scaling vs 推理 Scaling，很多人面试在这里踩坑。
很多同学一听到 Scaling，就只会说堆算力，这个回答在大厂面试里是不合格的。Scaling 分成两种，训练时 Scaling 和推理时 Scaling，本质完全不一样。
先说训练时 Scaling，Training-time Scaling。
它做的是扩大模型参数量、增加训练数据、拉长训练步数。整个过程会修改模型的权重参数，相当于重新塑造模型的大脑，直接拉高模型能力的天花板。
举个例子，从 7B 模型扩容到 70B，训练 token 从几百亿提升到几万亿。
特点是一次性投入巨大，周期很长，几周甚至几个月，门槛极高。但收益是通用的，所有任务的基础能力都会提升。
局限性也很明显：如果知识本身没有在训练数据里出现，无论后续怎么调用，模型都不会掌握这个知识。
然后是推理时 Scaling，也叫 Test-time Scaling。
这一步，模型的权重、参数完全固定，不会改动。是用户请求进来之后，在生成答案的阶段追加算力。
比如同一个问题，多次采样生成多个候选答案，做重排序、自我反思校验、调用工具、多路径搜索。
打个比方：不是换一个更聪明的大脑，而是给模型多一些草稿纸，多一点检查的时间。
它不会让模型学到新知识，只能减少错误，把模型已经具备的能力稳定发挥出来。
成本优势非常灵活，可以只给高价值请求，像复杂数学、代码、金融问答这类请求分配更多算力，普通简单请求不用额外消耗资源。
局限：模型本身不存在的知识，推理阶段再怎么加算力，也补不回来。
那企业落地怎么选？
如果是做基础大模型的团队，核心重点就是训练 Scaling，决定这个模型能力的边界上限。
如果是业务应用团队，做 RAG、Agent、合同审查、客服质检、报告生成这类业务，优先做推理 Scaling。不用重新训练底层大模型，靠多候选采样、结果校验、工具链路，就能直接提升输出质量。
