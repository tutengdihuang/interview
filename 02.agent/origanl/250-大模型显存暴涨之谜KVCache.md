主题：KV Cache（KV 缓存）—— 解释大模型长对话显存暴涨的根源，通俗讲解大模型推理的 “短期记忆”。
核心问题
模型权重只有十几 GB，长对话、多并发的时候显存飙升到几十、上百 GB，吃掉显存的不是模型权重，而是 KV Cache。
1. 什么是 KV Cache
大模型是逐 token 一字一字生成输出。
没有 KV Cache：每生成一个新 token，都要把历史全部 token 重新做注意力计算，序列越长重复计算越多，速度很慢。
KV Cache 思路：历史 token 算出来的 Key (K)、Value (V) 不会再改变，把它们保存到显存；新 token 只计算自己，直接读取缓存好的 K/V，不用重算历史。
本质：用显存（空间）换取算力（时间），加速文本生成。
2. 面试高频：为什么只缓存 K、V，不缓存 Query (Q)？
Query 只属于当前正在生成的这一步 token，这一步结束后就没有复用价值；
而历史的 K、V，后续每一步生成都要反复读取，值得缓存；缓存 Q 只会白白浪费显存。
3. KV Cache 疯狂吃显存的 3 个原因
Transformer每一层网络都有独立一份 KV 缓存，几十层模型就几十份缓存；
对话越长、token 越多，缓存就持续追加变大；
注意力头数、隐藏维度越大，单条 token 的 KV 张量体积越大。
现象：权重 20 多 GB 的模型，长上下文 + 多并发，KV Cache 就可以把显存直接占满。
4. 主流显存优化技术
PagedAttention（分页注意力，vLLM 核心）：借鉴操作系统内存分页，KV Cache 切成小块，不需要连续显存，减少显存碎片，大幅提升并发吞吐量。
FlashAttention：优化注意力计算的数据读写搬运，降低显存访问压力，提高 GPU 利用率。
KV 量化：把 FP16/BF16 的 KV 缓存压缩成 INT8/INT4，牺牲少量精度换显存空间。
其他：前缀缓存、滑动窗口注意力、GQA 分组查询注意力。
目标：有限显存，承载更长上下文、更多并发用户。
总结
KV Cache 就是大模型推理的短期记忆系统，只存 K、V 不存 Q；靠显存换算力，避免重复计算，长对话、Agent、代码补全都依赖它；显存暴涨大多是上下文 / 并发把 KV Cache 撑大，不是模型本身权重变大。

视频完整原文（抖音：神经元出逃计划｜标题：一个缓存，为什么能省掉大模型 99% 的重复计算？KV Cache：为什么只存 K 和 V，偏偏不存 Q？）
我们平时用 ChatGPT 或 Claude，光标总像打字机一样，一个词、一个词地往外蹦。直觉上大家可能会觉得这很自然，模型写完了一个词，自然就接着往下算下一个词。但如果把视线转到 GPU 显卡的底层，看看它每吐出一个词时究竟在干什么，你会发现一件很反常识的事。
在最原始的自回归实现里，模型每往外生成一个新 token，它其实需要把前面已经写好的几百甚至上千个词，连同你最初发给它的所有提示词，原封不动地重新送进整个神经网络，从头到尾完整跑一遍前向传播。这意味着什么？
假设模型正在写一篇一千字的回答，写到第十个字时，它把前九个字重算了一遍。写到第一百个字时，它把前九十九个字重算了一遍。等写到最后一千个字的时候，它居然还要把前面的九百九十九个字，重新送进三十二层甚至八十层的网络里，完整重算一次。
这就好比一个人在稿纸上写文章，每写下一个新字之前，非要把前面已经写好的整部书稿逐字逐句重新抄写、重新推导一遍，才能落笔写下一个字。
这种巨大的计算浪费，就是大模型自回归生成在没有缓存机制前所面临的最核心痛点。而解决这个问题的核心技术，就是我们今天的主角 KV Cache，键值缓存。
今天这一期我们就从最底层的问题出发，一步步讲透：为什么模型原本非要重新计算，能不能只算新词，凭什么能把历史结果存下来，为什么缓存的偏偏是 K 和 V，而不是 Q，以及当我们用空间换取了时间之后，为什么又迎面撞上了一堵显存墙。
现在的 GPT、Llama、DeepSeek 底层几乎都是 Decoder-only 架构的大语言模型，它们的工作模式叫自回归生成，每一步前向计算都是根据当前已有的全部上下文，预测下一个最可能的 token。
我们来看一个具体的例子，假设给模型输入提示词：小明在图书馆借了，让它接着生成科幻小说。这句话一共五个词，前三个是初始输入的提示词：位置一【小明】，位置二【在图书馆借了】，后面两个是模型需要依次生成的，位置四【科幻】，位置五【小说】。
在没有缓存的情况下，模型每生成一个词，都必须做一次完整的全序列前向传播。
第一轮，根据提示词预测位置四的科幻，输入序列是前三个词：小明、在、图书馆借了，长度为三。这三个词整体送入模型，从第一层到最后一层全部位置执行特征投影、自注意力、交互和前馈网络计算。模型只取最后一个位置，也就是位置三【借了】的输出向量，预测出下一个词是科幻。这一轮前向传播共处理了三个位置。
第二轮追加新词，预测位置五的小说，把刚生成的词放进上下文序列，变成：小明 在 图书馆借了 科幻，长度变为四。因为没有保存任何中间结果，模型只能把这四个词全部重新打包，再次从头跑一遍所有的网络层。模型取当前末尾位置四【科幻】的输出向量，预测出下一个词是小说。这一轮共处理了四个位置，其中前三个位置的计算和第一轮完全一样，纯属重复劳动。
第三轮如果继续往下生成后文，上下文进一步拉长为五个词，所有五个词再次全量送进网络，从头算一遍，处理了五个位置，前面的四个位置又被彻头彻尾地重新算了一次。
算下来三轮一共处理了 3+4+5=12 个位置，可每一轮真正新产出的只有一个词。最开头的小明被完整计算了整整三次，就连刚生成的科幻也已经被算了两次。
把这个逻辑放到真实的对话里，假设你的 prompt 有一千个 token，模型要生成一千个 token 的长篇文本。在没有缓存的情况下，第一步处理一千个位置，第二步处理一千零一个位置，直到最后一步处理一千九百九十九个位置。全部加起来累计前向计算的位置总数高达 1499500 次。而如果每个位置只算它本该计算的那一次，原本只需要处理不到两千个位置。百分之九十九以上的计算量都在一遍又一遍地重算过去已知的历史。
自注意力单次计算的复杂度是序列长度的平方，每一步生成如果都要重新处理完整序列，总计算量就会恶化为三次方级别累加。文本越写到后面，模型越卡顿，GPU 的算力几乎全耗在了重复劳动上。
看到这里，很自然就会产生一个想法：既然前面的历史已经算过了，那在第二步的时候，能不能只把新生成的词【科幻】单独送进模型？答案是看你怎么定义 “只送新词”。
如果你指的是只输入科幻，同时把之前所有的中间数据彻底扔掉，那肯定不行。因为 Transformer 不是 RNN，它没有一个跨时间步维护的循环隐状态。如果你只给它一个孤零零的科幻，自注意力层向四周看去一片空白，它根本不知道小明到底在图书馆借了什么，直接丢失了全部上下文。
但如果你指的是在网络前向传播时，只让新词科幻通过各层的线性投影，而在注意力计算时让它直接去读取之前已经算好的历史结果，这不仅完全可行，而且正是 KV Cache 的核心思想。
要做到这一点，在数学上必须确认两件事：
第一，新词加入之后，前面历史词的计算结果到底会不会发生改变？如果历史会变，那缓存就没法用了。
第二，如果历史不变，我们在每一层到底要留下什么数据，才能既不重算历史，又能让新词读到完整上下文？
我们先看第一个问题：凭什么保证后面的词出现后，前面的计算结果不会变？
在日常阅读中，人是会有回溯理解的，读完整句话可能会反过来改变对开头某个词的理解。但在自回归语言模型里，这件事在数学上是严格被禁止的，原因就在于因果掩码（Causal Masking）。
在自注意力矩阵里，右上角被全部填上了负无穷大。这意味着任何一个位置在计算注意力时，只能看到它自己以及排在它前面的词，绝对看不到未来的任何词。仔细看这里的因果链条：当位置二【在图书馆】计算注意力时，它只能看到位置一【小明】和它自己。后来位置三【借了】出现了，再后来位置四【科幻】也出现了，但对于坐在位置二上的【在图书馆】来说，后面的词全都在它的未来，全都被因果掩码阻挡在世界之外。
只要模型权重固定，前置文本没被修改，位置编码规则确定，那么无论未来生成了多少个新 token，【在图书馆】在第一层看到的输入永远只有那两个词，它算出来的注意力输出永远不会变。第一层的结果不变，传给第二层的输入就绝对不变。第二层同样受因果掩码保护，它的输出也不会变。这种确定性会沿着模型的深度一层层传递下去。
在计算上这意味着：已有的历史前缀，其各层的中间表示具有确定的时间不变性。昨天算出的结果今天拿来用依然完全正确。既然它永远不变，顺手把它存下来直接复用就成了最自然的选择。
既然要缓存，那自注意力里有三个核心矩阵：Q（Query 查询）、K（Key 键）、V（Value 值）。为什么工业界公认的方案只叫 KV Cache，为什么不存 Q，为什么不叫 QKVCache，或者为什么不直接把注意力权重存下来？
我们把自注意力的计算公式写出来看一眼：
Attention=softmax(QK^T/√d)V
（注：此处页面纯文本渲染为 “Attention=softmax( d QK T )V”，公式的分式结构在复制时丢失，按上下文还原为标准写法。）
在这个公式里三者的职责完全不同：
Query 是当前位置发起的解锁请求；
Key 是各个位置用来被解锁的属性标签；
Value 则是各个位置真正包含的内容特征。
以新词【科幻】，也就是第四个位置进入某一层为例，通过线性投影他先算出属于自己的三个向量 Q4、K4、V4。接下来看注意力计算到底用到了什么：
第一，匹配打分：用当前的查询向量 Q4 去和包含自己在内的所有 K，也就是 K1、K2、K3、K4 计算点积，得到一组注意力权重。
第二，加权提取：用这组权重对所有位置的 Value，也就是 V1、V2、V3、V4 进行加权求和，得到当前层的上下文表示。
看清楚这个过程就会发现一个很关键的细节：为了完成位置四的注意力计算，模型向历史索取的仅仅是前几个位置的 K 和 V。只要把历史的 K 和 V 提前保存在显存里，新词就可以直接拿来用，完全不需要为了重新得到这几组向量，让前面的词再跑一次网络。
理解到这里，两个最常见的疑惑也就解开了。
第一，为什么不用存历史的 Q？
因为发起解锁的永远是当前的新词，前几个位置当初算出的 Q1、Q2、Q3，在它们各自生成的时刻就已经完成了使命。现在是位置四【科幻】，再查上下文根本不需要历史上的旧 Q 再次出场。
第二，能不能把算好的注意力权重矩阵直接存下来？
不行，因为发起解锁的向量换成了崭新的 Q4，新的查询向量与历史 K 计算内积，会得到一组完全不同的相关度打分，这组权重必须在当前实时算出来。
所以分工非常清晰：Q 是单步现算，用完即抛的即时请求；K 与 V 才是跨时间步，长期保留的历史特征。这就是它被称为 KV Cache 的原因。
理解了机制，我们再来看真实推理引擎里一次生成的完整生命周期。整个生成被清晰地分成两个阶段：预填充阶段 Prefill，和解码阶段 Decode。
阶段一，Prefill 预填充
当你把提示词【小明在图书馆借了】发给模型，就进入了 prefill 阶段。因为这三个词是同时给出的，模型不需要一个一个串行处理，它可以利用 GPU 的张量核心 TensorCores，把三个词拼成一个矩阵，通过矩阵乘法一次性并行算完。
这一步里模型同时完成两件事：
预测出第一个新词，位置四的科幻。
把这三个词在每一层投影出的 Key 和 Value 写入预先开辟好的显存空间，建立起初始的 KV Cache。
阶段二，Decode 逐字解码
从生成第二个新词开始，模型切换成单步循环。刚刚生成的【科幻】作为输入送回模型。这一次输入长度只有一，各层网络只为这一个位置计算它的 Q4、K4、V4。新算出的 K4 和 V4 追加到这一层 KV Cache 的末尾。再用 Q4 去和缓存里所有的 K 计算点积，得到注意力权重，再对所有的 V 加权求和，结果一层层向上传递，直到最后一层预测出下一个词，位置五的小说。
然后【小说】又作为新的输入进入下一轮循环。所以在整个 decode 的阶段，每一步需要计算的位置永远只有一个。要注意，注意力仍然要读取全部历史的 K 和 V，只是这些向量不用再重新计算了。
回到前面的例子：一千个 token 的提示词，再生成一千个 token。没有缓存时，累计要处理近一百五十万个位置。有了 KV Cache，一次 prefill 处理一千个位置，加上一千步、每步一个位置的 decode，总共只处理约两千个位置，计算量下降了将近三个数量级。
KV Cache 把重复计算大幅削减了，但它也有代价：显存占用会随着上下文的长度一起膨胀。
我们来算一笔账，一个 token 的 KV Cache 到底占多大显存？公式很直接：
单个 token 的字节数 = 2 × 2 × 层数 × kv 头数 × 头维度
为什么前面乘了两个二？
第一个二：每一层都要同时存一份 K 和一份 V。
第二个二：在常用的 FP16 或 BF16 精度下，每个数值占两个字节。
以 Llama2 70B 的规模为例，八十层网络，每层六十四个注意力头，每个头的维度是一百二十八。我们先按标准的多头注意力来算，也就是每个头都存自己的 K 和 V。把这些数字乘在一起：2×2×80×64×128 = 2621440 字节，大约 2.5MB。
这意味着每多处理或生成一个 token，显卡就要再拿出约 2.5MB 的显存来存它的 K 和 V。如果一个用户的上下文是 4096 个 token，4096 × 2.5MB，大约就是 10GB。光这一个用户 KV Cache 就要占 10GB 显存。如果线上服务同时有五十个并发请求，50 × 10GB = 500GB。光存这五十个人的 KV 就至少需要七张 80GB 的 A100 显卡，这还没算模型自身的权重。
如果遇到 128k 甚至更长的上下文，单个用户的 KV Cache 就会膨胀到 320GB 左右，显存很快就会被耗尽。
也正因为这堵显存墙，真实的 Llama2 70B 并没有这样存。它让每八个注意力头共用一组 K 和 V，KV 头数从 64 降到 8，每个 token 只要约 0.31MB，是刚才的八分之一。这种做法叫分组查询注意力 GQA，我们下一期细说。
除了显存容量会被占满，GPU 硬件底层还发生了另一个关键变化：瓶颈的位置变了。
在 Prefill 阶段，GPU 一次处理成百上千个 token，每从显存读进一个权重，就能拿来和上千个 token 做计算，计算核心满载运转。这时瓶颈在计算能力上，叫做算力受限（Compute Bound）。
但到了 Decode 的阶段，情况完全颠倒。每一步只输入一个 token，需要的浮点计算其实很少。可为了算出这一个词，GPU 必须把整个模型的权重再加上整段历史 KV Cache 从显存搬进芯片内部的计算单元，算完之后吐出一个词。下一个词进来，又要把全部权重加上又涨了一截的 KV Cache 再完整搬一遍。
算一笔账，Decode 里每搬进一个字节大约只做一次计算。而一张 A100 要每个字节做一百五十次左右的计算才能让计算单元忙起来。结果就是 GPU 强大的计算单元大部分时间都在等数据，显存带宽却被占满了。这种情况叫做访存带宽受限（Memory Bandwidth Bound）。
这也是为什么在单卡本地推理时，显卡的算力看着很高，吐字速度却很难再提上去 —— 卡住它的是搬数据的速度。
到这里，我们把 KV Cache 的来龙去脉梳理清楚了。
核心痛点：朴素的自回归生成，每一步都要把历史重算一遍，重复计算随长度平方级累加，算力大量空转。
复用依据：因果掩码保证了历史特征的时间不变性，过去算出的 K 和 V，未来依然有效。
缓存逻辑：Q 是单步现用的查询，用完即抛；所以只存 K 和 V。
两阶段运转：Prefill 并行建档，Decode 单步追加，每一步只需要计算一个位置。
现实瓶颈：空间换时间，换来了显存随上下文线性增长，也把系统瓶颈推向了访存带宽。
正因为看到了 KV Cache 带来的显存与带宽压力，业界在最近几年发展出了一系列重要的优化技术。
架构层面：MQA 和 GQA 让多个查询头共享同一组 K 和 V，把显存占用压到原来的几分之一。DeepSeek 的 MLA 则用低秩压缩把 KV Cache 压得更小。
系统层面：伯克利团队提出的 PagedAttention，像操作系统内存那样把 KV Cache 切成固定大小的页来分配，大幅减少了显存碎片和浪费。
算法层面：FlashDecoding 把长长的 KV Cache 切成小块并行读取；投机采样让小模型先猜几个词，大模型一次验证，进一步降低每个词的延迟。
理解了 KV Cache，就等于找到了现代大模型推理优化的共同出发点。下一期我们就沿着这个方向具体拆解多查询注意力与分组查询注意力，看看 MQA 和 GQA 是如何在数学和工程上把 KV Cache 的体积大幅压缩下去的。
