抖音视频详细内容总结
视频主题：RAG 面试题 ——检索出来的文档全部主题相关，却没有一篇能直接回答用户问题，该如何处理。
核心认知：文档语义相关 ≠ 可以作答；很多面试者只会回答 “换关键词重新检索”，这会暴露缺少线上项目经验。这道题考察的不是调检索，而是区分「相关性」和「答案可作答性」、证据链处理、证据不足时的兜底策略。
一、为什么会出现 “文档都相关，但答不了题”
向量检索依靠语义相似度召回，文档和问题主题沾边，不代表拥有组成答案需要的关键事实，分两类典型场景：
多跳类问题：完整答案需要整合 2 条以上分散事实。例如先查公司创始人，再查创始人籍贯，单篇文档只保存部分信息。
条件不匹配问题：文档都在聊同一个大话题，但文档内约束条件和用户提问条件对不上。例如文档都讲退款，只写满 200 元退款，用户问的是满 500 元是否退款。
❌错误做法：直接把多篇相关文档丢给大模型，让模型自行总结，极易产生幻觉、硬编答案。
二、线上工程标准处理流程（三步核心思路）
步骤 1：增加「可回答性判断」（证据充足度门禁）
检索、重排模型把候选文档压缩到 Top‑5 之后，新增分级器模块，专门判断：当前这批上下文，是否具备回答用户问题需要的全部证据，而不是完全交给大模型碰运气做判断。
步骤 2：证据充足，但碎片分散在多篇文档 → 做多跳检索，组装证据链
将原始大问题拆解为多个子问题，利用 LangChain、LlamaIndex 的组件做多跳检索；
注意子问题依赖关系：互相独立的子问题可以并行检索；如果后一个子问题需要前一步结果，必须链式执行，把上一跳的答案带入下一轮检索词；
关键避坑点：拆解子问题时不能出现指代模糊（例如 “该公司”“这个作者”），必须回填完整实体，否则下一跳检索会发生实体漂移，多跳直接失败；
把各子问题返回结果拼接成完整证据链。
步骤 3：证据不足、多跳后依旧凑不齐事实 → 兜底，禁止强行编造
线上两个降级出口：
直接告知用户知识库没有该问题的相关知识；
反问澄清用户，补齐缺失条件，再开启新一轮检索。
强调：如果不做好这层兜底，前面召回、重排全部优化都失去意义。
三、面试答题参考话术
首先要明确：检索文档主题相关不等于可以作答。检索之后需要增加一道可回答性分级判断；如果证据充足但分散于多篇文档，就拆解问题执行多跳检索，组装跨文档证据链；如果证据不充分，则直接拒答或者反问用户澄清缺失条件，绝对不允许模型硬编造答案。
四、面试官考察的底层意图
这道题目考察候选人对 RAG 完整链路的掌控，不止是召回调参，还要覆盖召回、重排、证据充分性校验、多跳证据拼接、知识库缺失时兜底降级的全链路，要求讲出线上工程落地的决策逻辑，不是只谈调关键词、调相似度阈值。

视频完整逐点整理（全部要点、例子、结论，无省略）
视频原题：RAG 召回出来的文档全部主题相关，但是没有一篇文档能够直接回答用户问题，该怎么处理？
主讲：小哲大模型八股
开篇核心总纲：这道题表面问检索，本质考察可回答性判断；核心公理：文档上下文相关 ≠ 证据充分、不等于可以生成可靠答案；只回答 “扩大召回数量、调相似度阈值、改写 query 重新搜”，属于只有 Demo 经验，没有线上生产 RAG 落地经验，面试官会扣分。
一、开篇例子（视频核心业务示例，企业差旅制度 RAG）
用户提问：外包员工出差打车能不能报销？
召回结果：返回三篇文档，全部和差旅报销主题相关
《公司差旅整体报销流程》
《外包人员通用管理办法》
《交通费、打车发票规范要求》
问题：三篇文档单独看都相关，但没有任何一篇明确写明：外包员工出差打车是否允许报销
风险：直接把这三篇丢给大模型，模型会自己脑补、融合，编造出一条不存在的制度规则，也就是幻觉。
二、理论依据
视频明确引用：LlamaIndex 的评估指标体系，区分两个独立指标
Context Relevancy：上下文相关性（判断文档和问题主题是不是一类）
Answer Faithfulness：答案忠实性（判断现有文档证据能不能支撑出确定答案）
结论：相关性是第一道门槛，相关性通过之后，还必须单独做证据充分性校验，相关性高不能自动等价于忠实性达标。
三、整套标准四步流程（视频分四层完整方案，顺序不能乱）
第 1 层：问题拆槽（证据缺口识别模块，可回答性判断的核心）
操作：把用户原始问题拆解成一组必须全部被证据覆盖的槽位（关键要素）
示例（外包打车报销问题拆槽）：
主体槽：外包员工（第三方非正式员工）
场景槽：出差场景
事项槽：打车交通费
动作槽：报销（是否允许、报销标准）
判断逻辑：
遍历召回的 Top-N（Top5）重排之后的文档片段，逐个核对：每一个槽位，是否有文档原文明确覆盖、明确约束。
本例缺口标记：差旅、打车、报销都有覆盖；唯独【外包员工是否适用该打车报销规则】这个核心约束槽，没有任何原文支撑 → 标记【证据存在关键缺口】
视频强调面试避雷点：不要上来就说扩大 TopK 召回条数；正确顺序是：先拆解问题、定义回答需要哪些证据，再判断缺什么证据。
第 2 层：基于证据缺口，定向补充检索（多跳 / 二次检索）
不是无脑重复搜原问题，而是拿着识别出来的缺口槽，改写针对性检索词：
本例缺口检索 query 示例：
“外包人员 出差交通费报销”
“第三方员工 打车报销规则”
“非正式员工 差旅补贴范围”
额外检索数据源（不止向量知识库）：
结构化制度表、FAQ 库、历史工单记录、权限黑白名单
工程约束（视频重点）：补充检索必须设置最大迭代次数上限（例如最多 2 轮补充检索），防止 Agent 无限循环、疯狂调用检索接口，打爆向量库和 LLM。
分支判定：
补充检索命中缺失槽位证据 → 证据补齐，进入证据链组装，再交给生成模块回答；
达到检索上限，依然补不齐缺口 → 停止检索，进入第三层安全答案策略。
第 3 层：安全答案输出策略（证据不足兜底分支，分 4 种可选降级出口）
禁止：直接让模型强行综合相关文档，输出确定性结论。
四个分级兜底方案（视频给出优先级顺序）
【优先方案：说明缺口，给出不确定结论】
话术模板：现有资料仅覆盖 XX、XX 内容，暂时没有明确资料说明【外包员工打车报销】这条规则，无法给出确定答复；同时列出已经查到的相关信息给用户参考，不是冷冰冰一句 “不知道”。
【主动澄清反问用户】
向用户确认缺失条件：比如是否是长期驻场外包、是否走单独外包项目预算，等用户补齐条件之后，再重新发起检索。
【转人工客服 / 工单】
业务是企业内部客服、政务、财务这类高严谨场景，自动流转人工处理，留存检索上下文给人工坐席。
【极简拒答】
高风险场景（合同、财务、合规），直接告知知识库无对应规则，不提供推测内容。
第 4 层：评测 & Badcase 闭环治理（视频压轴、加分工程层，很多候选人完全不讲）
单次问答处理完不是结束，线上系统要把这类 case 回流：
埋点统计：专门统计一类指标 ——召回相关但是证据不足的 Query 数量、缺口类型、高频问题
回流知识库运营：高频出现的缺口问题，交给运营人员，补充、修订制度文档，把缺失的规则写入知识库，从根源减少同类失败 case
迭代评估集：把这类 “相关但不可答” 样本加入评测集，持续验证可回答性分类器、槽位拆解模块的效果，持续迭代模型
四、两类底层原因分类（视频里区分两种 “相关但答不出” 场景）
场景 A：条件不匹配（上面报销例子属于这类）
文档都在大主题内，但是文档里的适用前提、约束条件，和用户提问里主体对不上；文档讲正式员工，用户问外包员工。
场景 B：多跳推理类问题（第二个例子）
示例问题：XX 公司创始人是哪里人？
召回结果：文档 1 写 XX 公司创始人是谁；文档 2 写这个人的籍贯；两篇都和问题主题高度相关，但是单独任意一篇，都无法直接回答完整问题。
对应处理方式：槽位拆解之后识别到需要两步证据，做多跳链式检索，把前一跳结果实体回填到下一跳检索词，组装完整证据链；同时提醒坑：多跳不能带模糊指代（“该人、这家公司”），必须回填完整实体名称，防止实体漂移。
五、面试标准口述完整版台词（视频原文给的标准答案）
面试官问到这个题，你可以完整这样说：
首先要区分相关性和证据充分性，召回文档主题相关，不等于文档证据足够支撑答案。
我会先对用户问题做槽位拆解，识别回答这个问题必须的全部关键条件；然后核对重排后的召回片段，判断有没有证据缺口。
如果只是证据分散、需要多跳，就基于缺口改写查询、定向补充检索，并且限制检索轮次，避免无限循环；补齐证据之后再组装证据链回答。
如果多次检索之后关键证据依然缺失，就走降级策略：向用户说明现有信息的边界、说明缺哪部分资料，或者反问用户补充条件、转人工，严禁模型自行推断编造结论。
同时线上要做埋点和 badcase 回流，持续反哺知识库，减少这类问题持续发生。

区分 Demo 玩家（只会召回 + prompt）和真正上线维护 RAG 系统的工程师。
