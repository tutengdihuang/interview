抖音视频《面试官：RAG 怎么处理复杂文档证据链？》详细总结
视频围绕一道高频 RAG 面试题展开：当证据分散在正文、脚注、附件中，RAG 如何拼装出可靠答案。视频指出，如果仅回答 “文档切片 + 向量检索”，代表只有 Demo 经验，没有企业级落地经验。以招标、合同文档举例：正文写规则，脚注写限制条件，附件放清单，任意一块缺失，就会输出错误结论。该问题本质考察文档结构理解与证据链装配能力，普通 RAG 只看文本相似度，工程级 RAG 要关注证据之间的关联关系。
业务举例：查询供应商是否满足投标条件，正文要求注册资本 500 万以上；脚注补充该条款不适用于联合体；附件存放供应商资质清单。只召回正文会得到错误结论。
整套企业级方案分为结构化解析、关联召回、答案忠实性校验三大核心步骤，同时给出面试答题模板、验收评测方案和线上运维要点。
一、第一步：结构化解析（入库阶段）
不能直接固定字数粗暴切块 PDF/Word 文档。
识别文档结构元素：标题层级、页码、脚注、表格、附件名称、条款编号，识别文档内部引用关系，例如文中 “详见附件三” 属于正文指向附件的关联关系。
切片的时候保留完整元数据：记录片段所属章节、页码、来源是正文 / 脚注还是附件、条款编号、关联的附件编号。
核心逻辑：元数据是后续跨片段、跨附件找证据的基础，缺少元数据，检索只是在一堆碎片化文本中盲搜。
二、第二步：关联召回（检索阶段）
用户提问往往只能命中正文关键词，但关键约束、清单数据存在脚注、附件表格中。
先命中主证据，再顺着引用关系向外扩展证据。比如命中正文中的资质要求，自动拉取对应的脚注、附件三内容。
多路召回并行：语义向量召回、条款编号召回、附件名 / 实体名召回。
使用重排模型过滤片段：筛除文本上相似，但不能支撑业务结论的无关片段。
三、第三步：生成与忠实性校验（答案输出阶段）
视频核心观点：RAG 最大风险不是没有答案，而是证据不全，却生成一个完整、看起来通顺的错误答案。
强制绑定结论和证据：模型输出的每一条关键判断，必须标注来源，写明来自正文哪条、脚注哪句、附件哪一项，做到答案可溯源。
证据缺失时执行拒答策略：遇到附件解析失败、关键条款缺失等证据链断裂场景，不能强行给出判断，要输出 “当前信息不足以做出判断”，或者向用户追问补充材料。
四、面试标准回答模板
我会先把文档解析成带层级、页码、脚注、表格、附件引用关系的结构化数据；检索时先命中主证据，再沿着文档引用关系补齐脚注、附件等关联证据；生成答案要求每个关键结论绑定原文引用来源；如果关键证据缺失，则拒答或者向用户追问信息；最后用跨正文‑脚注‑附件的专用测试样本做验证，而不是单纯看单段文本召回率。
五、系统验收、评测方法
不能只用关键词匹配评判答案好坏，要专门构造跨页、跨脚注、跨附件的测试样本：
校验维度：检查回答是否集齐全部判断条件，引用来源是否完整覆盖所有证据。
重点场景：合同、招投标、审计类文档，脚注、附件很可能反转最终结论。
六、上线后运维质量管控要点
监控质量指标：跟踪引用缺失、引用内容不支持结论、附件解析失败等指标，把这些作为系统质量门禁。
变更回归：修改 Prompt、更换模型、调整检索策略，必须使用同一批测试样本重跑回归，观察正确率、引用质量、延迟、成本变化。
badcase 治理：线上抽样查看调用 Trace，把真实业务产生的失败样本，回灌到评测数据集，持续迭代优化。
不只是看最终答案是否通顺，要关注整体任务的长期稳定性。
七、视频核心结论
复杂文档场景下 RAG 的本质，不是检索到一段相似度高的文本，而是拼装一条可以验证的完整证据链。面试作答要串联解析、多路召回、重排、引用溯源、证据不足拒答、评测运维整套流程，体现工程落地能力，而不是只讲 Demo 概念。

【开篇面试原题 + 面试官考察内核】
面试问题原文：关键证据分别藏在正文、脚注、附件里面，RAG 怎么把它们拼成一个可靠答案？
反面回答：只回答「文档切片 + 向量检索」→ 视频结论：这么答直接暴露只有 Demo 玩具经验，没有企业级落地经验。
问题本质考点（视频原话）：表面问检索，实际考察文档结构理解 + 证据链装配能力。
普通 Demo 版 RAG 的局限：只看文本相似度，只找相似文字片段，不关心证据之间的逻辑依赖、引用关系。
工程落地版 RAG 核心目标：不只检索相似文本，而是把分散、有依赖关系的碎片证据，组装成一条可核验、完整的证据链。
【视频核心业务示例（招投标供应商案例，视频唯一主案例）】
场景：用户提问：这个供应商是否满足投标条件？
正文条款：投标方注册资本需要≥500 万；
脚注例外约束：本条注册资本要求，不适用于联合体投标；
附件表格：存放所有供应商清单、联合体标记、资质材料；
错误风险：如果向量检索只命中正文这一段，模型会输出 “注册资本 500 万即满足”，看起来通顺，但漏掉脚注例外、附件里的联合体标记，结论完全错误；
视频结论：合同、招标文档里经常出现：正文写主规则，脚注写例外限制，附件放清单、明细、证明材料，三块任意缺失，结论反转。
【整套方案总纲（视频固定三步框架）】
整套企业级 RAG 处理方案 = 结构化解析（入库阶段）→ 关联召回（检索阶段）→ 答案忠实性校验 + 生成（输出阶段）
第一步：结构化解析（入库阶段，视频全部要点）
核心观点：不能粗暴固定字数切块 PDF/Word，不能把文档拆成一堆无关联纯文本碎片
解析目标：识别文档里所有结构元素：标题层级、章节、页码、脚注、表格、附件名称、条款编号、内部引用标记；
重点识别：文档内部的引用关系，典型标记：详见附件三、见本条款脚注、参见 XX 附表；
切片规则：按语义 / 结构单元切，不是按固定 token 硬切；
强制绑定元数据（metadata，视频强调是整个方案的地基）：
每一个切片 / 节点，必须记录：
所属章节、标题
页码
来源标记：正文 / 脚注 / 附件 / 表格
条款编号、附件编号
该片段指向哪些其他片段（引用关系指针）
视频结论：元数据 + 引用关系索引，是后面跨片段、跨附件自动补齐证据的基础；没有这套索引，检索就是盲搜。
第二步：关联召回（检索阶段，视频全部要点）
核心观点：用户的关键词提问，通常只能命中主证据（正文），但约束条件、明细数据藏在脚注、附件表格里，必须顺着引用链条拉取配套证据。
召回逻辑顺序：先命中主证据 → 顺着文档预先识别好的引用关系，向外扩展召回关联证据（脚注、对应附件、附表）；不是无差别全库召回；
多路并行召回（多路召回）：
语义向量召回（处理自然语言模糊提问）
条款编号、附件名称、实体编号精确召回（匹配 “附件三、条款 7.2” 这类精确引用）
后置过滤：重排模型（Reranker）筛选，剔除文本语义相似、但是对当前业务判断无关、不能支撑结论的噪声片段；
视频重点提醒：不能只靠向量相似度决定要不要召回。
第三步：生成 + 答案忠实性校验（输出阶段，视频全部要点）
视频核心警示句：RAG 最大风险，不是找不到答案、没有召回结果；而是证据残缺不全，但大模型依然生成一段通顺、看起来很合理的错误结论（幻觉）
生成强制规则：模型输出的每一条关键判断、结论，必须绑定证据来源标注；标注要写清楚：来自正文哪一条、脚注哪一句、附件哪一项、页码；做到答案可溯源，用户可以直接定位原文核对；
兜底拒答策略（视频重点加分项，面试必说）：
遇到：附件解析失败、关键脚注没有召回、引用的附表缺失、证据链断裂场景；
→ 禁止强行拼凑结论；两种兜底：
① 输出说明：当前获取到的证据信息不足，无法给出可靠判断；
② 向用户追问，提示缺失哪些材料（比如缺少附件三）；
隐含校验：如果召回的多条证据互相冲突（正文和脚注矛盾），不能自动折中调和，要同时展示冲突证据 + 各自来源。
【视频给出的面试口述标准模板（原文一字版）】
我会先把文档解析成带层级、页码、脚注、表格、附件引用关系的结构化数据；检索时先命中主证据，再沿着文档引用关系补齐脚注、附件等关联证据；生成答案要求每个关键结论绑定原文引用来源；如果关键证据缺失，则拒答或者向用户追问信息；最后用跨正文‑脚注‑附件的专用测试样本做验证，而不是单纯看单段文本召回率。
【评测验收方案（视频单独一节，全部要点）】
视频明确：不能用普通问答集、关键词匹配来验收这套系统
专门构造跨位置测试用例：跨正文、跨脚注、跨附件、跨表格的测试样本（就是上面供应商投标这种案例）；
评测校验维度（视频列出）：
是否集齐全部用于判断的必要条件证据；
引用来源是否完整覆盖全部支撑材料；
有没有漏掉例外、限制条款；
适用高风险业务：合同、招投标、审计、法务文档；这类场景脚注、附件经常直接反转结论。
反对比：很多 Demo 评测只看单段召回率，这个指标对复杂证据链场景无效。
【上线运维、质量管控要点（视频最后一节运维闭环）】
建立专项监控指标（不是只监控召回率）：
引用缺失率
召回内容不支持最终结论（证据不匹配）
附件 / 表格解析失败率
视频结论：这些指标才是复杂文档 RAG 的质量门禁；
变更回归机制：只要修改 Prompt、更换 Embedding 模型、更换 Reranker、调整分块策略；必须用同一批跨证据链测试样本重跑回归；观测指标：正确率、引用完整性、接口延迟、调用成本；
Badcase 治理流程：线上抽样查看调用 Trace 链路；把真实业务产生的错误案例（漏脚注、漏附件导致答错）回灌进评测数据集，持续迭代；
运维关注点：不只看最终回答文字通顺度，重点看整套证据链路长期稳定。
【视频收尾最终结论（原话）】
复杂文档场景下 RAG 的本质：不是检索到一段相似度高的文本，而是拼装一条可以核验、可追溯的完整证据链。
面试回答要串联：结构化解析、多路关联召回、重排过滤、溯源引用生成、证据不足拒答、专项评测、回归运维整套闭环；只讲切块 + 向量检索，只能证明跑过 Demo，没有上线工程经验。
【视频隐含面试追问提示（视频内附带）】
面试官如果继续追问：“都召回回来直接丢给模型不就行了？”
视频隐含回答：全部片段直接丢上下文，会出现信息混杂、模型自动忽略脚注例外、自动忽略附件约束，依然会幻觉；必须先建立证据依赖关系，再约束模型基于完整证据、标注来源、缺证据就拒绝判断。
