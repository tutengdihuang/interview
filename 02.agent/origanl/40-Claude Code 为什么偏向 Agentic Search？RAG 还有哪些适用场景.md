视频详细内容总结
视频主题：Claude Code 为什么偏向 Agentic Search，RAG 还有哪些适用场景，主讲人小哲，围绕 AI 开发两条主流技术路线、RAG 现实价值、工业落地难点、Multi‑Agent 现状、项目落地理念展开讲解。
一、AI Agent 开发两大技术路线
现在工业界 Agent 开发主要两条路线：
基于 LangChain：固定 Workflow 业务流路线
适合业务流程明确的业务场景，RAG 在这条路线里依然具备很高实用价值。
基于 LangGraph：Multi‑Agent 多智能体（ReAct）路线
支持模型反思思考、多个智能体协同工作，也就是 Agentic Search 这类智能体自主检索模式。
视频观点：网上流传 “RAG 已死” 说法并不符合工业真实情况，RAG 没有被淘汰，只是使用方式发生变化。
二、RAG 的核心适用场景（为什么工业界还在用 RAG）
RAG 最大价值集中在垂直行业私有数据场景：
很多行业拥有大量不对外公开的私有业务数据，没办法靠大模型自带知识、也不能靠外部搜索获取，只能搭建私有 RAG 知识库，把内部私有数据给大模型使用，这是 RAG 不可替代的阵地。
三、工业级 RAG 落地，远不止搭建向量库那么简单
很多人以为只要建向量数据库、做文本分块 chunk 就完成 RAG 系统，实际上线要解决一大堆工程难题：
检索优化层面
如何提升召回率；多路召回策略设计；接入知识图谱；reranker 重排序；
单纯文本切 chunk（chunk）不足以解决召回问题，分块策略只是其中一小部分工作。
业务与安全层面
前端意图识别模块：需要做拒答、风险兜底；可以选择大模型识别、关键词字典、混合策略等多种实现方式，保障系统安全。
上线工程化层面（最容易被概念教程忽略）
全链路溯源：用户 query 经过系统哪些模块，需要完整链路追踪；
测试环节：冒烟测试、压力测试、灰度发布；
运行指标：兜底降级策略、全流程响应延迟等线上指标把控。
以上所有问题，只有真正做过上线工业项目才会完整接触到，看教程学概念很难体会。
四、Multi‑Agent（LangGraph/Agentic Search）的现实生产现状
虽然 LangGraph、ReAct 多智能体概念很火，但现实情况：
真正把 Multi‑Agent 系统稳定跑在企业生产环境的项目非常少。
多数多智能体项目停留在个人使用、Demo 原型；
仅适合容错度高、业务简单的场景；复杂企业业务直接上 Multi‑Agent 风险很高。
也解释了 Claude Code 选择 Agentic Search 是针对代码这个特定场景的最优解，不等于所有业务都要抛弃 RAG。
五、视频核心的项目开发理念
选型原则：优先做可以真正上线的项目，而不是追新潮概念。
技术没有绝对好坏：RAG 和 Multi‑Agent 不是非此即彼，要匹配自身业务 workflow。
实践大于概念：很多架构、策略问题，要在真实项目问题中才能吃透；只学习理论概念，理解不到工业项目的真实要求。
补充隐含结论（结合主题 Claude Code）
Agentic Search（智能体自主搜索、多轮工具调用）更适配代码场景：模型自主调用工具多轮探索、反思迭代；
但垂直私有业务数据、固定业务流程场景，RAG 依旧是首选方案，两者是互补，不是互相替代。
