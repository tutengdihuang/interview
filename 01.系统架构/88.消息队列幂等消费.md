## 🎯 一句话定位

**消息队列幂等消费解决什么问题？**
```
消息重复投递导致重复消费
用户付了一次款，积分加了两次

**生活化比喻**：
就像快递签收：
- 快递员送了一次（消息投递）

- 快递公司的系统要能识别"已签收"

## 一、重复消费问题

### ❌ 典型事故

```
支付成功后发 MQ 消息给积分服务

问题：
- 订单服务只投递了一次消息
- 积分服务执行了两次消费逻辑

## 三、三层幂等防线

### 3.1 数据库唯一键约束

```go
// 利用业务唯一 ID 建立唯一索引
func AddPoints(msg *Message) error {
    // 唯一索引：user_id + order_id
    err := db.Exec("INSERT INTO points (user_id, order_id, points) VALUES (?, ?, ?)",
        msg.UserID, msg.OrderID, msg.Points)
    
    if isDuplicateKeyError(err) {
        // 重复消费，直接忽略
        return nil
    }
    
    return err
}
```

### 3.2 幂等表校验

```go
// 维护消息消费记录表
func ProcessMessage(msg *Message) error {
    // 1. 查询是否已处理
    record := db.GetConsumeRecord(msg.MessageID)
    if record != nil {
        return nil // 已处理，幂等返回
    }
    
    // 2. 执行业务逻辑 + 插入记录（同一事务）
    tx := db.Begin()
    
    // 执行业务
    err := doBusiness(tx, msg)
    if err != nil {
        tx.Rollback()
        return err
    }
    
    // 插入消费记录
    tx.Exec("INSERT INTO consume_record (message_id, consumed_at) VALUES (?, ?)",
        msg.MessageID, time.Now())
    
    tx.Commit()
    
    return nil
}
```

### 3.3 状态机流转

```go
// 只允许状态向前流转
func UpdateOrderStatus(orderID string, newStatus string) error {
    // 查询当前状态
    order := db.GetOrder(orderID)
    
    // 状态机校验
    if !canTransition(order.Status, newStatus) {
        // 重复消息，状态已是目标状态
        return nil
    }
    
    // 更新状态
    return db.Exec("UPDATE orders SET status = ? WHERE id = ?",
        newStatus, orderID)
}

func canTransition(from, to string) bool {
    // 定义状态转换规则
    transitions := map[string][]string{
        "CREATED":   {"PAID", "CANCELLED"},
        "PAID":      {"SHIPPED", "REFUNDED"},
        "SHIPPED":   {"DELIVERED"},
        "DELIVERED": {},
    }
    
    for _, allowed := range transitions[from] {
        if allowed == to {
            return true
        }
    }
    return false
}
```

func ConsumeMessage(msg *Message) error {
    err := doBusiness(msg)
    
    if err != nil {
        // 业务异常：进入死信队列

        // 系统异常：触发重试

七、技术深入探讨

### Q1: 消息重复消费怎么处理？

**方案参考**：
> 消息重复消费通过幂等性解决：
> 
> 1. **数据库唯一键**：利用业务唯一 ID 建立唯一索引，重复插入直接报错
> 2. **幂等表校验**：维护消费记录表，消费前查询是否已处理
> 3. **状态机流转**：只允许状态向前流转，重复消息遇到已完成状态直接忽略
> 
> 核心是保证同一条消息执行多少次结果都一致。

### Q2: 如何设计幂等性方案？

**方案参考**：
> 幂等性设计分三层：
> 
> 1. **业务分级**：强幂等（核心交易）严格去重，弱幂等（通知）轻量校验
> 2. **三层防线**：唯一键约束 + 幂等表校验 + 状态机流转
> 3. **生产端去重**：消息携带唯一业务标识，配合 MQ 端去重
> 
> 核心是根据业务场景选择方案，不能一刀切。
