### 3.4 高并发流量冲击

**问题**：
```
流量洪峰超过数据库承受能力
```

**解决方案**：
```java
// ✅ 多级缓存：本地缓存 + Redis 缓存
@Component
public class MultiLevelCache {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    private Cache<String, String> localCache = CacheBuilder.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    public String get(String key) {
        // 1. 先查本地缓存
        String value = localCache.getIfPresent(key);
        if (value != null) {
            return value;
        }
        
        // 2. 再查 Redis 缓存
        value = redisTemplate.opsForValue().get(key);
        if (value != null) {
            // 写入本地缓存
            localCache.put(key, value);
            return value;
        }
        
        // 3. 最后查数据库
        value = queryFromDB(key);
        if (value != null) {
            // 写入 Redis 和本地缓存
            redisTemplate.opsForValue().set(key, value, 1, TimeUnit.HOURS);
            localCache.put(key, value);
        }
        
        return value;
    }
}
```

**分布式锁阻拦突增请求**：

// ✅ 分布式锁
public String getWithLock(String key) {
    String lockKey = "lock:" + key;
    
    if (redisLock.tryLock(lockKey, 10, TimeUnit.SECONDS)) {
        try {
            // 查询缓存或数据库
            return get(key);
        } finally {
            redisLock.unlock(lockKey);
        }
    } else {
        // 获取锁失败，返回兜底数据

    }
}

### 3.5 上线引发的雪崩

**问题**：
```
服务重启后，缓存全部失效，请求涌入数据库
```

**解决方案**：
```java
// ✅ 缓存预热
@Component
public class CacheWarmup {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductMapper productMapper;
    
    @PostConstruct
    public void warmup() {
        // 分批次加载热点数据
        List<Product> hotProducts = productMapper.selectHotProducts(1000);
        
        for (Product product : hotProducts) {
            String key = "product:" + product.getId();
            redisTemplate.opsForValue().set(key, JSON.toJSONString(product), 1, TimeUnit.HOURS);
        }
        
        log.info("缓存预热完成，加载了 {} 个热点商品", hotProducts.size());
    }
}
```

**生活化比喻**：

### Q1: 怎么避免批量 key 同时失效？

**答**：
> 解决方案：随机过期时间
>
> ```java
> int expireTime = 3600 + new Random().nextInt(300);
> redisTemplate.opsForValue().set(key, value, expireTime, TimeUnit.SECONDS);
> ```
>
> 原理：在基础过期时间上加上随机时间（0-300 秒），错开缓存失效时间，避免集体失效。

### Q2: Redis 集群整体宕机该如何应急兜底？

**答**：
> 应急兜底方案：
>
> 1. **多级缓存**：本地缓存 + Redis 缓存，Redis 宕机后本地缓存还能抵挡一部分请求
> 2. **数据库兜底**：缓存全部失效后，请求打到数据库，但要开启限流保护数据库
> 3. **服务降级**：返回兜底数据，避免服务完全不可用
> 4. **快速恢复**：启动缓存预热，快速恢复热点数据

### Q3: 高并发场景下如何搭配多重策略？

**答**：
> 多重策略组合：
>
> 1. **本地缓存**：抵挡 80% 的重复请求
> 2. **Redis 缓存**：抵挡 15% 的请求
> 3. **分布式锁**：防止缓存击穿，保护数据库
> 4. **限流熔断**：防止流量洪峰超过系统承受能力
> 5. **服务降级**：系统不可用时返回兜底数据
