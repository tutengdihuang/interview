## 二、第一层：网关流量治理与转发优化

### 2.1 流量分层隔离

**代码示例**：
```java
// ✅ 流量分层
@Configuration
public class GatewayConfig {
    
    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
            // 核心接口 - 独立线程池
            .route("order-service", r -> r.path("/api/order/**")
                .filters(f -> f.requestRateLimiter(c -> {
                    c.setKeyResolver(userKeyResolver());
                    c.setRedisRateLimiter(new RedisRateLimiter(100, 200));
                }))
                .uri("lb://order-service"))
            
            // 非核心接口 - 共享线程池
            .route("logistics-service", r -> r.path("/api/logistics/**")
                .filters(f -> f.requestRateLimiter(c -> {
                    c.setKeyResolver(userKeyResolver());
                    c.setRedisRateLimiter(new RedisRateLimiter(50, 100));
                }))
                .uri("lb://logistics-service"))
            .build();
    }
}
```

**生活化比喻**：
```
就像商场：
- VIP 通道：高端用户，快速通行
- 普通通道：普通用户，正常通行
- 快速通道：紧急事务，优先处理
```

## 三、第二层：熔断降级精细化策略设计

### 3.1 熔断分级管控

**代码示例（Sentinel）**：
```java
// ✅ 熔断配置
@SentinelResource(
    value = "queryLogistics",
    fallback = "logisticsFallback"
)
public LogisticsInfo queryLogistics(String orderId) {
    return thirdPartyApi.query(orderId);
}

// 熔断降级方法
public LogisticsInfo logisticsFallback(String orderId) {
    log.warn("物流查询熔断，返回兜底数据");
    LogisticsInfo fallback = new LogisticsInfo();
    fallback.setOrderId(orderId);
    fallback.setStatus("查询中，请稍后重试");
    return fallback;
}

// 熔断规则配置
List<DegradeRule> rules = new ArrayList<>();
DegradeRule rule = new DegradeRule();
rule.setResource("queryLogistics");
rule.setGrade(RuleConstant.DEGRADE_GRADE_RT); // 慢调用比例
rule.setCount(500); // 响应时间超过 500ms
rule.setTimeWindow(10); // 熔断时长 10 秒
rule.setMinRequestAmount(10); // 最小请求数
rule.setStatIntervalMs(10000); // 统计时长
rule.setSlowRatioThreshold(0.5); // 慢调用比例阈值 50%
rules.add(rule);
DegradeRuleManager.loadRules(rules);
```

**生活化比喻**：
```
就像商场：
- 小火灾：局部关闭，10 秒后尝试恢复
- 大火灾：全部关闭，等待消防处理
- 半开状态：10 秒后尝试恢复，成功则恢复，失败则继续熔断
```

### 3.2 精准降级方案

**代码示例**：
```java
// ✅ 非核心接口 - 直接返回空数据
@SentinelResource(value = "queryRecommend", fallback = "recommendFallback")
public List<Product> queryRecommend() {
    return recommendService.query();
}

public List<Product> recommendFallback() {
    return Collections.emptyList(); // 返回空数据
}

// ✅ 核心接口 - 保留基础功能，关闭拓展功能
@SentinelResource(value = "createOrder", fallback = "orderFallback")
public Result createOrder(OrderRequest request) {
    // 基础功能：创建订单
    Order order = orderService.create(request);
    
    // 拓展功能：发送通知、积分等
    if (canExecuteExtendedFeatures()) {
        notifyService.send(order);
        pointService.add(order);
    }
    
    return Result.success(order);
}

public Result orderFallback(OrderRequest request) {
    // 降级时只保留基础功能
    Order order = orderService.create(request);
    return Result.success(order);
}
```

五、技术深入探讨

### Q1: 网关如何做流量分层与请求隔离？

**答**：
> 流量分层方案：
>
> 1. **按用户等级分层**：VIP 用户、普通用户、游客
> 2. **按接口优先级分层**：核心接口（下单、支付）、非核心接口（查询、推荐）
> 3. **按地域分层**：不同地区的流量路由到不同的服务集群
>
> 实现：核心接口独立线程池，非核心接口共享线程池，避免相互影响。

### Q2: 熔断策略怎么区分瞬时故障和永久故障？

**答**：
> 区分方案：
>
> **瞬时故障**：
> - 慢调用比例超过阈值（如 50% 的请求超过 500ms）
> - 熔断时长较短（如 10 秒）
> - 半开状态渐进试探恢复
>
> **永久故障**：
> - 异常比例超过阈值（如 50% 的请求抛出异常）
> - 熔断时长较长（如 60 秒）
> - 需要人工介入排查

### Q3: 降级如何精准区分核心、非核心业务？

**答**：
> 精准降级方案：
>
> **非核心接口**：
> - 直接返回静态兜底数据、空数据
> - 如：推荐接口返回空列表
>
> **核心接口**：
> - 保留基础功能，关闭拓展功能
> - 如：下单接口保留创建订单功能，关闭发送通知、积分等拓展功能
>
> 核心：绝不一刀切全量降级。
