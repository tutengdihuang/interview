> **场景定位**：分布式系统技术场景

## 🎯 一句话定位

**分布式锁失效问题是什么？**
```
基础配置没问题，但锁还是失效了：
- 服务集群负载过高，部分节点执行任务超时
- 30 秒后锁自动过期
- 其他节点趁机获取锁执行同一批任务
- 导致对账数据重复计算、金额错乱
```

**生活化比喻**：就像公共厕所的门锁，你进去后锁上了，但超过 30 分钟没出来，锁自动开了，其他人以为没人，又进去了，结果两个人同时在里面。

**核心特点**：分布式锁不仅仅是 setnx + 过期时间，还需要锁续期、异常处理、集群适配。

## 一、问题本质：锁失效的隐性风险

### ❌ 常见误区

**误区 1：setnx + expire 就够了**
```
问题：
- setnx 和 expire 不是原子操作
- setnx 成功后，expire 执行前服务宕机
- 锁永远不会过期（死锁）

解决：
- 用 SET NX EX 原子命令
- 一条命令完成加锁和设置过期时间
```

**误区 2：过期时间设长一点就安全**
```
问题：
- 过期时间过长，服务宕机后锁长时间不释放
- 其他节点无法获取锁，任务无法执行

解决：
- 合理设置过期时间
- 使用锁续期机制
```

**误区 3：释放锁时直接 delete**
```
问题：
- 直接 delete 可能删除其他节点的锁
- A 节点锁过期，B 节点获取锁
- A 节点任务完成，delete 锁
- B 节点的锁被误删

解决：
- 锁添加唯一标识（UUID）
- 释放前校验标识
- 用 Lua 脚本保证原子性
```

## 二、第一层防御：基础实现避坑

### 2.1 Redis 锁优化

**生活化比喻**：
```
SET NX EX = 一步完成锁门和设闹钟
- 原子操作，不会中途失败
- 避免 setnx 和 expire 分离的问题

唯一标识 = 锁上刻你的名字
- 释放时检查是不是你的锁
- 避免误删其他节点的锁

Lua 脚本 = 检查 + 删除一步完成
- 原子操作
- 避免竞态条件
```

**代码示例（正确实现）**：
```java
@Service
public class RedisLockService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * 获取分布式锁（原子命令）
     */
    public boolean tryLock(String lockKey, String requestId, long expireSeconds) {
        // ✅ 正确做法：SET NX EX 原子命令
        Boolean result = redisTemplate.execute(
            (RedisCallback<Boolean>) connection -> 
                connection.set(
                    lockKey.getBytes(),
                    requestId.getBytes(),
                    Expiration.seconds(expireSeconds),
                    RedisStringCommands.SetOption.SET_IF_ABSENT
                )
        );
        
        return result != null && result;
    }
    
    /**
     * 释放分布式锁（Lua 脚本）
     */
    public boolean unlock(String lockKey, String requestId) {
        // ✅ 正确做法：Lua 脚本保证原子性
        String luaScript = 
            "if redis.call('get', KEYS[1]) == ARGV[1] then " +
            "    return redis.call('del', KEYS[1]) " +
            "else " +
            "    return 0 " +
            "end";
        
        DefaultRedisScript<Long> redisScript = new DefaultRedisScript<>();
        redisScript.setScriptText(luaScript);
        redisScript.setResultType(Long.class);
        
        Long result = redisTemplate.execute(
            redisScript,
            Collections.singletonList(lockKey),
            requestId
        );
        
        return result != null && result == 1L;
    }
}

// 使用示例
@Service
public class TaskService {
    
    @Autowired
    private RedisLockService lockService;
    
    public void executeTask(String taskId) {
        String lockKey = "task:lock:" + taskId;
        String requestId = UUID.randomUUID().toString();
        
        try {
            // 获取锁（过期时间 30 秒）
            boolean locked = lockService.tryLock(lockKey, requestId, 30);
            
            if (!locked) {
                log.warn("获取锁失败，taskId={}", taskId);
                return;
            }
            
            // 执行任务
            doTask(taskId);
            
        } finally {
            // 释放锁
            lockService.unlock(lockKey, requestId);
        }
    }
}
```

### 2.2 锁粒度设计

**生活化比喻**：
```
锁粒度 = 锁的范围
- 过粗：锁整个厕所（并发低）
- 过细：锁每个马桶的每个按钮（锁冲突频繁）
- 合适：锁单个隔间（平衡并发和冲突）

按任务 ID 锁定：
- 不同任务可以并发执行
- 同一任务不会重复执行

按用户 ID 锁定：
- 不同用户可以并发操作
- 同一用户不会并发操作
```

**代码示例**：
```java
// ❌ 错误做法：锁粒度太粗
public void processAllTasks() {
    String lockKey = "task:lock:all"; // 锁定所有任务
    // ...
}

// ✅ 正确做法：锁粒度合适
public void processTask(String taskId) {
    String lockKey = "task:lock:" + taskId; // 只锁定单个任务
    // ...
}
```

## 三、第二层防御：过期与续期处理

### 3.1 锁续期机制

**生活化比喻**：
```
锁续期 = 快超时时自动续费
- 任务执行时间可能超过锁的过期时间
- 在锁即将过期前，自动续期
- 避免任务未完成锁已过期

就像：
- 洗澡时间可能超过 30 分钟
- 快超时时，自动续费 10 分钟
- 避免被强制开门
```

**代码示例（Redisson 看门狗）**：
```java
@Service
public class TaskService {
    
    @Autowired
    private RedissonClient redissonClient;
    
    public void executeTask(String taskId) {
        String lockKey = "task:lock:" + taskId;
        RLock lock = redissonClient.getLock(lockKey);
        
        try {
            // 获取锁（自动续期）
            // Redisson 的看门狗机制会自动续期
            boolean locked = lock.tryLock(
                10,  // 等待时间 10 秒
                30,  // 锁持有时间 30 秒（会被看门狗自动续期）
                TimeUnit.SECONDS
            );
            
            if (!locked) {
                log.warn("获取锁失败，taskId={}", taskId);
                return;
            }
            
            // 执行任务（可能超过 30 秒）
            // 看门狗会自动续期，不会提前过期
            doTask(taskId);
            
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            // 释放锁
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
    
    private void doTask(String taskId) {
        // 耗时操作
        try {
            Thread.sleep(60000); // 60 秒
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

**看门狗原理**：
```
Redisson 看门狗机制：
- 每隔 10 秒检查一次（默认锁时间的 1/3）
- 如果线程还持有锁，自动续期 30 秒
- 线程释放锁或宕机后，停止续期
- 锁过期后自动释放
```

### 3.2 合理设置过期时间

**生活化比喻**：
```
过期时间 = 根据洗澡时间设闹钟
- 任务最长 20 秒，锁设 30 秒（预留 10 秒冗余）
- 避免过期时间过短（任务未完成锁已过期）
- 避免过期时间过长（服务宕机后锁长时间不释放）
```

**代码示例**：
```java
public void executeTask(String taskId) {
    // 估算任务最长执行时间
    long maxExecuteTime = estimateMaxExecuteTime(taskId); // 如 20 秒
    
    // 预留冗余时间（如 50%）
    long lockExpireTime = (long) (maxExecuteTime * 1.5); // 30 秒
    
    String lockKey = "task:lock:" + taskId;
    String requestId = UUID.randomUUID().toString();
    
    try {
        boolean locked = lockService.tryLock(lockKey, requestId, lockExpireTime);
        if (!locked) {
            return;
        }
        
        doTask(taskId);
        
    } finally {
        lockService.unlock(lockKey, requestId);
    }
}
```

### 3.3 超时兜底

**代码示例**：
```java
@Service
public class TaskService {
    
    @Autowired
    private RedisLockService lockService;
    
    @Autowired
    private TaskMapper taskMapper;
    
    public void executeTask(String taskId) {
        String lockKey = "task:lock:" + taskId;
        String requestId = UUID.randomUUID().toString();
        
        try {
            boolean locked = lockService.tryLock(lockKey, requestId, 30);
            
            if (!locked) {
                log.warn("获取锁失败，taskId={}", taskId);
                return;
            }
            
            // 设置任务超时时间
            ExecutorService executor = Executors.newSingleThreadExecutor();
            Future<?> future = executor.submit(() -> doTask(taskId));
            
            try {
                // 等待任务完成（超时 25 秒）
                future.get(25, TimeUnit.SECONDS);
            } catch (TimeoutException e) {
                // 任务超时
                log.error("任务执行超时，taskId={}", taskId);
                
                // 主动释放锁
                lockService.unlock(lockKey, requestId);
                
                // 记录异常日志
                taskMapper.updateStatus(taskId, "TIMEOUT");
                
                // 发送告警
                sendAlert("任务执行超时，taskId=" + taskId);
                
                // 取消任务
                future.cancel(true);
            }
            
        } finally {
            // 确保锁被释放
            if (lockService.isLocked(lockKey, requestId)) {
                lockService.unlock(lockKey, requestId);
            }
        }
    }
}
```

## 四、第三层防御：异常兜底与集群适配

### 4.1 异常释放

**生活化比喻**：
```
异常释放 = 人晕倒后锁自动开
- 服务宕机时，锁应该自动释放
- Redis：过期自动释放
- ZooKeeper：临时节点自动删除

避免死锁：
- 锁必须有过期时间
- 服务宕机后，锁过期自动释放
```

### 4.2 集群适配（Redlock 算法）

**生活化比喻**：
```
Redlock = 多个厕所共用一套锁系统
- Redis 集群模式下，主从切换可能导致锁丢失
- Redlock 算法：在多个独立的 Redis 实例上加锁
- 大多数实例加锁成功，才算加锁成功

就像：
- 有 5 个厕所，每个都有独立的锁
- 至少在 3 个厕所加锁成功，才算加锁成功
- 避免单个厕所故障导致锁失效
```

**代码示例（Redlock）**：
```java
@Service
public class RedLockService {
    
    private List<RedissonClient> redisInstances;
    
    public RedLockService() {
        // 初始化多个独立的 Redis 实例
        redisInstances = Arrays.asList(
            Redisson.create(config1),
            Redisson.create(config2),
            Redisson.create(config3),
            Redisson.create(config4),
            Redisson.create(config5)
        );
    }
    
    /**
     * Redlock 算法加锁
     */
    public boolean tryLock(String lockKey, String requestId, long expireSeconds) {
        long startTime = System.currentTimeMillis();
        int successCount = 0;
        
        // 在所有实例上加锁
        for (RedissonClient redis : redisInstances) {
            RLock lock = redis.getLock(lockKey);
            
            try {
                boolean locked = lock.tryLock(
                    0, expireSeconds, TimeUnit.SECONDS
                );
                
                if (locked) {
                    successCount++;
                }
            } catch (Exception e) {
                log.error("加锁失败", e);
            }
        }
        
        // 大多数实例加锁成功（N/2 + 1）
        int requiredCount = redisInstances.size() / 2 + 1;
        
        if (successCount >= requiredCount) {
            return true;
        } else {
            // 加锁失败，释放所有实例上的锁
            unlock(lockKey, requestId);
            return false;
        }
    }
    
    public void unlock(String lockKey, String requestId) {
        for (RedissonClient redis : redisInstances) {
            RLock lock = redis.getLock(lockKey);
            
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

### 4.3 监控告警

**代码示例**：
```java
@Component
public class LockMonitorService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * 监控锁获取失败
     */
    public void monitorLockFailure(String lockKey, String taskId) {
        String failKey = "lock:fail:" + lockKey;
        
        // 记录失败次数
        Long failCount = redisTemplate.opsForValue().increment(failKey);
        redisTemplate.expire(failKey, 1, TimeUnit.HOURS);
        
        if (failCount > 10) {
            // 失败超过 10 次，发送告警
            sendAlert("锁获取失败超过 10 次，lockKey=" + lockKey);
        }
    }
    
    /**
     * 监控锁持有超时
     */
    @Scheduled(fixedRate = 60000) // 每分钟检查一次
    public void monitorLockTimeout() {
        // 扫描所有锁
        Set<String> lockKeys = redisTemplate.keys("task:lock:*");
        
        for (String lockKey : lockKeys) {
            Long ttl = redisTemplate.getExpire(lockKey, TimeUnit.SECONDS);
            
            if (ttl > 60) { // 锁持有超过 60 秒
                sendAlert("锁持有超时，lockKey=" + lockKey);
            }
        }
    }
    
    /**
     * 监控任务重复执行
     */
    public void monitorDuplicateExecution(String taskId) {
        String execKey = "task:exec:" + taskId;
        
        Boolean isFirst = redisTemplate.opsForValue()
            .setIfAbsent(execKey, "1", 1, TimeUnit.HOURS);
        
        if (!isFirst) {
            // 重复执行，发送告警
            sendAlert("任务重复执行，taskId=" + taskId);
        }
    }
    
    private void sendAlert(String message) {
        // 发送钉钉告警
        System.out.println("[ALERT] " + message);
    }
}
```

五、技术深入探讨

### 考点 1：如何避免分布式锁失效？

**方案参考**（30 秒版）：
> "避免分布式锁失效要分三层：1）基础实现：用 SET NX EX 原子命令，锁添加唯一标识，释放前校验标识；2）过期续期：使用锁续期机制（如 Redisson 看门狗），合理设置过期时间；3）异常兜底：服务宕机后锁自动释放，集群模式用 Redlock 算法，监控告警及时发现异常。"

**加分回答**：
> "实际生产中，我会用 Redisson 实现分布式锁，它的看门狗机制会自动续期，避免任务未完成锁已过期。对于高可用要求高的场景，会用 Redlock 算法在多个 Redis 实例上加锁。同时要监控锁的获取失败、持有超时、任务重复执行，及时告警。"

### 考点 2：锁续期怎么实现？

**方案参考**：
> "锁续期是在锁即将过期前，自动延长锁的过期时间。Redisson 的看门狗机制：每隔 10 秒检查一次（默认锁时间的 1/3），如果线程还持有锁，自动续期 30 秒。线程释放锁或宕机后，停止续期，锁过期后自动释放。"

**加分回答**：
> "除了 Redisson，也可以自己实现：启动一个定时任务，每隔一段时间检查锁是否还被持有，如果是就续期。但要注意定时任务的可靠性，可以用 ZooKeeper 的临时节点特性，节点存在就续期，节点删除就停止续期。"

### 考点 3：Redlock 算法的原理？

**方案参考**：
> "Redlock 算法是在多个独立的 Redis 实例上加锁。步骤：1）依次在所有实例上加锁；2）如果在大多数实例（N/2 + 1）上加锁成功，才算加锁成功；3）加锁失败，释放所有实例上的锁。这样可以避免单个 Redis 实例故障导致锁失效。"

**加分回答**：
> "Redlock 算法要求 Redis 实例是独立的，不能是主从复制。因为主从切换可能导致锁丢失。实际生产中，Redlock 用得较少，因为实现复杂，性能开销大。大多数场景用 Redisson 的单实例锁就够了。对于高可用要求高的场景，可以用 ZooKeeper 实现分布式锁。"

## 六、总结（一句话带走）

### 🎯 一句话总结

> **分布式锁三层防御 = 基础实现（原子命令/唯一标识/锁粒度） + 过期续期（自动续期/合理过期/超时兜底） + 异常兜底（异常释放/集群适配/监控告警）**

### 🧠 核心记忆点

1. **为什么锁会失效？** 过期时间太短，任务未完成锁已过期；setnx 和 expire 不是原子操作；直接 delete 可能误删其他节点的锁。
2. **如何避免锁失效？** 用 SET NX EX 原子命令，锁添加唯一标识，释放前用 Lua 脚本校验。
3. **锁续期怎么实现？** Redisson 看门狗机制，每隔 10 秒检查一次，自动续期 30 秒。
4. **集群模式如何保证锁可靠？** Redlock 算法，在多个独立 Redis 实例上加锁，大多数成功才算成功。
5. **如何监控锁异常？** 监控锁获取失败、持有超时、任务重复执行，及时告警。
