# 大文件上传断点续传

> **场景定位**：系统设计场景  
> **核心设计要点**：分片上传、断点续传、MD5 校验、临时文件清理、并发处理

---

## 🎯 一句话定位

```
大文件上传不是简单的"传文件"：
- SpringMVC 原生上传 → 大文件 OOM
- Nginx/Tomcat 请求体限制 → 413 报错
- 分片上传 + 断点续传 → 90% 的人踩坑
```

**生活化比喻**：
就像搬家——你不能一次性把所有家具搬上车（OOM），而是一趟趟搬（分片上传）。如果搬到一半车坏了（网络中断），不用从头搬，接着上次的继续（断点续传）。但关键是你要给每件家具编号（MD5），不然搬到新地方发现东西对不上（文件损坏）。

---

## 💎 核心观点

**分片上传三大坑**：
1. **分片乱序** → 必须按 index 排序合并
2. **重复分片** → MD5 + 分片索引 去重
3. **临时文件堆积** → 定时清理过期分片

**断点续传两大坑**：
1. **用文件名做标识** → 必须用文件 MD5
2. **分片大小不统一** → 首次上传锁定分片大小

**完整性校验**：合并后重新计算 MD5 比对

---

## 🚀 一句话精华

> **大文件上传 = 分片上传（乱序合并+去重+清理） + 断点续传（MD5 标识+固定分片+进度持久化） + MD5 校验完整性**

---

## 一、为什么大文件必须分片？

```
SpringMVC 原生上传：
  → 一次性加载全部文件流到内存
  → 1GB 文件 → 1GB 内存 → OOM ❌

Nginx/Tomcat 限制：
  → 请求体大小限制（默认 1MB~10MB）
  → 大文件直接 413 报错 ❌

正确方案：
  → 前端分片（如 512KB/片）
  → 后端接收并存储临时分片
  → 全部上传完成后按序合并
```

---

## 二、分片上传三大坑

### 2.1 坑一：分片乱序导致文件损坏

```
问题：
  网络传输无序——先发的分片可能后到
  如果后端收到就追加写入 → 文件损坏

✅ 正确做法：
  1. 每个分片接收后存为独立临时文件
  2. 所有分片上传完成后校验数量
  3. 按 index 序号从小到大排序合并
```

### 2.2 坑二：重复分片浪费资源

```
问题：
  网络抖动/刷新页面/误操作重传
  → 同一分片被重复上传和存储

✅ 标准方案：
  文件 MD5 + 分片索引 做唯一标识
  每次上传前先校验是否已存在
  已存在的分片直接返回成功，跳过
```

### 2.3 坑三：临时文件堆积冲爆磁盘

```
问题：
  用户传了一半关掉页面 / 网络断掉 / 中途放弃
  → 服务器遗留大量无效临时分片
  → 长期堆积 → 磁盘爆满 → 服务宕机

✅ 兜底方案：
  定时任务清理 24 小时以上未合并的过期分片
  同时清理对应 Redis 缓存
```

---

## 三、断点续传两大坑

### 3.1 坑一：用文件名做续传标识

```
问题：
  文件名可以改、可以重复
  用户改名字重传 → 断点错乱
  同名文件 → 覆盖 → 续传失效

✅ 标准答案：
  用文件 MD5 作为唯一标识
  文件内容不变 → MD5 不变
  不管改文件名、换设备都能精准识别进度
```

### 3.2 坑二：分片大小不统一

```
问题：
  第一次上传用 512KB 分片
  刷新页面后前端改成 1MB 分片
  → 新旧分片规格对不上 → 续传失效

✅ 解决方案：
  首次上传时把分片大小存入 Redis
  后续续传请求校验分片大小一致
  不一致直接拒绝
```

---

## 四、完整性校验（加分项）

```
文件合并完成后：
  1. 后端重新计算完整文件的 MD5
  2. 与前端传来的原始文件 MD5 比对
  3. 一致 → 上传成功
  4. 不一致 → 删除破损文件，返回失败
```

---

五、技术方案

### 方案参考

> "大文件分片上传核心解决 OOM 和 413 报错，关键要处理三个坑：
> 1. **分片乱序**：每个分片单独存为临时文件，全部上传完按 index 排序合并。
> 2. **重复分片**：用文件 MD5 + 分片索引做唯一标识，已存在的跳过。
> 3. **临时文件堆积**：定时任务清理 24 小时以上未合并的过期分片。
> 
> 断点续传靠 MD5 唯一标识文件，首次上传锁定分片大小存 Redis，续传校验一致性。最后合并完重新计算 MD5 比对原始值，保证文件完整性。"

---

## 六、总结

> **大文件上传 = 分片（乱序合并+去重+清理） + 断点续传（MD5 标识+固定分片+进度持久化） + MD5 校验**

### 🧠 核心记忆点

1. **分片乱序必须按 index 排序合并**——不能直接追加写入。
2. **断点续传用 MD5 做标识**——不是文件名。
3. **合并后 MD5 校验**——保证文件完整性。
