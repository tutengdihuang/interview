## 🎯 一句话定位

**接口幂等性全链路设计解决什么问题？**
```
高并发下接口重复执行
消息重复投递导致数据错乱
单一幂等手段兜不住全链路风险
```

**生活化比喻**：
就像电梯按钮：
- 按一次（请求）
- 按多次（重复请求）
- 电梯只响应一次（幂等）

## 二、三重防护

### 2.1 幂等令牌

```go
// 生成幂等令牌
func GenerateIdempotentToken(orderID string) string {
    token := fmt.Sprintf("%s_%d", orderID, time.Now().UnixNano())
    redis.Set(token, "1", 10*time.Minute)
    return token
}

// 校验幂等令牌
func CheckIdempotentToken(token string) bool {
    // 校验令牌是否存在
    exists := redis.Exists(token)
    if !exists {
        return false // 令牌不存在，重复请求
    }
    
    // 删除令牌（只允许一次）
    redis.Del(token)
    return true
}
```

### 2.2 状态机校验

```go
// 状态机校验
func UpdateOrderStatus(orderID string, newStatus string) error {
    // 查询当前状态
    order := db.GetOrder(orderID)
    
    // 状态机校验
    if !canTransition(order.Status, newStatus) {
        return errors.New("状态不允许转换")
    }
    
    // 更新状态
    return db.Exec("UPDATE orders SET status = ? WHERE id = ?",
        newStatus, orderID)
}
```

### 2.3 数据库唯一约束

```go
// 唯一约束兜底
func CreateOrder(order *Order) error {
    // 唯一索引：order_id
    err := db.Exec("INSERT INTO orders (order_id, ...) VALUES (?, ...)",
        order.ID, ...)
    
    if isDuplicateKeyError(err) {
        return errors.New("订单已存在") // 重复请求
    }
    
    return err
}
```

## 三、MQ消费幂等

```go
// 消费去重表
func ConsumeMessage(msg *Message) error {
    // 1. 查询是否已消费
    record := db.GetConsumeRecord(msg.MessageID)
    if record != nil {
        return nil // 已消费，幂等返回
    }
    
    // 2. 乐观锁
    tx := db.Begin()
    
    // 执行业务
    err := doBusiness(tx, msg)
    if err != nil {
        tx.Rollback()
        return err
    }
    
    // 插入消费记录
    tx.Exec("INSERT INTO consume_record (message_id) VALUES (?)",
        msg.MessageID)
    
    tx.Commit()
    
    return nil
}

// 死信队列兜底
func HandleFailedMessage(msg *Message) {
    // 消费失败转入死信队列
    deadLetterQueue.Push(msg)
    
    // 人工兜底
    alert("消费失败: %v", msg.MessageID)
}
```

## 五、架构层优化

### 5.1 统一超时与重试策略

```go
// 统一规范
var RetryPolicy = &Policy{
    MaxRetries: 3,
    Backoff:    ExponentialBackoff,
    Idempotent: true, // 必须保证幂等
}

// 禁止无幂等保障的盲目重试
func Retry(fn func() error) error {
    if !isIdempotent(fn) {
        return errors.New("禁止重试：非幂等操作")
    }
    
    return doRetry(fn, RetryPolicy)
}
```

### 5.2 网关层统一幂等校验

```go
// 网关层统一校验
func GatewayIdempotent(c *gin.Context) {
    token := c.GetHeader("X-Idempotent-Token")
    
    if !checkIdempotentToken(token) {
        c.JSON(400, gin.H{"error": "重复请求"})
        c.Abort()
        return
    }
    
    c.Next()
}
```

六、技术深入探讨

### Q1: 如何设计全链路幂等方案？

**方案参考**：
> 全链路幂等三层防御：
> 
> 1. **业务分级**：强幂等（支付、库存）严格去重，弱幂等（点赞、浏览）轻量校验
> 2. **三重防护**：幂等令牌 + 状态机校验 + 数据库唯一约束
> 3. **MQ消费幂等**：消费去重表 + 乐观锁 + 死信队列兜底
> 
> 核心是全链路防护，单点手段不够。

### Q2: MQ消费重复怎么处理？

**方案参考**：
> MQ消费重复通过幂等表解决：
> 
> 1. **消费去重表**：消费前查询是否已处理，已处理直接返回
> 2. **乐观锁**：执行业务 + 插入记录同一事务
> 3. **死信队列**：消费失败转入死信，人工兜底
> 4. **定时对账**：自动核对数据，修复异常
> 
> 核心是保证同一条消息只执行一次。
