# 缓存穿透全方位防护

> **场景定位**：Redis 缓存技术场景  
> **核心设计要点**：布隆过滤器、空值缓存、参数校验、IP 限流、缓存降级、数据库防护

---

## 🎯 一句话定位

**缓存穿透问题是什么？**
```
布隆过滤器和空值缓存都配置了，但还是出现了缓存穿透：
- 黑客批量伪造不存在的商品 ID，疯狂请求
- 布隆过滤器未拦截所有非法 ID
- 空值缓存被频繁覆盖
- 大量请求直接穿透到 MySQL
- 数据库连接池被打满，CPU 飙升到 100%
- 核心接口全部超时，正常商品也无法访问
```

**生活化比喻**：就像图书馆查书，你设了图书查询系统（布隆过滤器）和"查无此书"的便签（空值缓存），但有人恶意频繁查不存在的书，便签被频繁覆盖，管理员还是得跑遍整个图书馆找书，累趴下了。

**核心特点**：缓存穿透不仅仅是加布隆过滤器和空值缓存，而是源头拦截、缓存防护、数据库兜底相结合的完整体系。

## 一、问题本质：缓存穿透的隐性风险

### ❌ 常见误区

**误区 1：布隆过滤器配置了就不会穿透**
```
问题：
- 布隆过滤器有误判率
- 合法 ID 更新后，过滤器未同步更新
- 黑客构造的 ID 恰好落在误判区间

解决：
- 合理设置误判率（如 0.01%）
- 定期更新过滤器中的合法 ID 集合
- 结合其他防护手段
```

**误区 2：空值缓存配置了就万事大吉**
```
问题：
- 空值缓存过期时间设置不当
- 黑客频繁请求不同的非法 ID
- 空值缓存被频繁覆盖，失去作用

解决：
- 合理设置空值过期时间
- 限制空值缓存的数量
- 结合参数校验、IP 限流
```

**误区 3：缓存穿透是缓存的问题**
```
问题：
- 只关注缓存层面
- 忽略了源头拦截
- 忽略了数据库防护

解决：
- 三层防御：源头拦截 + 缓存防护 + 数据库兜底
- 多层防护，互为补充
```

## 二、第一层防御：源头拦截

### 2.1 布隆过滤器优化

**生活化比喻**：
```
布隆过滤器 = 图书查询系统
- 先查有没有这本书
- 没有就不去图书馆找
- 有误判率（可能把没有的书判断为有）

优化：
- 合理设置误判率（如 0.01%）
- 定期更新合法 ID 集合
- 避免 ID 更新后误判漏拦
```

**代码示例**：
```java
@Component
public class BloomFilterService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    private static final String BLOOM_FILTER_KEY = "product:bloom:filter";
    
    /**
     * 初始化布隆过滤器
     */
    @PostConstruct
    public void init() {
        // 预计元素数量：1000 万
        // 误判率：0.01%
        RBloomFilter<String> bloomFilter = RedissonClient.create()
            .getBloomFilter(BLOOM_FILTER_KEY);
        
        bloomFilter.tryInit(10000000L, 0.0001);
        
        // 加载所有合法商品 ID
        loadValidProductIds(bloomFilter);
    }
    
    /**
     * 判断商品 ID 是否存在
     */
    public boolean mightContain(String productId) {
        RBloomFilter<String> bloomFilter = RedissonClient.create()
            .getBloomFilter(BLOOM_FILTER_KEY);
        
        return bloomFilter.contains(productId);
    }
    
    /**
     * 添加商品 ID
     */
    public void add(String productId) {
        RBloomFilter<String> bloomFilter = RedissonClient.create()
            .getBloomFilter(BLOOM_FILTER_KEY);
        
        bloomFilter.add(productId);
    }
    
    /**
     * 定期更新合法 ID 集合（定时任务）
     */
    @Scheduled(cron = "0 0 2 * * ?") // 每天凌晨 2 点
    public void updateBloomFilter() {
        // 查询所有合法商品 ID
        List<String> validProductIds = productMapper.selectAllProductIds();
        
        // 重新初始化布隆过滤器
        RBloomFilter<String> bloomFilter = RedissonClient.create()
            .getBloomFilter(BLOOM_FILTER_KEY);
        
        bloomFilter.tryInit(validProductIds.size() * 2L, 0.0001);
        
        for (String productId : validProductIds) {
            bloomFilter.add(productId);
        }
        
        log.info("布隆过滤器更新完成，共 {} 个商品 ID", validProductIds.size());
    }
    
    private void loadValidProductIds(RBloomFilter<String> bloomFilter) {
        List<String> validProductIds = productMapper.selectAllProductIds();
        
        for (String productId : validProductIds) {
            bloomFilter.add(productId);
        }
    }
}
```

### 2.2 接口参数校验

**生活化比喻**：
```
参数校验 = 检查借书证是否有效
- 网关层校验：格式错误、非法范围
- 接口层校验：业务规则校验
- 从源头减少无效请求

就像：
- 借书证格式不对，直接拒绝
- 借书证过期，直接拒绝
- 借书证号码超出范围，直接拒绝
```

**代码示例**：
```java
@RestController
@RequestMapping("/product")
public class ProductController {
    
    @Autowired
    private BloomFilterService bloomFilterService;
    
    /**
     * 商品详情接口
     */
    @GetMapping("/detail/{productId}")
    public Result<Product> getProductDetail(@PathVariable String productId) {
        // 1. 参数格式校验
        if (!isValidProductId(productId)) {
            return Result.error("商品 ID 格式错误");
        }
        
        // 2. 布隆过滤器校验
        if (!bloomFilterService.mightContain(productId)) {
            return Result.error("商品不存在");
        }
        
        // 3. 查询商品信息
        Product product = productService.getProductById(productId);
        
        return Result.success(product);
    }
    
    /**
     * 商品 ID 格式校验
     */
    private boolean isValidProductId(String productId) {
        // 商品 ID 必须是数字，且长度在 10-20 位之间
        if (productId == null || productId.length() < 10 || productId.length() > 20) {
            return false;
        }
        
        return productId.matches("\\d+");
    }
}
```

### 2.3 IP 限流拦截

**生活化比喻**：
```
IP 限流 = 限制一个人借书频率
- 对高频请求同一非法参数的 IP 进行限流
- 防止黑客批量刷量
- 避免恶意请求冲击数据库

就像：
- 一个人 1 分钟内借 100 本书，肯定不正常
- 限制他 1 分钟只能借 10 本
- 超过限制，直接拉黑
```

**代码示例**：
```java
@Component
public class IpRateLimiter {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * IP 限流检查
     */
    public boolean isAllowed(String ip, String productId) {
        String key = "rate:limit:" + ip + ":" + productId;
        
        // 1 分钟内最多请求 10 次
        Long count = redisTemplate.opsForValue().increment(key);
        
        if (count == 1) {
            // 第一次请求，设置过期时间 1 分钟
            redisTemplate.expire(key, 1, TimeUnit.MINUTES);
        }
        
        if (count > 10) {
            log.warn("IP 限流触发，ip={}, productId={}, count={}", ip, productId, count);
            return false; // 超过限制
        }
        
        return true;
    }
    
    /**
     * IP 黑名单检查
     */
    public boolean isBlacklisted(String ip) {
        String key = "blacklist:" + ip;
        return redisTemplate.hasKey(key);
    }
    
    /**
     * 加入黑名单
     */
    public void addToBlacklist(String ip) {
        String key = "blacklist:" + ip;
        redisTemplate.opsForValue().set(key, "1", 24, TimeUnit.HOURS); // 拉黑 24 小时
        
        log.warn("IP 加入黑名单，ip={}", ip);
    }
}

@RestController
@RequestMapping("/product")
public class ProductController {
    
    @Autowired
    private IpRateLimiter ipRateLimiter;
    
    @GetMapping("/detail/{productId}")
    public Result<Product> getProductDetail(
        @PathVariable String productId,
        HttpServletRequest request
    ) {
        String ip = getClientIp(request);
        
        // 1. IP 黑名单检查
        if (ipRateLimiter.isBlacklisted(ip)) {
            return Result.error("请求被限制");
        }
        
        // 2. IP 限流检查
        if (!ipRateLimiter.isAllowed(ip, productId)) {
            // 频繁请求非法参数，加入黑名单
            if (!bloomFilterService.mightContain(productId)) {
                ipRateLimiter.addToBlacklist(ip);
            }
            return Result.error("请求过于频繁");
        }
        
        // 3. 查询商品信息
        Product product = productService.getProductById(productId);
        
        return Result.success(product);
    }
}
```

## 三、第二层防御：缓存防护

### 3.1 空值缓存优化

**生活化比喻**：
```
空值缓存 = "查无此书"的便签
- 查询不存在的商品，缓存空值
- 避免每次都查数据库
- 但要合理设置过期时间

优化：
- 合理设置过期时间（如 5 分钟）
- 避免频繁覆盖
- 定期清理过期空值
```

**代码示例**：
```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductMapper productMapper;
    
    private static final String PRODUCT_CACHE_KEY = "product:detail:";
    private static final int NULL_VALUE_EXPIRE = 300; // 空值缓存 5 分钟
    
    public Product getProductById(String productId) {
        String cacheKey = PRODUCT_CACHE_KEY + productId;
        
        // 1. 查询缓存
        String cacheValue = redisTemplate.opsForValue().get(cacheKey);
        
        if (cacheValue != null) {
            if ("NULL".equals(cacheValue)) {
                // 空值缓存，直接返回 null
                return null;
            }
            
            return JSON.parseObject(cacheValue, Product.class);
        }
        
        // 2. 缓存未命中，查询数据库
        Product product = productMapper.selectById(productId);
        
        if (product != null) {
            // 商品存在，缓存商品信息（过期时间 1 小时）
            redisTemplate.opsForValue().set(
                cacheKey,
                JSON.toJSONString(product),
                1, TimeUnit.HOURS
            );
        } else {
            // 商品不存在，缓存空值
            redisTemplate.opsForValue().set(
                cacheKey,
                "NULL",
                NULL_VALUE_EXPIRE, TimeUnit.SECONDS
            );
        }
        
        return product;
    }
}
```

### 3.2 热点缓存永不过期

**生活化比喻**：
```
热点缓存 = 常借的书放在前台
- 核心合法商品高频访问数据不设置过期时间
- 通过定时任务主动刷新
- 确保缓存始终有效

就像：
- 热门书籍永远放在前台
- 不用每次去仓库找
- 定时检查是否需要更新
```

**代码示例**：
```java
@Service
public class HotProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductMapper productMapper;
    
    private static final String HOT_PRODUCT_KEY = "product:hot:";
    
    /**
     * 查询热点商品（永不过期）
     */
    public Product getHotProduct(String productId) {
        String cacheKey = HOT_PRODUCT_KEY + productId;
        
        String cacheValue = redisTemplate.opsForValue().get(cacheKey);
        
        if (cacheValue != null) {
            return JSON.parseObject(cacheValue, Product.class);
        }
        
        // 缓存未命中，查询数据库
        Product product = productMapper.selectById(productId);
        
        if (product != null) {
            // 热点商品不设置过期时间
            redisTemplate.opsForValue().set(
                cacheKey,
                JSON.toJSONString(product)
            );
        }
        
        return product;
    }
    
    /**
     * 定时刷新热点商品缓存
     */
    @Scheduled(fixedRate = 300000) // 每 5 分钟刷新一次
    public void refreshHotProductCache() {
        // 查询热点商品 ID 列表
        List<String> hotProductIds = getHotProductIds();
        
        for (String productId : hotProductIds) {
            Product product = productMapper.selectById(productId);
            
            if (product != null) {
                String cacheKey = HOT_PRODUCT_KEY + productId;
                redisTemplate.opsForValue().set(
                    cacheKey,
                    JSON.toJSONString(product)
                );
            }
        }
        
        log.info("热点商品缓存刷新完成，共 {} 个商品", hotProductIds.size());
    }
    
    private List<String> getHotProductIds() {
        // 从配置或数据库查询热点商品 ID
        return Arrays.asList("100001", "100002", "100003");
    }
}
```

### 3.3 缓存降级兜底

**生活化比喻**：
```
缓存降级 = 系统坏了用纸质记录
- Redis 故障或缓存失效时，启用本地缓存临时兜底
- 避免请求直接穿透到数据库
- 用 Caffeine 等本地缓存

就像：
- 电子查询系统坏了
- 用纸质记录 temporarily 顶替
- 虽然慢一点，但总比没有好
```

**代码示例**：
```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductMapper productMapper;
    
    // 本地缓存（Caffeine）
    private final Cache<String, Product> localCache = Caffeine.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    public Product getProductById(String productId) {
        String cacheKey = "product:detail:" + productId;
        
        try {
            // 1. 尝试查询 Redis 缓存
            String cacheValue = redisTemplate.opsForValue().get(cacheKey);
            
            if (cacheValue != null) {
                if ("NULL".equals(cacheValue)) {
                    return null;
                }
                
                Product product = JSON.parseObject(cacheValue, Product.class);
                
                // 同步到本地缓存
                localCache.put(cacheKey, product);
                
                return product;
            }
            
        } catch (Exception e) {
            log.error("Redis 查询失败，降级到本地缓存", e);
            
            // Redis 故障，降级到本地缓存
            Product localProduct = localCache.getIfPresent(cacheKey);
            if (localProduct != null) {
                return localProduct;
            }
        }
        
        // 2. 缓存未命中，查询数据库
        Product product = productMapper.selectById(productId);
        
        if (product != null) {
            // 写入 Redis 缓存
            try {
                redisTemplate.opsForValue().set(
                    cacheKey,
                    JSON.toJSONString(product),
                    1, TimeUnit.HOURS
                );
            } catch (Exception e) {
                log.error("Redis 写入失败", e);
            }
            
            // 写入本地缓存
            localCache.put(cacheKey, product);
        }
        
        return product;
    }
}
```

## 四、第三层防御：数据库防护

### 4.1 数据库限流

**生活化比喻**：
```
数据库限流 = 限制进入图书馆的人数
- 给数据库设置最大连接数和请求阈值
- 超过阈值则拒绝请求
- 避免数据库被打垮

就像：
- 图书馆最多容纳 1000 人
- 超过就不让进了
- 避免拥挤踩踏
```

**代码示例**：
```java
@Configuration
public class DataSourceConfig {
    
    @Bean
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        
        // 最大连接数
        config.setMaximumPoolSize(50);
        
        // 最小空闲连接数
        config.setMinimumIdle(10);
        
        // 连接超时时间
        config.setConnectionTimeout(30000);
        
        // 空闲连接存活时间
        config.setIdleTimeout(600000);
        
        // 连接最大存活时间
        config.setMaxLifetime(1800000);
        
        return new HikariDataSource(config);
    }
}

@Service
public class DatabaseRateLimiter {
    
    @Autowired
    private DataSource dataSource;
    
    /**
     * 数据库请求限流
     */
    public boolean isAllowed() {
        try {
            HikariDataSource hikariDataSource = (HikariDataSource) dataSource;
            
            int activeConnections = hikariDataSource.getHikariPoolMXBean().getActiveConnections();
            int maxPoolSize = hikariDataSource.getMaximumPoolSize();
            
            // 活跃连接数超过 80%，拒绝新请求
            if (activeConnections > maxPoolSize * 0.8) {
                log.warn("数据库连接池接近上限，activeConnections={}, maxPoolSize={}", 
                    activeConnections, maxPoolSize);
                return false;
            }
            
            return true;
            
        } catch (Exception e) {
            log.error("数据库限流检查失败", e);
            return true; // 检查失败，放行
        }
    }
}
```

### 4.3 监控预警

**代码示例**：

五、技术深入探讨

### 考点 1：布隆过滤器为什么还会穿透？

**方案参考**（30 秒版）：
> "布隆过滤器有误判率，可能把不存在的 ID 判断为存在。同时如果合法 ID 更新后，过滤器未同步更新，也会导致误判。解决方案是合理设置误判率（如 0.01%），定期更新过滤器中的合法 ID 集合，结合参数校验、IP 限流等多层防护。"

**加分回答**：
> "实际生产中，我会用 Redisson 的 RBloomFilter，设置误判率 0.01%，预计元素数量 1000 万。每天凌晨定时任务重新加载所有合法 ID，避免 ID 更新后误判。同时网关层严格校验参数格式，IP 限流防止恶意刷量。多层防护，互为补充。"

### 考点 2：空值缓存为什么还会穿透？

**方案参考**：
> "空值缓存过期时间设置不当，可能被频繁覆盖。黑客频繁请求不同的非法 ID，空值缓存失效快，还是会穿透到数据库。解决方案是合理设置空值过期时间（如 5 分钟），限制空值缓存数量，结合参数校验和 IP 限流。"

**加分回答**：
> "我会给空值缓存设置 5 分钟过期时间，同时用 Caffeine 本地缓存作为二级缓存。Redis 故障时，降级到本地缓存，避免请求直接穿透到数据库。同时要监控穿透请求数，发现异常立即告警。"

### 考点 3：如何全方位防护缓存穿透？

**方案参考**：
> "全方位防护要三层防御：1）源头拦截：布隆过滤器 + 参数校验 + IP 限流；2）缓存防护：空值缓存 + 热点缓存永不过期 + 缓存降级兜底；3）数据库防护：数据库限流 + 索引优化 + 监控预警。多层防护，互为补充。"

**加分回答**：
> "实际生产中，我会建立完整的防护体系：网关层参数校验和 IP 限流，拦截非法请求；布隆过滤器拦截不存在的 ID；空值缓存和热点缓存保证缓存命中率；Redis 故障时降级到本地缓存；数据库限流和索引优化兜底；全链路监控，发现异常立即告警。核心是预判风险，多层兜底。"

## 六、总结（一句话带走）

### 🎯 一句话总结

> **缓存穿透三层防御 = 源头拦截（布隆过滤器/参数校验/IP 限流） + 缓存防护（空值缓存/热点缓存/降级兜底） + 数据库防护（限流/索引/监控）**

### 🧠 核心记忆点

1. **布隆过滤器为什么还会穿透？** 有误判率，合法 ID 更新后未同步更新。解决方案：合理设置误判率，定期更新。

3. **源头拦截怎么做？** 布隆过滤器 + 参数校验 + IP 限流。
4. **缓存防护怎么做？** 空值缓存 + 热点缓存永不过期 + 缓存降级兜底。
5. **数据库防护怎么做？** 数据库限流 + 索引优化 + 监控预警。
