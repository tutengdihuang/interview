# 大文件上传断点续传

> **场景定位**：后端实战技术场景  
> **核心设计要点**：分片上传、断点续传、MD5校验、临时文件清理

---

## 🎯 一句话定位

**大文件上传断点续传解决什么问题？**
```
大文件直接上传：
- OOM 内存溢出
- Nginx 413 报错
- 网络中断从头重传
```

**生活化比喻**：
就像寄快递：
- 大箱子拆成多个小包（分片）
- 每个包编号（index）
- 中途断了，只补寄没到的（断点续传）

---

## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 分片上传三大坑**
```
分片乱序：合并文件损坏
重复上传：浪费资源
临时文件堆积：磁盘爆满
```

**2. 分片乱序处理**
```
❌ 错误：收到就追加写入
✅ 正确：单独存储，按index排序合并
```

**3. 重复分片处理**
```
文件MD5 + 分片index
上传前校验
已上传过直接返回成功
```

**4. 临时文件清理**
```
定时任务清理24小时以上
未完成合并的过期分片
清理对应Redis缓存
```

**5. 断点续传核心**
```
MD5作为唯一标识
固定分片大小
持久化上传进度
```

> **断点续传 = 分片上传（乱序/重复/清理） + MD5唯一标识 + 固定分片大小 + 进度持久化 + 完整性校验**

## 一、分片上传三大坑

### 1.1 分片乱序

```go
// ❌ 错误：收到就追加
func UploadShard(file *File, shard []byte, index int) {
    // 乱序导致文件损坏
    file.Append(shard)
}

// ✅ 正确：单独存储，按序合并
func UploadShard(file *File, shard []byte, index int) {
    // 1. 单独存储为临时文件
    tempFile := fmt.Sprintf("/tmp/%s_%d", file.ID, index)
    ioutil.WriteFile(tempFile, shard, 0644)
    
    // 2. 所有分片上传完成后，按序合并
    if allShardsUploaded(file.ID) {
        mergeShards(file.ID)
    }
}

func mergeShards(fileID string) {
    // 按 index 排序
    shards := getShards(fileID)
    sort.Slice(shards, func(i, j int) bool {
        return shards[i].Index < shards[j].Index
    })
    
    // 合并
    for _, shard := range shards {
        data := ioutil.ReadFile(shard.Path)
        finalFile.Append(data)
    }
}
```

### 1.2 重复分片

```go
// 上传前校验
func UploadShard(fileMD5 string, index int, shard []byte) error {
    // 1. 校验是否已上传
    key := fmt.Sprintf("upload:%s:%d", fileMD5, index)
    if redis.Exists(key) {
        return nil // 已上传，直接返回成功
    }
    
    // 2. 存储分片
    saveShard(fileMD5, index, shard)
    
    // 3. 记录已上传
    redis.Set(key, "1", 24*time.Hour)
    
    return nil
}
```

### 1.3 临时文件清理

```go
// 定时清理过期分片
func CleanExpiredShards() {
    ticker := time.NewTicker(1 * time.Hour)
    for range ticker.C {
        // 1. 查询24小时以上未完成的上传
        expiredUploads := db.Query("SELECT * FROM uploads WHERE created_at < ? AND status = 'UPLOADING'",
            time.Now().Add(-24*time.Hour))
        
        for _, upload := range expiredUploads {
            // 2. 删除临时分片文件
            deleteTempFiles(upload.ID)
            
            // 3. 清理Redis缓存
            redis.Del(fmt.Sprintf("upload:%s:*", upload.MD5))
            
            // 4. 删除数据库记录
            db.Delete(upload)
        }
    }
}
```

## 二、断点续传核心

### 2.1 MD5唯一标识

```go
// ❌ 错误：用文件名
func ResumeUpload(fileName string) {
    // 文件名可改，可重复
    // 续传错乱
}

// ✅ 正确：用文件MD5
func ResumeUpload(fileMD5 string) {
    // 文件内容不变，MD5不变
    // 不管改文件名、换设备都能精准识别
    progress := getUploadProgress(fileMD5)
    return progress
}
```

### 2.2 固定分片大小

```go
// 第一次上传时记录分片大小
func StartUpload(fileMD5 string, shardSize int) {
    // 1. 记录分片大小
    redis.Set(fmt.Sprintf("upload:%s:shard_size", fileMD5), shardSize)
    
    // 2. 开始上传
}

// 续传时校验分片大小
func ResumeUpload(fileMD5 string, shardSize int) error {
    // 1. 查询记录的分片大小
    recordedSize := redis.Get(fmt.Sprintf("upload:%s:shard_size", fileMD5))
    
    // 2. 校验一致性
    if shardSize != recordedSize {
        return errors.New("分片大小不一致，续传失败")
    }
    
    return nil
}
```

### 2.3 持久化上传进度

```go
// 记录上传进度
func UpdateProgress(fileMD5 string, shardIndex int) {
    // 1. 记录已上传的分片
    redis.SAdd(fmt.Sprintf("upload:%s:shards", fileMD5), shardIndex)
    
    // 2. 更新总进度
    totalShards := getTotalShards(fileMD5)
    uploadedShards := redis.SCard(fmt.Sprintf("upload:%s:shards", fileMD5))
    
    progress := float64(uploadedShards) / float64(totalShards)
    redis.Set(fmt.Sprintf("upload:%s:progress", fileMD5), progress)
}

// 查询上传进度
func GetProgress(fileMD5 string) float64 {
    return redis.Get(fmt.Sprintf("upload:%s:progress", fileMD5))
}
```

// 合并完成后校验
func VerifyFile(fileMD5 string, mergedFile *File) error {
    // 1. 重新计算完整文件MD5
    actualMD5 := calculateMD5(mergedFile)
    
    // 2. 比对原始MD5

四、技术深入探讨

### Q1: 大文件上传为什么要分片？

**方案参考**：
> 大文件分片上传解决两个问题：
> 
> 1. **OOM内存溢出**：SpringMVC原生上传一次性加载全部文件流，大文件触发OOM
> 2. **413报错**：Nginx、Tomcat有请求体大小限制，直传大文件报413
> 
> 解决方案：前端分片，后端合并，搭配断点续传。

### Q2: 断点续传怎么实现？

**方案参考**：
> 断点续传核心：
> 
> 1. **MD5唯一标识**：文件内容不变MD5不变，精准识别上传进度
> 2. **固定分片大小**：第一次上传记录分片大小，续传校验一致性
> 3. **进度持久化**：Redis记录已上传分片，查询进度
> 4. **完整性校验**：合并后重新计算MD5，比对原始MD5
> 
> 核心是MD5唯一标识 + 进度持久化。
