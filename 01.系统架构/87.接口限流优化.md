## 三、动态阈值调整

```go
// 动态调整限流阈值
func DynamicThreshold() {
    ticker := time.NewTicker(1 * time.Second)
    for range ticker.C {
        // 监控各节点负载
        for _, node := range cluster.Nodes {
            load := node.GetLoad()
            triggerRate := node.GetTriggerRate()
            
            // 高负载节点提额
            if load > 0.8 {
                node.IncreaseQuota(10)
            }
            
            // 低负载节点降额
            if load < 0.3 {
                node.DecreaseQuota(10)
            }
            
            // 限流触发率过高，自动调额
            if triggerRate > 0.5 {
                node.IncreaseQuota(20)
            }
        }
    }
}
```

// 限流组件异常时自动旁路
func LimiterFallback(c *gin.Context) {
    defer func() {
        if r := recover(); r != nil {
            // 限流组件异常，自动旁路
            log.Error("限流组件异常: %v", r)
            // 优先保障业务正常运行
            c.Next()
        }

九、技术深入探讨

### Q1: 为什么单机限流会误伤用户？

**方案参考**：
> 单机限流误伤原因：
> 
> 1. **流量分布不均**：部分机器满载，其他机器空闲
> 2. **整体容量没跑满**：总流量才 50%，但部分机器已顶到阈值
> 3. **用户被误拦截**：正常请求被限流
> 
> 解决方案：核心接口用分布式全局限流，精准控制集群整体并发量。

### Q2: 如何设计多级限流防线？

**方案参考**：
> 多级限流防线：
> 
> 1. **网关层**：全局限流，防止流量洪峰
> 2. **服务层**：接口级限流，保护核心接口
> 3. **数据层**：数据库保护，最后防线
> 
> 单层规则失效时其他层继续兜底，避免单点防护失效。限流组件异常时自动旁路，优先保障业务。
