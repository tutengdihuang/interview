# 缓存穿透解决方案

> **场景定位**：缓存架构技术场景  
> **核心设计要点**：布隆过滤器、空值缓存、多层防护、误判处理

---

## 🎯 一句话定位

**缓存穿透解决什么问题？**
```
查询不存在的数据
缓存和数据库都没有
→ 每次请求都打到数据库
→ 数据库被打垮
```

**生活化比喻**：
就像查电话号码：
- 通讯录没有（缓存没有）
- 黄页也没有（数据库没有）
- 每次都去公安局查（数据库）
- 公安局被打爆了

---

## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 布隆过滤器不是万能的**
```
❌ 误区：加个布隆过滤器就完事
✅ 真相：误判率、元素超量、数据新增不同步
都会误伤正常请求
```

**2. 多层防护组合**
```
空值缓存 + 布隆过滤器 + 接口限流
不同层级拦截不同类型穿透请求
```

**3. 误判兜底机制**
```
被布隆过滤器拦截的请求
设置小比例透传校验
确认数据真实不存在再返回
```

**4. 新增数据同步**
```
业务数据新增时
同步写入布隆过滤器
避免新数据因未入库被误拦
```

**5. 核心场景开关**
```
大促或批量上新期间
临时降低布隆过滤器拦截强度
开启透传校验模式
```

## 一、布隆过滤器原理

### 1.1 核心思想

```
布隆过滤器 = 位数组 + 多个哈希函数

插入元素：
- 用 k 个哈希函数计算 k 个位置
- 把 k 个位置都设为 1

查询元素：
- 用 k 个哈希函数计算 k 个位置
- 如果 k 个位置都是 1 → 可能存在
- 如果有 0 → 一定不存在
```

### 1.2 代码示例

```go
type BloomFilter struct {
    bitSet []bool
    size   uint
    hashes []hash.Hash
}

// 添加元素
func (f *BloomFilter) Add(data []byte) {
    for _, h := range f.hashes {
        h.Write(data)
        pos := uint(h.Sum(nil)[0]) % f.size
        f.bitSet[pos] = true
    }
}

// 查询元素
func (f *BloomFilter) MaybeContains(data []byte) bool {
    for _, h := range f.hashes {
        h.Write(data)
        pos := uint(h.Sum(nil)[0]) % f.size
        if !f.bitSet[pos] {
            return false // 一定不存在
        }
    }
    return true // 可能存在
}
```

### 1.3 误判率

```
误判率 = (1 - e^(-kn/m))^k

其中：
- m：位数组大小
- n：元素数量
- k：哈希函数数量

推荐参数：
- m = 10n（位数组大小是元素数的 10 倍）
- k = 7（7 个哈希函数）
- 误判率 < 1%
```

## 二、布隆过滤器的坑

### 2.1 误判导致误杀

**典型事故**：
```
运营反馈：一批新品用户访问全部提示"商品不存在"
排查发现：布隆过滤器把新品误判为不存在
```

**根因**：
```
商品上新时没有同步写入布隆过滤器
→ 布隆过滤器认为商品不存在
→ 请求被拦截
→ 用户看不到新品
```

### 2.2 元素超量导致误判率飙升

```
设计容量：100 万元素
实际元素：200 万元素
误判率从 1% 飙升到 10%
→ 10% 的正常请求被误杀
```

## 三、多层防护方案

### 3.1 空值缓存

```go
// 查询数据
func GetProduct(id string) (*Product, error) {
    // 1. 查缓存
    product, err := redis.Get(id)
    if err == nil {
        if product == nil {
            return nil, nil // 空值，数据不存在
        }
        return product, nil
    }
    
    // 2. 查数据库
    product, err = db.Query(id)
    if err != nil {
        return nil, err
    }
    
    if product == nil {
        // 数据不存在，缓存空值（5 分钟）
        redis.Set(id, nil, 5*time.Minute)
        return nil, nil
    }
    
    // 3. 写入缓存
    redis.Set(id, product, 10*time.Minute)
    return product, nil
}
```

### 3.2 布隆过滤器 + 透传校验

```go
func GetProductWithBloom(id string) (*Product, error) {
    // 1. 布隆过滤器检查
    if !bloomFilter.MaybeContains(id) {
        // 2. 小比例透传（1%）
        if rand.Float64() < 0.01 {
            // 透传到数据库校验
            product, _ := db.Query(id)
            if product != nil {
                // 数据存在，修复布隆过滤器
                bloomFilter.Add(id)
                return product, nil
            }
        }
        
        return nil, nil // 数据不存在
    }
    
    // 3. 查缓存
    return GetProduct(id)
}
```

### 3.3 新增数据同步

```go
// 商品上新时
func CreateProduct(product *Product) error {
    // 1. 写入数据库
    err := db.Create(product)
    if err != nil {
        return err
    }
    
    // 2. 同步写入布隆过滤器
    bloomFilter.Add(product.ID)
    
    return nil
}
```

## 四、核心场景开关

```go
// 大促或批量上新期间
func PeakMode() {
    // 临时降低布隆过滤器拦截强度
    bloomFilter.SetThreshold(0.5) // 50% 的请求透传
    
    // 或完全关闭布隆过滤器
    bloomFilter.Disable()
}

// 恢复正常
func NormalMode() {
    bloomFilter.SetThreshold(1.0)
    bloomFilter.Enable()
}
```

五、技术深入探讨

### Q1: 布隆过滤器误判怎么办？

**方案参考**：
> 布隆过滤器有误判（可能误认为存在，但不会误认为不存在），处理方案：
> 
> 1. **透传校验**：被拦截的请求，小比例（1%）透传到数据库校验
> 2. **数据同步**：新增数据时同步写入布隆过滤器
> 3. **动态扩容**：容量使用超过 80% 时自动扩容
> 4. **核心开关**：大促期间临时降低拦截强度
> 
> 核心是多层防护，单层失效有其他层兜底。

### Q2: 缓存穿透和缓存击穿有什么区别？

**方案参考**：
> 两者完全不同：
> 
> **缓存穿透**：查询不存在的数据，缓存和数据库都没有
> 解决方案：空值缓存 + 布隆过滤器
> 
> **缓存击穿**：热点 Key 过期，大量请求打到数据库
> 解决方案：互斥锁 + 永不过期 + 多级缓存
> 
> 一个是数据不存在，一个是热点 Key 过期。

### 🎯 一句话总结

> **缓存穿透 = 空值缓存（兜底） + 布隆过滤器（拦截） + 误判处理（透传校验） + 数据同步（新增同步）**

### 🧠 核心记忆点

1. **布隆过滤器有坑**：误判、元素超量、数据不同步
2. **多层防护**：空值缓存 + 布隆过滤器 + 限流
3. **误判处理**：小比例透传校验
4. **数据同步**：新增数据同步写入布隆过滤器
