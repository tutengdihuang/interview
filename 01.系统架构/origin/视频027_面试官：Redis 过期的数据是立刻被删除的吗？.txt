面试官：Redis 过期的数据是立刻被删除的吗？ #java #java 面试 #后端 #后端开发 #程序员
Redis 过期的数据是立刻被删除的吗？不是，过期数据可能还在内存里占着空间很久。为什么设了过期时间都觉得到点就自动失效？这个懵了，一追问又答不上来了。这个问题答案不是简单的是或不是，而是看你懂不懂 Redis 过期删除背后的策略与性能权衡。
这道题表面在问过期删不删，实际上面试官想考的是你对 Redis 内存管理与淘汰机制的理解。如果这道题你也不会回答，我整理了让大厂面试官沉默的必考题库，涵盖：Java 基础、JVM 夺命连环问、Spring 全家桶、MySQL、Redis、微服务、分布式实战等等。只要是我粉丝留下 "PDF" 直接打包带走。
Redis 过期删除到底是怎么运行的？很多人脑子里只有一个粗糙的印象，设了过期时间等于到点自动删除，等于内存立刻释放。但真实情况下细得多，删，不删取决于有没有触发删除条件，还取决于当前内存水位与配置的淘汰策略。能把这层讲清楚，Redis 与缓存调优功底就立住了。
先说为什么大家会觉得立刻删除？给 key 设置过期时间之后到期再去访问就会返回空，给人的直观感受是数据到点就被删掉了。但这其实是惰性删除在起作用，只有当你主动去查询 key 的时候，Redis 才会顺带检查它有没有过期，过期了就当场删除并返回空。
如果过期 key 一直没人访问，它就会一直躺在内存里占着空间，这就是大家最容易忽略的删除机制。所以在只触发惰性删除的场景下，答案确实不是立刻删除，过期数据会残留内存。
但是这里有个关键的转折，Redis 还有主动清理的定期删除策略。Redis 会每隔一段时间随机抽取一批设置了过期时间的 key 检查其中过期的并批量删除，这在保证主线程性能的前提下主动清理了一部分无人访问的过期数据，避免过期数据越积越多。
还有一个更强制的清理机制就是内存淘汰策略。当 Redis 内存占用达到 max‑memory 上限的时候，哪怕数据没过期也会按照配置的淘汰规则删掉部分数据腾空间。反过来如果内存充足，哪怕过期了没被抽到也没被访问，就会一直留着，相当于内存水位直接决定了要不要强制清理。
这个机制逻辑在真实项目里有什么用？意义非常大。像普通的业务缓存热点数据设置合理的过期时间配合惰性加定期删除就能保证大部分过期数据被及时清理，不用额外干预。而像大促临时，生成的海量短周期缓存活动结束后大量过期 key 没人访问就要注意内存残留问题，必要时主动批量删除或者配置合适的内存淘汰策略，避免过期数据占满内存导致正常缓存被淘汰。
这样既能利用组合删除策略的低开销优势，又能在特殊场景主动规避内存风险，避免了以为过期就删导致的内存溢出隐患，也避免了全量扫描删除带来的性能波动。所以不是设置了过期时间数据就会立刻删除。Redis 是用惰性加定期的组合策略平衡性能与清理效率，做不到时时删除，坑也在这儿。
如果以为过期 key 会立刻释放内存，大量写入短生命周期缓存后不做监控就可能出现过期数据堆积，占用大量内存，甚至触发正常数据被淘汰的问题。这种问题在大促活动结束批量缓存过期的场景里最容易踩到。
所以面试的时候不能只回答会或者不会，标准的思路是先分情况，Redis 不会立刻删除所有过期数据，默认采用惰性删除加定期删除的组合策略，访问到过期 key 时当场删除，同时定期抽样清理部分过期 key，只有当内存达到上限触发淘汰策略时才会强制清理更多数据。
过期删除策略的核心是在不影响 Redis 高性能的前提下尽可能回收过期内存。最后点一句，判断过期数据会不会被删除的本质是看有没有触发删除的条件，而不是单纯到了过期时间就会立刻删除。这样答就显得你是真的懂 Redis 底层机制也懂线上运维，而不是死记硬背结论。这种缓存中间件结合内存管理的题最容易暴露你是不是只停在表面。
