### 1.1 阻断非核心流量

### 1.2 分批 kill 慢查询

```go
// 按执行时长分批 kill
func KillSlowQueries() {
    // 1. 查询慢查询
    slowQueries := db.Query("SELECT id, time FROM information_schema.processlist WHERE time > 10")
    
    // 2. 按执行时长排序
    sort.Slice(slowQueries, func(i, j int) bool {
        return slowQueries[i].Time > slowQueries[j].Time
    })
    
    // 3. 分批 kill，避免批量回滚
    for i := 0; i < len(slowQueries); i += 10 {
        end := i + 10
        if end > len(slowQueries) {
            end = len(slowQueries)
        }
        
        for _, q := range slowQueries[i:end] {
            db.Exec(fmt.Sprintf("KILL %d", q.ID))
        }
        
        // 间隔 1 秒，避免加重负载
        time.Sleep(1 * time.Second)
    }
}
```

## 二、根因定位

### 2.1 快速区分四类场景

```go
// 通过 processlist 定位故障类型
func DiagnoseRootCause() {
    // 1. 查询 processlist
    processes := db.Query("SHOW PROCESSLIST")
    
    // 2. 分析锁等待
    lockWaits := db.Query("SELECT * FROM information_schema.innodb_lock_waits")
    
    // 3. 定位根因
    if len(lockWaits) > 0 {
        // 行锁冲突
        alert("行锁冲突堆积")
    } else if hasLongTransaction(processes) {
        // 大事务
        alert("大事务阻塞")
    } else if hasFullTableScan(processes) {
        // 索引失效
        alert("索引失效，全表扫描")
    } else if isReplicationLag() {
        // 主从延迟
        alert("主从延迟叠加")
    }
}
```

// 监控数据库健康度
func MonitorDatabase() {
    ticker := time.NewTicker(1 * time.Minute)
    for range ticker.C {
        // 1. 慢查询占比
        slowRatio := getSlowQueryRatio()
        if slowRatio > 0.1 {
            alert("慢查询占比 %.2f，超过阈值", slowRatio)
        }
        
        // 2. 平均锁等待时长
        avgLockWait := getAvgLockWaitTime()
        if avgLockWait > 5*time.Second {
            alert("平均锁等待 %v，超过阈值", avgLockWait)
        }
        
        // 3. 连接活跃率
        activeRatio := getConnectionActiveRatio()
        if activeRatio > 0.8 {
            alert("连接活跃率 %.2f，超过阈值", activeRatio)
        }
        
        // 4. 扫描行数/返回行数比值
        scanRatio := getScanToReturnRatio()
        if scanRatio > 1000 {

        }
        
        // 5. 主从延迟时长
        replicationLag := getReplicationLag()
        if replicationLag > 5*time.Second {
            alert("主从延迟 %v，超过阈值", replicationLag)

## 四、SQL上线准入

### 4.1 自动化审核

```go
// SQL 上线强制审核
func ValidateSQL(sql string) error {
    // 1. 索引规范检查
    if !hasIndex(sql) {
        return errors.New("缺少索引")
    }
    
    // 2. 分页查询检查
    if isDeepPagination(sql) {
        return errors.New("禁止深度分页")
    }
    
    // 3. 事务时长检查
    if estimateExecutionTime(sql) > 5*time.Second {
        return errors.New("预计执行时间过长")
    }
    
    // 4. 禁用语法检查
    if hasForbiddenSyntax(sql) {
        return errors.New("包含禁用语法")
    }
    
    return nil
}
```

### 4.2 执行计划校验

```go
// 全量数据量下校验执行计划
func ValidateExecutionPlan(sql string) error {
    // 1. 获取执行计划
    plan := db.Query("EXPLAIN " + sql)
    
    // 2. 检查是否全表扫描
    if plan.Type == "ALL" {
        return errors.New("全表扫描，禁止上线")
    }
    
    // 3. 检查扫描行数
    if plan.Rows > 100000 {
        return errors.New("扫描行数过多")
    }
    
    // 4. 检查是否使用索引
    if plan.Key == "" {
        return errors.New("未使用索引")
    }
    
    return nil
}
```

七、技术深入探讨

### Q1: 慢SQL雪崩怎么应急？

**方案参考**：
> 慢SQL雪崩应急分三步：
> 
> 1. **阻断流量**：网关层阻断非核心业务，只保留核心交易
> 2. **分批 kill**：按执行时长分批 kill 慢查询，避免批量回滚加重负载
> 3. **根因定位**：通过 processlist 和锁等待列表快速区分四类场景
> 
> 核心是先止损后排查，避免故障扩散。

### Q2: 如何长效治理慢SQL？

**方案参考**：
> 长效治理从三个层面：
> 
> 1. **SQL准入**：自动化审核 + 执行计划校验，禁止无索引、深度分页上线
> 2. **日常巡检**：慢查询日志分析，索引健康度扫描
> 3. **核心复核**：订单、支付等核心业务 SQL 变更人工 100% 复核
> 
> 核心是从源头杜绝慢SQL上线。
