## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 主流方案缺陷**
```
单机Quartz：集群必然重复
数据库锁：大流量锁等待
Redisson锁：锁过期重复
XXL-JOB：学习成本高
```

**2. 数据库乐观锁**
```
任务表新增状态、机器、时间戳
调度前更新状态，抢占执行权
锁竞争开销小
```

**3. 任务分片并行**
```
大数据量任务分片拆分
多节点耗时长任务分段
断点续跑，不用全量重跑
```

**4. 异常兜底**
```
执行时长管控：超时自动中断
时钟偏差适配：容错区间
全链路监控：失败/堆积/耗时告警
失败补偿：阶梯重试
```

**5. 断点续跑**
```
执行过程持续记录进度
当机重启后从上次断点继续
不用全量重跑
```

## 一、主流方案缺陷

### 1.1 单机Quartz

```
问题：多实例必然重复执行
```

### 1.2 数据库锁

```go
// 数据库锁抢占
func ExecuteTask(taskID string) error {
    // 1. 加锁
    err := db.Exec("UPDATE tasks SET status = 'RUNNING', lock_time = ? WHERE id = ? AND status = 'IDLE'",
        time.Now(), taskID)
    
    if err != nil || rowsAffected == 0 {
        return errors.New("获取锁失败")
    }
    
    // 2. 执行任务
    doTask(taskID)
    
    // 3. 释放锁
    db.Exec("UPDATE tasks SET status = 'IDLE' WHERE id = ?", taskID)
    
    return nil
}

// 问题：大流量下频繁锁等待
```

### 1.3 Redisson锁

```go
// Redisson分布式锁
func ExecuteTask(taskID string) error {
    lock := redisson.GetLock("task:" + taskID)
    
    // 加锁，设置过期时间
    ok := lock.TryLock(10 * time.Second)
    if !ok {
        return errors.New("获取锁失败")
    }
    defer lock.Unlock()
    
    // 执行任务
    doTask(taskID)
    
    return nil
}
```

## 二、数据库乐观锁

```go
// 乐观锁抢占机制
func ExecuteTask(taskID string) error {
    // 1. 任务表结构
    // tasks: id, status, execute_machine, execute_time, version
    
    // 2. 乐观锁抢占
    result := db.Exec(`
        UPDATE tasks 
        SET status = 'RUNNING', 
            execute_machine = ?, 
            execute_time = ?,
            version = version + 1
        WHERE id = ? AND status = 'IDLE' AND version = ?`,
        machineID, time.Now(), taskID, currentVersion)
    
    if result.RowsAffected == 0 {
        return errors.New("抢占失败")
    }
    
    // 3. 执行任务
    doTask(taskID)
    
    // 4. 更新状态
    db.Exec("UPDATE tasks SET status = 'IDLE', version = version + 1 WHERE id = ?", taskID)
    
    return nil
}

// 优势：锁竞争开销小
```

```go
// 任务分片
type TaskShard struct {
    TaskID    string
    ShardID   int
    StartPos  int64
    EndPos    int64
    Status    string
    Progress  int64
}

// 分片并行处理
func ProcessShards(taskID string, totalSize int64, shardCount int) {
    // 1. 拆分分片
    shardSize := totalSize / int64(shardCount)
    
    for i := 0; i < shardCount; i++ {
        shard := &TaskShard{
            TaskID:   taskID,
            ShardID:  i,
            StartPos: int64(i) * shardSize,
            EndPos:   int64(i+1) * shardSize,
            Status:   "PENDING",
        }
        
        // 2. 分配给不同节点
        assignToNode(shard)
    }
}

// 单节点处理分片
func ProcessShard(shard *TaskShard) error {
    // 1. 查询进度
    progress := getProgress(shard)
    
    // 2. 从断点继续
    for pos := progress; pos < shard.EndPos; pos += batchSize {
        // 处理数据
        processData(pos, batchSize)
        
        // 3. 记录进度
        updateProgress(shard, pos)
    }
    
    return nil
}
```

```go
// 断点续跑
func ResumeTask(taskID string) error {
    // 1. 查询上次进度
    lastProgress := getLastProgress(taskID)
    
    // 2. 从断点继续
    for pos := lastProgress; pos < totalSize; pos += batchSize {
        // 处理数据
        processData(pos, batchSize)
        
        // 3. 持续记录进度
        saveProgress(taskID, pos)
    }
    
    return nil
}

// 当机重启后
func OnRestart() {
    // 1. 查询未完成的任务
    unfinishedTasks := db.Query("SELECT * FROM tasks WHERE status = 'RUNNING'")
    
    for _, task := range unfinishedTasks {
        // 2. 从断点继续
        ResumeTask(task.ID)
    }
}
```

## 五、异常兜底

### 5.1 执行时长管控

```go
// 限制单任务最大执行时间
func ExecuteWithTimeout(taskID string, maxDuration time.Duration) error {
    // 1. 设置超时
    ctx, cancel := context.WithTimeout(context.Background(), maxDuration)
    defer cancel()
    
    // 2. 执行任务
    done := make(chan error, 1)
    go func() {
        done <- doTask(taskID)
    }()
    
    // 3. 超时自动中断
    select {
    case err := <-done:
        return err
    case <-ctx.Done():
        // 超时，释放线程
        return errors.New("任务执行超时，已中断")
    }
}
```

```go
// 调度时间增加容错区间
func ScheduleTask(taskID string, scheduleTime time.Time) {
    // 1. 容错区间：±5秒
    tolerance := 5 * time.Second
    
    // 2. 判断是否执行
    now := time.Now()
    if now.After(scheduleTime.Add(-tolerance)) && now.Before(scheduleTime.Add(tolerance)) {
        executeTask(taskID)
    }
}
```

### 5.4 失败补偿

```go
// 失败任务阶梯重试
func RetryFailedTask(taskID string, retryCount int) {
    // 1. 阶梯重试间隔
    intervals := []time.Duration{
        1 * time.Minute,
        5 * time.Minute,
        15 * time.Minute,
        1 * time.Hour,
    }
    
    if retryCount >= len(intervals) {
        // 2. 多次失败转入人工处理
        transferToManualQueue(taskID)
        alert("任务 %s 多次失败，已转入人工处理", taskID)
        return
    }
    
    // 3. 定时重试
    time.AfterFunc(intervals[retryCount], func() {
        err := executeTask(taskID)
        if err != nil {
            RetryFailedTask(taskID, retryCount+1)
        }
    })
}
```

### Q1: 集群任务重复执行怎么解决？

**方案参考**：
> 集群任务重复执行解决方案：
> 
> 1. **数据库乐观锁**：任务表新增状态、机器、时间戳，调度前更新状态抢占执行权
> 2. **任务分片**：大数据量任务分片拆分，多节点并行处理
> 3. **断点续跑**：执行过程持续记录进度，当机重启后从断点继续
> 
> 核心是乐观锁抢占 + 任务分片。

### Q2: 任务堆积怎么处理？

**方案参考**：
> 任务堆积处理方案：
> 
> 1. **执行时长管控**：限制单任务最大执行时间，超时自动中断
> 2. **时钟偏差适配**：调度时间增加容错区间，搭配机器定时同步
> 3. **全链路监控**：监控失败次数、堆积数量、执行耗时，实时告警
> 4. **失败补偿**：阶梯重试，多次失败转入人工处理
> 
> 核心是监控告警 + 自动补偿。
