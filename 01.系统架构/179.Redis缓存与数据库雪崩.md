# Redis 缓存与数据库雪崩

> **场景定位**：高并发缓存设计技术场景  
> **核心设计要点**：缓存过期策略、缓存宕机、缓存穿透、多级缓存、限流降级、布隆过滤器

---

## 🎯 一句话定位

**Redis 缓存与数据库雪崩问题是什么？**
```
用了 Redis 缓存，但缓存失效时所有请求瞬间打向数据库：
- 上千个商品缓存同时过期
- 恰逢大促高峰期百万用户访问
- 缓存全部 miss，请求全部打到数据库
- 数据库直接崩溃，整个系统不可用
```

**生活化比喻**：就像超市收银台（Redis）突然全部关闭，所有顾客（请求）都涌向唯一的收银员（数据库），收银员直接累瘫，整个超市瘫痪。

**核心特点**：缓存设计不是"用了 Redis 就万事大吉"，而是要做好缓存过期、缓存宕机、缓存穿透的完整容错设计。

### 核心观点（3 层防御）

**1. 缓存过期错开：避免集中失效**
```
随机过期时间：
- 给不同商品设置随机过期时间
- 避免上千个缓存同时过期
- 分散数据库压力

热门商品永不过期：
- 设置永不过期（或超长过期时间）
- 定期后台异步更新数据
- 保证数据一致性的同时避免缓存失效

生活化比喻：
随机过期 = 超市收银台错开休息时间
永不过期 = 24 小时自助收银台（始终开放）
```

**2. 缓存降级 + 限流兜底：防止数据库被击垮**
```
缓存降级：
- Redis 宕机或命中率极低时
- 返回兜底数据（如热门商品默认列表）
- 不直接穿透到数据库

限流保护：
- 对数据库查询做限流
- 限制每秒请求数（如 1000 QPS）
- 防止瞬时流量击垮数据库

生活化比喻：
降级 = 收银台关闭时引导顾客自助结账
限流 = 限制进入超市的人数（避免拥挤）
```

**3. 多级缓存 + 穿透防护：立体防御**
```
多级缓存架构：
- 本地缓存（Caffeine）+ 分布式缓存（Redis）
- 减少 Redis 访问压力
- 本地缓存响应速度更快（微秒级）

布隆过滤器：
- 过滤不存在的商品 ID
- 杜绝缓存穿透
- 避免无效请求打向数据库

生活化比喻：
多级缓存 = 便利店（本地缓存）+ 大超市（Redis）
布隆过滤器 = 门卫检查（拦截无效请求）
```

## 详细章节

### 一、问题本质：为什么 Redis 缓存还会导致数据库雪崩？

#### 1.1 缓存失效的三种场景

```
1. 缓存过期（集中失效）
   - 大量缓存同时过期
   - 恰逢高并发访问
   - 所有请求瞬间打到数据库

2. 缓存宕机（Redis 不可用）
   - Redis 服务挂掉
   - 所有缓存请求失效
   - 请求全部穿透到数据库

3. 缓存穿透（查询不存在的数据）
   - 查询根本不存在的数据
   - 缓存永远 miss
   - 每次请求都打到数据库
```

#### 1.2 技术场景还原

**场景提问**：
```
一个电商首页商品数据频繁被访问，怎么避免数据库被压垮？
```

**普通回答**（60 分）：
```
用 Redis 缓存商品数据，设置过期时间，
查询先查缓存，缓存 miss 再查数据库，简单高效。
```

**加分回答**（90 分）：
```
如果首页上千种商品的缓存同时过期，恰逢大促高峰期百万用户同时访问，
缓存全部 miss，所有请求瞬间打向数据库，数据库直接崩掉，你怎么解决？

需要做好三层防护：
1. 缓存过期错开，避免集中失效
2. 缓存降级 + 限流兜底，防止数据库被击垮
3. 多级缓存 + 穿透防护，立体防御
```

### 二、三层防御详解

#### 2.1 第一层：缓存过期错开

**问题**：上千个商品缓存同时过期，请求全部打到数据库。

**解决方案**：

```java
// ❌ 错误做法：所有商品缓存过期时间相同
for (Product product : products) {
    redis.set("product:" + product.getId(), 
              JSON.toJSONString(product),
              "EX", 3600);  // 都是 1 小时过期
}

// ✅ 正确做法：随机过期时间
Random random = new Random();
for (Product product : products) {
    // 基础过期时间 1 小时 + 随机 0-30 分钟
    int expireTime = 3600 + random.nextInt(1800);
    redis.set("product:" + product.getId(),
              JSON.toJSONString(product),
              "EX", expireTime);
}
```

**热门商品永不过期**：

```java
// 热门商品设置永不过期
redis.set("product:hot:123", 
          JSON.toJSONString(hotProduct));
// 不设置过期时间，或设置超长过期时间（如 7 天）

// 后台异步更新任务（每 10 分钟更新一次）
@Scheduled(fixedRate = 600000)
public void updateHotProducts() {
    List<Product> hotProducts = productMapper.selectHotProducts();
    for (Product product : hotProducts) {
        redis.set("product:hot:" + product.getId(),
                  JSON.toJSONString(product));
    }
}
```

#### 2.2 第二层：缓存降级 + 限流兜底

**缓存降级示例**：

```java
public Product getProduct(Long productId) {
    // 1. 尝试从 Redis 获取
    String json = redis.get("product:" + productId);
    if (json != null) {
        return JSON.parseObject(json, Product.class);
    }
    
    // 2. Redis 不可用，触发降级
    try {
        return productMapper.selectById(productId);
    } catch (Exception e) {
        // 数据库也挂了，返回兜底数据
        log.error("数据库查询失败，返回兜底数据", e);
        return getDefaultProduct(productId);
    }
}

private Product getDefaultProduct(Long productId) {
    // 返回默认商品信息（从本地缓存或配置文件读取）
    return defaultProductCache.get(productId);
}
```

**限流保护示例**（使用 Guava RateLimiter）：

```java
// 限制每秒 1000 个请求
private RateLimiter rateLimiter = RateLimiter.create(1000);

public Product getProductWithRateLimit(Long productId) {
    // 获取不到许可，直接返回降级数据
    if (!rateLimiter.tryAcquire()) {
        log.warn("触发限流，返回降级数据");
        return getDefaultProduct(productId);
    }
    
    return getProduct(productId);
}
```

#### 2.3 第三层：多级缓存 + 穿透防护

**多级缓存架构**：

```java
// 本地缓存（Caffeine）
private Cache<Long, Product> localCache = Caffeine.newBuilder()
    .maximumSize(10000)
    .expireAfterWrite(5, TimeUnit.MINUTES)
    .build();

public Product getProductMultiLevel(Long productId) {
    // 1. 先查本地缓存（微秒级）
    Product product = localCache.getIfPresent(productId);
    if (product != null) {
        return product;
    }
    
    // 2. 再查 Redis（毫秒级）
    String json = redis.get("product:" + productId);
    if (json != null) {
        product = JSON.parseObject(json, Product.class);
        localCache.put(productId, product);  // 写入本地缓存
        return product;
    }
    
    // 3. 最后查数据库
    product = productMapper.selectById(productId);
    if (product != null) {
        redis.set("product:" + productId, JSON.toJSONString(product), "EX", 3600);
        localCache.put(productId, product);
    }
    
    return product;
}
```

**布隆过滤器防穿透**：

```java
// 初始化布隆过滤器（预期 100 万个商品 ID，误判率 1%）
private BloomFilter<Long> bloomFilter = BloomFilter.create(
    Funnels.longFunnel(), 
    1000000, 
    0.01
);

// 启动时加载所有商品 ID 到布隆过滤器
@PostConstruct
public void init() {
    List<Long> allProductIds = productMapper.selectAllIds();
    for (Long id : allProductIds) {
        bloomFilter.put(id);
    }
}

public Product getProductWithBloomFilter(Long productId) {
    // 1. 布隆过滤器判断商品是否存在
    if (!bloomFilter.mightContain(productId)) {
        // 肯定不存在，直接返回 null，不查数据库
        return null;
    }
    
    // 2. 可能存在，继续查询缓存/数据库
    return getProductMultiLevel(productId);
}
```

### 三、代码示例：完整的缓存容错方案

```java
@Service
public class ProductService {
    
    @Autowired
    private ProductMapper productMapper;
    
    @Autowired
    private StringRedisTemplate redis;
    
    // 本地缓存（Caffeine）
    private Cache<Long, Product> localCache = Caffeine.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    // 布隆过滤器
    private BloomFilter<Long> bloomFilter = BloomFilter.create(
        Funnels.longFunnel(), 1000000, 0.01
    );
    
    // 限流器（每秒 1000 个请求）
    private RateLimiter rateLimiter = RateLimiter.create(1000);
    
    /**
     * 完整的缓存查询方案
     */
    public Product getProduct(Long productId) {
        // 0. 限流检查
        if (!rateLimiter.tryAcquire()) {
            log.warn("触发限流，返回降级数据");
            return getDefaultProduct(productId);
        }
        
        // 1. 布隆过滤器检查（防穿透）
        if (!bloomFilter.mightContain(productId)) {
            return null;  // 商品肯定不存在
        }
        
        // 2. 查本地缓存（微秒级）
        Product product = localCache.getIfPresent(productId);
        if (product != null) {
            return product;
        }
        
        // 3. 查 Redis（毫秒级）
        try {
            String json = redis.opsForValue().get("product:" + productId);
            if (json != null) {
                product = JSON.parseObject(json, Product.class);
                localCache.put(productId, product);
                return product;
            }
        } catch (Exception e) {
            log.error("Redis 查询失败", e);
            // Redis 挂了，继续查数据库
        }
        
        // 4. 查数据库（兜底）
        try {
            product = productMapper.selectById(productId);
            if (product != null) {
                // 写入缓存（随机过期时间）
                int expireTime = 3600 + new Random().nextInt(1800);
                redis.opsForValue().set(
                    "product:" + productId,
                    JSON.toJSONString(product),
                    expireTime,
                    TimeUnit.SECONDS
                );
                localCache.put(productId, product);
            }
            return product;
        } catch (Exception e) {
            log.error("数据库查询失败", e);
            // 数据库也挂了，返回降级数据
            return getDefaultProduct(productId);
        }
    }
    
    private Product getDefaultProduct(Long productId) {
        // 返回默认商品信息
        return new Product(productId, "商品已下架", 0.0);
    }
}
```

### 考点 1：缓存雪崩是什么？怎么解决？

**方案参考**（60 分）：
```
缓存雪崩是指大量缓存同时过期，
导致所有请求都打到数据库，数据库压力过大而崩溃。

解决方法：
1. 给缓存设置随机过期时间，避免同时过期
2. 热门商品永不过期，后台异步更新
```

**加分回答**（90 分）：
```
缓存雪崩的完整解决方案需要三层防护：

第一层：缓存过期错开
- 随机过期时间，避免集中失效
- 热门商品永不过期，异步更新

第二层：缓存降级 + 限流兜底
- Redis 宕机时返回兜底数据
- 对数据库查询做限流，防止被击垮

第三层：多级缓存 + 穿透防护
- 本地缓存（Caffeine）+ Redis 多级缓存
- 布隆过滤器过滤不存在的 ID，防穿透

核心思路：缓存的核心不是"加速查询"，
而是在高并发下保护数据库不崩，同时保证系统可用数据一致。
```

### 考点 2：Redis 宕机了怎么办？

**方案参考**（60 分）：
```
Redis 宕机时，所有缓存请求都会失效，
请求会全部打到数据库，导致数据库崩溃。

解决方法：
1. 搭建 Redis 集群（主从 + 哨兵）
2. 数据库做限流保护
3. 返回降级数据
```

**加分回答**（90 分）：
```
Redis 宕机的完整应对方案：

1. 缓存降级
   - Redis 不可用时，直接查数据库
   - 数据库也挂了，返回兜底数据（默认列表）
   - 不直接穿透到数据库

2. 限流保护
   - 对数据库查询做限流（如 1000 QPS）
   - 超出限流的请求直接返回降级数据
   - 防止数据库被瞬时流量击垮

3. 多级缓存
   - 本地缓存（Caffeine）作为第一道防线
   - 即使 Redis 挂了，本地缓存还能扛一部分

4. Redis 高可用架构
   - Redis 集群（主从 + 哨兵）
   - 自动故障转移，减少宕机时间

核心思路：不依赖单一缓存，多级缓存 + 降级 + 限流，立体防御。
```

---

### 考点 3：如何防止缓存穿透？

**方案参考**（60 分）：
```
缓存穿透是指查询根本不存在的数据，
缓存永远 miss，每次请求都打到数据库。

解决方法：
1. 布隆过滤器过滤不存在的 ID
2. 缓存空值（设置较短过期时间）
```

**加分回答**（90 分）：
```
缓存穿透的完整解决方案：

1. 布隆过滤器（推荐）
   - 启动时加载所有商品 ID 到布隆过滤器
   - 查询时先判断 ID 是否存在
   - 肯定不存在的数据直接返回，不查数据库
   - 误判率 1%，内存占用小

2. 缓存空值
   - 查询数据库返回 null 时，缓存空值
   - 设置较短过期时间（如 5 分钟）
   - 缺点：如果攻击者随机生成大量不存在的 ID，
     缓存会膨胀，内存占用大

3. 参数校验
   - 对 ID 做合法性校验（如 ID > 0，ID 格式正确）
   - 拦截明显非法的请求

推荐方案：布隆过滤器 + 参数校验，双重防护。
布隆过滤器误判率低，内存占用小，性能高。
```
