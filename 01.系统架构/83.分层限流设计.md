# 分层限流设计

> **场景定位**：高并发架构技术场景  
> **核心设计要点**：多层防护、流量分级、动态调参、核心保护

---

## 🎯 一句话定位

**分层限流解决什么问题？**
```
单一限流无法应对复杂流量场景
需要多层防护，分级处理
保护核心业务不被流量洪峰冲垮
```

**生活化比喻**：
就像地铁限流：
- 站外限流：控制进站人数（网关层）
- 站台限流：控制候车人数（服务层）
- 车厢限流：控制乘车人数（数据层）

---

## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 三层限流架构**
```
网关层：全局限流，粗粒度
服务层：接口级限流，细粒度
数据层：数据库保护，最后防线
```

**2. 流量分级**
```
核心业务：优先保障，高配额
非核心业务：可降级，低配额
边缘业务：高峰期直接熔断
```

**3. 四种限流算法**
```
固定窗口：实现简单，临界问题
滑动窗口：平滑限流，资源消耗大
漏桶算法：恒定速率，突发处理差
令牌桶：允许突发，实现复杂
```

**4. 动态调参**
```
平时：宽松配额，保障体验
大促：收紧配额，保护核心
故障：紧急降级，快速恢复
```

**5. 限流熔断联动**
```
限流：防止过载
熔断：快速失败
降级：保障核心
```

## 一、三层限流架构

### 1.1 网关层限流

```go
// 网关层：全局限流
func GatewayLimiter(c *gin.Context) {
    // 全局限流：每秒 10000 请求
    if !globalLimiter.Allow(10000) {
        c.JSON(503, gin.H{"error": "系统繁忙，请稍后重试"})
        c.Abort()
        return
    }
    
    // 用户级限流：每秒 100 请求
    userID := c.GetHeader("X-User-ID")
    if !userLimiter.Allow(userID, 100) {
        c.JSON(429, gin.H{"error": "请求过于频繁"})
        c.Abort()
        return
    }
    
    c.Next()
}
```

### 1.2 服务层限流

```go
// 服务层：接口级限流
func APILimiter() gin.HandlerFunc {
    return func(c *gin.Context) {
        path := c.Request.URL.Path
        
        // 核心接口：每秒 5000 请求
        if strings.HasPrefix(path, "/api/order") {

                c.JSON(503, gin.H{"error": "下单繁忙"})

        // 非核心接口：每秒 1000 请求

                return
            }
        }
        
        c.Next()
    }
}
```

## 二、流量分级

### 2.1 业务分级

```go
type BusinessLevel int

const (
    Core      BusinessLevel = iota // 核心业务：订单、支付
    Normal                         // 非核心：查询、统计
    Edge                           // 边缘：日志、埋点
)

// 根据业务等级分配配额
func AllocateQuota(level BusinessLevel) int {
    switch level {
    case Core:
        return 5000 // 高配额
    case Normal:
        return 1000 // 中配额
    case Edge:
        return 100  // 低配额
    default:
        return 0
    }
}
```

### 2.2 分级限流

```go
func RateLimitByLevel(c *gin.Context) {
    level := getBusinessLevel(c.Request.URL.Path)
    quota := AllocateQuota(level)
    
    if !limiter.Allow(quota) {
        // 核心业务：排队等待
        if level == Core {
            time.Sleep(100 * time.Millisecond)
            return
        }
        
        // 非核心业务：直接拒绝
        c.JSON(503, gin.H{"error": "系统繁忙"})
        c.Abort()
    }
}
```

## 三、四种限流算法

### 3.1 固定窗口

```go
type FixedWindowLimiter struct {
    limit  int
    window time.Duration
    count  int
    reset  time.Time
}

func (l *FixedWindowLimiter) Allow() bool {
    now := time.Now()
    if now.After(l.reset) {
        l.count = 0
        l.reset = now.Add(l.window)
    }
    
    if l.count >= l.limit {
        return false
    }
    
    l.count++
    return true
}
```

### 3.2 滑动窗口

```go
type SlidingWindowLimiter struct {
    limit    int
    window   time.Duration
    requests []time.Time
}

func (l *SlidingWindowLimiter) Allow() bool {
    now := time.Now()
    windowStart := now.Add(-l.window)
    
    // 清理过期请求
    var valid []time.Time
    for _, t := range l.requests {
        if t.After(windowStart) {
            valid = append(valid, t)
        }
    }
    l.requests = valid
    
    if len(l.requests) >= l.limit {
        return false
    }
    
    l.requests = append(l.requests, now)
    return true
}
```

### 3.3 令牌桶

```go
type TokenBucketLimiter struct {
    rate     float64 // 令牌生成速率
    capacity int     // 桶容量
    tokens   float64
    lastTime time.Time
}

func (l *TokenBucketLimiter) Allow() bool {
    now := time.Now()
    elapsed := now.Sub(l.lastTime).Seconds()
    
    // 生成新令牌
    l.tokens += elapsed * l.rate
    if l.tokens > float64(l.capacity) {
        l.tokens = float64(l.capacity)
    }
    l.lastTime = now
    
    // 消耗令牌
    if l.tokens < 1 {
        return false
    }
    
    l.tokens--
    return true
}
```

```go
// 动态调整限流参数
func AdjustRateLimit(mode string) {
    switch mode {
    case "normal":
        // 平时：宽松配额
        globalQuota = 10000
        coreQuota = 5000
    case "promotion":
        // 大促：收紧配额

        // 故障：紧急降级

    }
}

// 监控告警自动调参
func AutoAdjust() {
    ticker := time.NewTicker(1 * time.Minute)
    for range ticker.C {
        cpu := getCPUUsage()
        memory := getMemoryUsage()
        
        if cpu > 80 || memory > 80 {
            AdjustRateLimit("emergency")
            alert("系统负载过高，已自动降级")
        }
    }
}
```

六、技术深入探讨

### Q1: 为什么要分层限流？

**方案参考**：
> 分层限流是为了多层防护：
> 
> 1. **网关层**：全局限流，防止流量洪峰冲垮系统
> 2. **服务层**：接口级限流，保护核心接口
> 3. **数据层**：数据库保护，最后防线
> 
> 单层限流无法应对复杂流量场景，需要多层防护，分级处理。

### Q2: 四种限流算法怎么选？

**方案参考**：
> 四种算法各有优缺点：
> 
> 1. **固定窗口**：实现简单，但有临界问题
> 2. **滑动窗口**：平滑限流，但资源消耗大
> 3. **漏桶算法**：恒定速率，但突发处理差
> 4. **令牌桶**：允许突发，但实现复杂
> 
> 推荐：网关层用令牌桶（允许突发），服务层用滑动窗口（平滑），数据层用漏桶（恒定）。
