## 🎯 一句话定位

**大文件上传问题是什么？**
```
分片上传逻辑没问题，断点续传也正常，但：
- 分片丢失导致无法合并
- 上传速度极慢，大文件上传一半超时
- 上传成功后视频无法播放、文件损坏
```

**生活化比喻**：就像寄一个大型家具，拆成了 10 个包裹寄出，但有的包裹丢了（分片丢失），有的寄错了地址（乱序），组装时发现零件不匹配（文件损坏）。

**核心特点**：分片上传不仅仅是切片和上传，还需要分片校验、并发控制、存储优化。

## 一、问题本质：分片上传的隐性风险

### ❌ 常见误区

**误区 1：分片越小越好**
```
问题：
- 分片过小（如 100KB），1GB 文件需要 10000 个请求
- 请求过多，服务器压力大
- 合并时间长

解决：
- 合理分片大小（如 5-10MB）
- 结合网络带宽动态调整
```

**误区 2：上传成功就万事大吉**
```
问题：
- 分片可能损坏（网络传输错误）
- 分片可能乱序（并发上传）
- 合并时没有校验

解决：
- 每个分片上传后校验 MD5
- 校验分片顺序
- 合并后校验完整文件
```

**误区 3：断点续传只是记录进度**
```
问题：
- 只记录进度，不校验分片有效性
- 服务重启后状态丢失
- 重复上传无效分片

解决：
- 记录每个分片的 MD5 值
- 持久化上传状态（Redis/数据库）
- 恢复时校验分片有效性
```

## 二、第一层防御：基础方案优化

### 2.1 分片策略优化

**生活化比喻**：
```
分片大小 = 包裹大小
- 太小（100KB）：1GB 文件 10000 个包裹，快递累死
- 太大（100MB）：单个包裹太大，容易丢失
- 合适（5-10MB）：1GB 文件 100-200 个包裹，刚好

动态调整：
- 网络好：分片大一些（10MB）
- 网络差：分片小一些（2MB）
```

**代码示例（动态分片）**：
```javascript
// 前端：根据网络带宽动态调整分片大小
function calculateChunkSize(file) {
    // 检测网络带宽（Navigator API）
    const connection = navigator.connection || navigator.mozConnection || navigator.webkitConnection;
    
    if (connection) {
        const bandwidth = connection.downlink; // Mbps
        
        if (bandwidth > 10) {
            return 10 * 1024 * 1024; // 10MB
        } else if (bandwidth > 5) {
            return 5 * 1024 * 1024; // 5MB
        } else {
            return 2 * 1024 * 1024; // 2MB
        }
    }
    
    // 默认 5MB
    return 5 * 1024 * 1024;
}

// 分片
function sliceFile(file) {
    const chunkSize = calculateChunkSize(file);
    const chunks = [];
    let start = 0;
    let index = 0;
    
    while (start < file.size) {
        const end = Math.min(start + chunkSize, file.size);
        chunks.push({
            blob: file.slice(start, end),
            index: index,
            start: start,
            end: end
        });
        start = end;
        index++;
    }
    
    return chunks;
}
```

### 2.2 分片校验机制

**生活化比喻**：
```
分片校验 = 每个包裹贴条形码
- 上传前计算 MD5（发件人贴条形码）
- 上传后服务器校验 MD5（收件人检查条形码）
- 不匹配说明包裹损坏，重新上传

顺序校验：
- 记录分片顺序号
- 合并时按顺序号排序
- 防止乱序合并
```

**代码示例**：
```java
@RestController
public class UploadController {
    
    @Autowired
    private StorageService storageService;
    
    @PostMapping("/upload/chunk")
    public Result uploadChunk(
        @RequestParam("file") MultipartFile chunk,
        @RequestParam("fileId") String fileId,
        @RequestParam("chunkIndex") int chunkIndex,
        @RequestParam("chunkMd5") String chunkMd5
    ) {
        // 1. 计算实际 MD5
        String actualMd5 = calculateMd5(chunk);
        
        // 2. 校验 MD5
        if (!actualMd5.equals(chunkMd5)) {
            return Result.error("分片校验失败，请重新上传");
        }
        
        // 3. 存储分片
        String chunkPath = "chunks/" + fileId + "/" + chunkIndex;
        storageService.save(chunkPath, chunk.getBytes());
        
        // 4. 记录分片信息
        saveChunkInfo(fileId, chunkIndex, chunkMd5);
        
        return Result.success();
    }
    
    private String calculateMd5(MultipartFile file) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            byte[] digest = md.digest(file.getBytes());
            return DatatypeConverter.printHexBinary(digest).toLowerCase();
        } catch (Exception e) {
            throw new RuntimeException("MD5 计算失败", e);
        }
    }
    
    private void saveChunkInfo(String fileId, int chunkIndex, String md5) {
        // 保存到 Redis 或数据库
        String key = "upload:chunks:" + fileId;
        redisTemplate.opsForHash().put(key, chunkIndex, md5);
    }
}
```

### 2.3 断点续传升级

**生活化比喻**：
```
断点续传 = 记录哪些包裹已寄出
- 上传前查询已上传的分片
- 只上传未上传的分片
- 避免重复上传

状态恢复：
- 持久化上传状态（Redis/数据库）
- 服务重启后可以恢复
- 校验已上传分片的有效性
```

**代码示例**：
```javascript
// 前端：断点续传
async function uploadFile(file) {
    const fileId = generateFileId(file);
    
    // 1. 查询已上传的分片
    const uploadedChunks = await getUploadedChunks(fileId);
    
    // 2. 分片
    const chunks = sliceFile(file);
    
    // 3. 上传未上传的分片
    for (const chunk of chunks) {
        if (uploadedChunks.includes(chunk.index)) {
            console.log(`分片 ${chunk.index} 已上传，跳过`);
            continue;
        }
        
        // 计算 MD5
        const md5 = await calculateMd5(chunk.blob);
        
        // 上传分片
        await uploadChunk(chunk, fileId, md5);
        
        // 更新进度
        updateProgress(chunk.index, chunks.length);
    }
    
    // 4. 合并分片
    await mergeChunks(fileId, file.name);
}

// 查询已上传的分片
async function getUploadedChunks(fileId) {
    const response = await fetch(`/upload/chunks?fileId=${fileId}`);
    const result = await response.json();
    return result.data || [];
}
```

```java
// 后端：查询已上传的分片
@GetMapping("/upload/chunks")
public Result<List<Integer>> getUploadedChunks(@RequestParam("fileId") String fileId) {
    String key = "upload:chunks:" + fileId;
    
    Map<Object, Object> chunkMap = redisTemplate.opsForHash().entries(key);
    
    List<Integer> uploadedChunks = chunkMap.keySet().stream()
        .map(k -> Integer.parseInt(k.toString()))
        .collect(Collectors.toList());
    
    return Result.success(uploadedChunks);
}
```

## 三、第二层防御：性能优化

### 3.1 并发分片上传

**生活化比喻**：
```
并发上传 = 同时寄多个包裹
- 前端多线程同时上传
- 后端支持并发接收
- 限制并发数（避免服务器压力过大）

就像：
- 同时叫 5 个快递员寄包裹
- 但不要让 100 个快递员同时来（服务器会崩）
```

**代码示例**：
```javascript
// 前端：并发上传
async function uploadChunksInParallel(chunks, fileId, concurrency = 5) {
    const results = [];
    const executing = new Set();
    
    for (const chunk of chunks) {
        const p = Promise.resolve().then(() => uploadChunk(chunk, fileId));
        results.push(p);
        executing.add(p);
        
        const clean = () => executing.delete(p);
        p.then(clean).catch(clean);
        
        // 控制并发数
        if (executing.size >= concurrency) {
            await Promise.race(executing);
        }
    }
    
    return Promise.all(results);
}

// 使用
uploadChunksInParallel(chunks, fileId, 5); // 最多 5 个并发
```

### 3.3 预上传校验

**生活化比喻**：
```
预校验 = 寄之前检查包裹是否合规
- 检查文件格式（是否允许）
- 检查文件大小（是否超限）
- 检查 MD5（是否重复）

提前拦截非法文件
```

**代码示例**：
```java
@PostMapping("/upload/check")
public Result<CheckResult> checkUpload(
    @RequestParam("fileName") String fileName,
    @RequestParam("fileSize") long fileSize,
    @RequestParam("fileMd5") String fileMd5
) {
    CheckResult result = new CheckResult();
    
    // 1. 检查文件格式
    String extension = fileName.substring(fileName.lastIndexOf(".") + 1);
    List<String> allowedExtensions = Arrays.asList("mp4", "avi", "mov", "mkv");
    if (!allowedExtensions.contains(extension.toLowerCase())) {
        return Result.error("不支持的文件格式");
    }
    
    // 2. 检查文件大小
    long maxSize = 2L * 1024 * 1024 * 1024; // 2GB
    if (fileSize > maxSize) {
        return Result.error("文件大小超过限制");
    }
    
    // 3. 检查是否已上传（秒传）
    String fileKey = "upload:file:" + fileMd5;
    String existFileId = redisTemplate.opsForValue().get(fileKey);
    
    if (existFileId != null) {
        // 文件已存在，秒传
        result.setUploaded(true);
        result.setFileId(existFileId);
        return Result.success(result);
    }
    
    // 4. 返回上传配置
    result.setUploaded(false);
    result.setFileId(generateFileId());
    result.setChunkSize(5 * 1024 * 1024);
    
    return Result.success(result);
}
```

### 4.1 分片存储容错

**生活化比喻**：
```
分布式存储 = 多个仓库备份包裹
- 分片存储到分布式文件系统（如 MinIO、HDFS）
- 避免单节点故障导致分片丢失
- 支持多副本备份

就像：
- 每个包裹在 3 个仓库都有备份
- 一个仓库着火了，其他仓库还有
```

**代码示例（MinIO 存储）**：
```java
@Service
public class StorageService {
    
    @Autowired
    private MinioClient minioClient;
    
    public void saveChunk(String fileId, int chunkIndex, byte[] data) {
        String objectName = fileId + "/" + chunkIndex;
        
        try {
            ByteArrayInputStream bais = new ByteArrayInputStream(data);
            
            minioClient.putObject(
                PutObjectArgs.builder()
                    .bucket("upload-chunks")
                    .object(objectName)
                    .stream(bais, data.length, -1)
                    .build()
            );
        } catch (Exception e) {
            throw new RuntimeException("分片存储失败", e);
        }
    }
    
    public byte[] getChunk(String fileId, int chunkIndex) {
        String objectName = fileId + "/" + chunkIndex;
        
        try {
            InputStream stream = minioClient.getObject(
                GetObjectArgs.builder()
                    .bucket("upload-chunks")
                    .object(objectName)
                    .build()
            );
            
            return stream.readAllBytes();
        } catch (Exception e) {
            throw new RuntimeException("分片读取失败", e);
        }
    }
}
```

### 4.2 合并失败补偿

**生活化比喻**：
```
合并补偿 = 组装失败重新组装
- 合并失败自动重试（最多 3 次）
- 重试仍失败，通知用户
- 保留已上传分片，支持再次合并
- 避免重复上传全部内容
```

**代码示例**：
```java
@Service
public class MergeService {
    
    @Autowired
    private StorageService storageService;
    
    public void mergeChunks(String fileId, String fileName) {
        int maxRetries = 3;
        int retryCount = 0;
        
        while (retryCount < maxRetries) {
            try {
                doMerge(fileId, fileName);
                return; // 合并成功
            } catch (Exception e) {
                retryCount++;
                log.error("合并失败，第 {} 次重试", retryCount, e);
                
                if (retryCount >= maxRetries) {
                    // 重试次数用尽，通知用户
                    notifyUser(fileId, "合并失败，请重试");
                    
                    // 保留分片，支持再次合并
                    saveMergeStatus(fileId, "FAILED");
                }
            }
        }
    }
    
    private void doMerge(String fileId, String fileName) throws IOException {
        // 1. 获取所有分片
        Map<Object, Object> chunkMap = getChunkMap(fileId);
        
        // 2. 按顺序合并
        try (OutputStream os = Files.newOutputStream(Paths.get("temp/" + fileName))) {
            for (int i = 0; i < chunkMap.size(); i++) {
                byte[] chunk = storageService.getChunk(fileId, i);
                os.write(chunk);
            }
        }
        
        // 3. 校验完整文件
        String fileMd5 = calculateFileMd5("temp/" + fileName);
        
        // 4. 上传到最终存储
        storageService.saveFinalFile(fileName, fileMd5);
        
        // 5. 清理分片
        cleanupChunks(fileId);
        
        // 6. 记录文件信息
        saveFileInfo(fileName, fileMd5);
    }
}
```

```java
public class UploadMonitorService {

     */

        long totalUploads = getTotalUploads(1);
        long failedUploads = getFailedUploads(1);
        
        double failureRate = (double) failedUploads / totalUploads;
        
        if (failureRate > 0.05) { // 失败率超过 5%
            sendAlert("上传失败率告警：" + failureRate);
        }
    }
    
    /**
     * 监控存储占用
     */
    @Scheduled(fixedRate = 3600000) // 每小时检查一次
    public void monitorStorageUsage() {
        long storageUsed = getStorageUsed();
        long storageLimit = 1000L * 1024 * 1024 * 1024; // 1TB
        
        double usageRate = (double) storageUsed / storageLimit;
        
        if (usageRate > 0.8) { // 使用率超过 80%
            sendAlert("存储空间告警：" + usageRate);
        }
    }

        System.out.println("[ALERT] " + message);
    }
```

五、技术深入探讨

### 考点 1：如何解决分片丢失？

**方案参考**（30 秒版）：
> "解决分片丢失要分三步：1）每个分片上传后校验 MD5，确保分片完整；2）用分布式存储（如 MinIO）存储分片，避免单节点故障；3）支持多副本备份，提高可靠性。合并时按顺序号排序，防止乱序。"

**加分回答**：
> "实际生产中，我会用 MinIO 存储分片，它支持分布式部署和多副本。每个分片上传后计算 MD5，服务器校验，不匹配则重新上传。同时要监控分片存储状态，发现异常及时告警。"

### 考点 2：如何优化大文件上传性能？

**方案参考**：
> "优化大文件上传性能要从三个方面：1）前端并发上传，多线程同时上传多个分片，控制并发数；2）CDN 加速，就近节点接收分片，降低延迟；3）预上传校验，检查文件格式、大小、MD5，提前拦截非法文件。"

**加分回答**：
> "实际生产中，我会用 Web Worker 实现并发上传，避免阻塞主线程。同时用 CDN 加速，支持分片就近上传。对于超大文件（如 10GB），可以动态调整分片大小（网络好时大一些，网络差时小一些）。还要做秒传，文件已存在则直接返回。"

### 考点 3：如何处理合并失败？

**方案参考**：
> "合并失败要有补偿机制：1）自动重试，最多 3 次；2）重试仍失败，通知用户；3）保留已上传分片，支持再次合并，避免重复上传。同时要记录合并日志，便于排查问题。"

**加分回答**：
> "实际生产中，我会用异步任务处理合并，避免阻塞用户请求。合并失败后，记录失败原因，自动重试。重试仍失败，发送通知给用户，并在界面上显示"重试合并"按钮。同时要监控合并失败率，发现异常及时告警。"

## 六、总结（一句话带走）

### 🎯 一句话总结

> **大文件上传三层防御 = 基础优化（分片策略/校验/断点续传） + 性能优化（并发/CDN/预校验） + 兜底保障（存储容错/合并补偿/监控）**

### 🧠 核心记忆点

1. **分片丢失**：每个分片校验 MD5，用分布式存储，支持多副本备份。
2. **上传超时**：合理分片大小（5-10MB），并发上传，CDN 加速。
3. **文件损坏**：分片校验 + 合并后校验完整文件。
4. **断点续传**：记录已上传分片，只上传未上传的分片。
5. **合并失败**：自动重试，保留分片，支持再次合并。
