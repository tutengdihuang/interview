# Spring事务失效排查

> **场景定位**：Spring 框架技术场景  
> **核心设计要点**：AOP代理、异常处理、传播行为、多线程、多数据源

---

## 🎯 一句话定位

**Spring事务失效解决什么问题？**
```
加了 @Transactional 注解
但异常了数据没回滚
事务直接失效
```

**生活化比喻**：
就像保险：
- 买了保险（加了注解）
- 出事了不赔（没回滚）
- 因为没看清条款（失效场景）

---

## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 事务基于AOP代理**
```
只有通过代理对象调用才生效
同类自调用绕过代理 → 失效
```

**2. 异常处理不当**
```
异常被 try-catch 吞了 → 切面无法感知
异常类型与 rollbackFor 不匹配 → 不回滚
```

**3. 传播行为错配**
```
嵌套事务用了 REQUIRED → 共享事务
应该用 REQUIRES_NEW → 独立事务
```

**4. 多线程环境**
```
子线程的写操作不纳入当前事务
ThreadLocal 事务上下文线程隔离
```

**5. 多数据源**
```
默认管一个数据源
跨数据源需要指定事务管理器
```

---

## 🚀 一句话精华

> **事务失效 = AOP代理（同类自调用） + 异常处理（吞异常/类型不匹配） + 传播行为（REQUIRED/REQUIRES_NEW） + 多线程（ThreadLocal隔离） + 多数据源（指定管理器）**

## 一、同类自调用失效

### ❌ 失效场景

```java
@Service
public class OrderService {
    
    // 没有事务注解
    public void createOrder() {
        // 同类调用，绕过代理
        this.doCreateOrder(); // ❌ 事务失效
    }
    
    @Transactional
    public void doCreateOrder() {
        // 数据库操作
    }
}
```

### ✅ 解决方案

```java
// 方案1：注入自身代理对象
@Service
public class OrderService {
    
    @Autowired
    private OrderService self;
    
    public void createOrder() {
        self.doCreateOrder(); // ✅ 通过代理调用
    }
    
    @Transactional
    public void doCreateOrder() {
        // 数据库操作
    }
}

// 方案2：AopContext 获取代理
@Service
public class OrderService {
    
    public void createOrder() {
        OrderService proxy = (OrderService) AopContext.currentProxy();
        proxy.doCreateOrder(); // ✅ 通过代理调用
    }
    
    @Transactional
    public void doCreateOrder() {
        // 数据库操作
    }
}
```

## 二、异常处理不当

### ❌ 异常被吞

```java
@Transactional
public void createOrder() {
    try {
        // 数据库操作
        throw new RuntimeException("异常");
    } catch (Exception e) {
        // ❌ 异常被吞，事务不回滚
        log.error("错误", e);
    }
}
```

### ✅ 手动回滚

```java
@Transactional
public void createOrder() {
    try {
        // 数据库操作
        throw new RuntimeException("异常");
    } catch (Exception e) {
        // ✅ 手动标记回滚
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        log.error("错误", e);
    }
}
```

### ✅ 配置 rollbackFor

```java
// 指定回滚异常类型
@Transactional(rollbackFor = Exception.class)
public void createOrder() throws Exception {
    // 数据库操作
    throw new Exception("异常"); // ✅ 会回滚
}
```

## 三、传播行为错配

### ❌ REQUIRED 共享事务

```java
@Transactional(propagation = Propagation.REQUIRED)
public void methodA() {
    // 事务 A
    methodB(); // 共享同一个事务
}

@Transactional(propagation = Propagation.REQUIRED)
public void methodB() {
    // 如果 methodB 异常，methodA 也会回滚
}
```

### ✅ REQUIRES_NEW 独立事务

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void methodA() {
    // 事务 A
    methodB(); // 独立事务
}

@Transactional(propagation = Propagation.REQUIRES_NEW)
public void methodB() {
    // 事务 B，独立于事务 A
    // methodB 异常不影响 methodA
}
```

## 四、多线程环境

### ❌ 子线程不纳入事务

```java
@Transactional
public void createOrder() {
    // 主线程事务
    
    new Thread(() -> {
        // ❌ 子线程的写操作不纳入当前事务
        db.insert(data);
    }).start();
}
```

### ✅ 解决方案

```java
@Transactional
public void createOrder() {
    // 主线程内执行所有数据库操作
    db.insert(data1);
    db.insert(data2);
    
    // 不要在事务内开子线程做数据库操作
}
```

## 五、多数据源

### ❌ 默认事务管理器

```java
@Transactional
public void createOrder() {
    // 默认使用主数据源事务管理器
    // 如果操作从数据源，事务失效
    slaveDb.insert(data); // ❌ 不受事务控制
}
```

### ✅ 指定事务管理器

```java
@Transactional("slaveTransactionManager")
public void createOrder() {
    // 指定从数据源事务管理器
    slaveDb.insert(data); // ✅ 受事务控制
}
```

## 六、编程式事务

```java
@Service
public class OrderService {
    
    @Autowired
    private TransactionTemplate transactionTemplate;
    
    public void createOrder() {
        // 编程式事务，灵活控制
        transactionTemplate.execute(status -> {
            try {
                // 数据库操作
                return true;
            } catch (Exception e) {
                status.setRollbackOnly(); // 手动回滚
                return false;
            }
        });
    }
}
```

**优势**：
- 不受 AOP 代理限制
- 灵活控制事务边界
- 适合复杂业务场景

## 七、快速排查四步法

```
线上事务不回滚，按四步定位：

1. 查是否同类自调用
   - 是否 this.method() 调用
   
2. 查是否吞了异常
   - 是否有 try-catch 没抛出
   
3. 查方法是否为 public
   - 非 public 方法代理不生效
   
4. 核对传播行为与异常类型
   - rollbackFor 是否匹配
```

八、技术深入探讨

### Q1: 事务失效有哪些场景？

**方案参考**：
> 事务失效六大场景：
> 
> 1. **同类自调用**：绕过 AOP 代理
> 2. **异常被吞**：try-catch 没抛出
> 3. **异常类型不匹配**：rollbackFor 配置错误
> 4. **非 public 方法**：代理不生效
> 5. **多线程环境**：ThreadLocal 隔离
> 6. **多数据源**：未指定事务管理器
> 
> 核心是理解 AOP 代理机制。

### Q2: 怎么避免事务失效？

**方案参考**：
> 避免事务失效建立规范：
> 
> 1. **禁止同类直接调用**：通过注入自身代理或 AopContext
> 2. **统一 rollbackFor**：覆盖全异常类型
> 3. **禁止静默捕获异常**：手动标记回滚
> 4. **正确选择传播行为**：独立事务用 REQUIRES_NEW
> 5. **多数据源指定管理器**：明确指定事务管理器
> 
> 建立事务开发规范，从源头避免失效。

## 九、总结

### 🎯 一句话总结

> **事务失效 = AOP代理（同类自调用） + 异常处理（吞异常/类型不匹配） + 传播行为（REQUIRED/REQUIRES_NEW） + 多线程（ThreadLocal隔离） + 多数据源（指定管理器）**

### 🧠 核心记忆点

1. **AOP代理**：同类自调用绕过代理
2. **异常处理**：吞异常、类型不匹配
3. **传播行为**：REQUIRED 共享，REQUIRES_NEW 独立
4. **多线程**：ThreadLocal 隔离
5. **多数据源**：指定事务管理器
