# 分布式全局唯一ID

> **场景定位**：分布式系统技术场景  
> **核心设计要点**：雪花算法、时钟回拨、workerID分配、去重校验

---

## 🎯 一句话定位

**分布式全局唯一ID解决什么问题？**
```
雪花算法生成订单主键ID
服务器时间校准后
不同节点生成的ID出现重叠
数据库主键冲突
```

**生活化比喻**：
就像身份证号：
- 每个人独一无二（唯一ID）
- 但如果时钟回拨（时间校准）
- 可能生成重复号码

---

## 💎 核心观点（5 分钟速览版）

### 核心观点（5 个关键点）

**1. 雪花算法不是万能的**
```
❌ 误区：雪花算法就保证唯一
✅ 真相：时钟回拨、workerID冲突
机器扩容都会导致重复
```

**2. 业务分级**
```
强唯一：订单号、支付流水、资金账单
→ 高可靠方案，零容忍重复
非核心：日志ID、消息标识
→ 轻量方案，极低概率重复
```

**3. workerID统一分配**
```
独立注册中心
服务启动自动申请
杜绝人工配置重复
```

**4. 时钟回拨容错**
```
小幅回拨：等待时间追上
大幅回拨：切换备用号段
拒绝生成重复ID
```

**5. 生成前去重校验**
```
核心ID生成后
先经分布式缓存校验唯一性
确认无冲突再返回
```

## 一、雪花算法隐患

### ❌ 典型事故

```
雪花算法生成订单主键ID

问题：
1. 机房服务器时间校准
2. 时钟回拨
3. 不同节点生成的ID出现重叠
4. 数据库主键冲突
5. 支付流水、物流单出现重复号

根因：时钟回拨导致ID重复
```

## 四、时钟回拨容错

```go
// 时钟回拨检测
type ClockMonitor struct {
    lastTimestamp int64
}

func (m *ClockMonitor) GenerateID() (string, error) {
    now := time.Now().UnixNano() / 1e6
    
    // 1. 检测时钟回拨
    if now < m.lastTimestamp {
        // 2. 小幅回拨：等待时间追上
        if m.lastTimestamp-now < 5 {
            time.Sleep(time.Duration(m.lastTimestamp-now) * time.Millisecond)
            now = time.Now().UnixNano() / 1e6
        } else {
            // 3. 大幅回拨：切换备用号段
            return generateWithBackupSegment()
        }
    }
    
    // 4. 生成ID
    id := doGenerate(now)
    m.lastTimestamp = now
    
    return id, nil
}
```

## 五、生成前去重校验

```go
// 核心ID生成后校验
func GenerateCoreIDWithCheck() (string, error) {
    // 1. 生成ID
    id := generateID()
    
    // 2. 分布式缓存校验唯一性
    exists := redis.Exists(fmt.Sprintf("id:%s", id))
    if exists {
        // 冲突，重新生成
        return GenerateCoreIDWithCheck()
    }
    
    // 3. 记录已生成
    redis.Set(fmt.Sprintf("id:%s", id), "1", 24*time.Hour)
    
    // 4. 确认无冲突再返回
    return id, nil
}
```

## 六、熔断兜底

```go
// 熔断模式兜底
type IDGenerator struct {
    snowflake  *Snowflake
    database   *Database
    useBackup  bool
}

func (g *IDGenerator) Generate() (string, error) {
    // 1. 雪花算法异常时自动切换
    if g.useBackup {
        // 2. 数据库熔断生成方案
        return g.database.GenerateID()
    }
    
    // 3. 正常雪花算法
    id, err := g.snowflake.Generate()
    if err != nil {
        // 4. 切换备用方案
        g.useBackup = true
        return g.database.GenerateID()
    }
    
    return id, nil
}
```

九、技术深入探讨

### Q1: 雪花算法时钟回拨怎么处理？

**方案参考**：
> 时钟回拨容错方案：
> 
> 1. **小幅回拨**：等待时间追上，Sleep等待
> 2. **大幅回拨**：切换备用号段，拒绝生成重复ID
> 3. **workerID统一分配**：独立注册中心，服务启动自动申请
> 4. **生成前去重**：分布式缓存校验唯一性
> 
> 核心是时钟检测 + 备用号段。

### Q2: 如何保证分布式ID绝对唯一？

**方案参考**：
> 保证分布式ID唯一：
> 
> 1. **业务分级**：强唯一场景高可靠方案，非核心轻量方案
> 2. **workerID统一**：注册中心自动分配，杜绝人工重复
> 3. **时钟回拨容错**：小幅等待，大幅切换备用号段
> 4. **去重校验**：生成后分布式缓存校验
> 5. **熔断兜底**：雪花异常切换数据库生成
> 
> 核心是全链路防护。
