# 对比单 Agent，多 Agent 场景幻觉会变多还是变少？解释原因。

> 面向生产环境的多 Agent 系统设计 · 第 8 问

---

## 核心问题

对比单 Agent，多 Agent 场景幻觉会变多还是变少？解释原因。

---

## 核心结论

**架构决定方向——无验证的串行链路会显著放大幻觉；带边界验证的并行/评审架构可以减少幻觉。数量本身不是变量，拓扑和验证点位置才是。**

多 Agent 把幻觉从**检测问题**变成了**传播控制问题**。

---

## 变多的机制（放大效应）

### 1. 错误复合（error compounding）

**原理**：串行流水线中每个 Agent 的输出是下一个的"信任输入"

**计算**：
- 单步 5% 事实错误率
- 4 Agent 链至少出一次错的概率 = 1 − 0.95⁴ ≈ **18.5%**
- 6 Agent 链升至 **26.5%**
- 单步 10% 时 4 Agent 链达 **34.4%**

**结论**：链路越长，错误累积越快

---

### 2. 幻觉雪球（hallucination snowball）

**原理**：幻觉不是原样传递而是**变形洗白**

**变形过程**：
```
原始事实 → 派生计算 → 叙事化 → 编辑背书
```

**检测率衰减**：
- 实测 gpt-4o 从 **72% 跌到 50.9%**
- **23.7% 的注入幻觉最终完全不可检测**

**关键洞察**：
- 上游幻觉被下游当作 ground truth
- 越早进入破坏越大
- 越晚进入越难发现

---

### 3. 上下文污染

**原理**：一个 Agent 的错误推理进入同伴上下文后产生**锚定**（latent synchronization）

**后果**：
- 同底座模型集体复制同一错误
- **Sybil-thought / 假共识**

---

### 4. 责任稀释

**原理**：
- 单 Agent 时错误在唯一输出里可见
- 多 Agent 时错误埋在多层"表面自洽"的推理之下

**后果**：
- 错误更难定位
- 责任更难追溯

---

## 变少的机制（抑制效应）

### 1. 分工收窄幻觉面

**原理**：
- 子 Agent 上下文更聚焦
- 工具更少
- 职责单一

**效果**：单 Agent 幻觉率下降（路径依赖降低、探索轨迹独立）

---

### 2. 交叉验证

**方法**：
- 并行独立产出 + 裁决/评审可捕获单点错误
- **异构模型 ensemble** 的盲区不重叠

**效果**：单点错误被多方校验捕获

---

### 3. 边界门控

**方法**：
- 在交接处做**接地验证**（对照源文档、可执行校验）

**效果**：
- 实测可将幻觉存活率从 **58.4% 压到 16.2%**

**关键洞察**：
> 验证点位置比验证次数更重要

---

### 4. 逐轮修订净衰减

**研究观察**：
- 级联中的幻觉分数逐轮修订净衰减（0.422 → 0.272）
- 但伴随**事实保真度的小幅损失**

**张力**：
> "减幻觉"与"保事实"存在张力，不能只看单一指标。

---

## 面试表述建议

> "多 Agent 把幻觉从**检测问题**变成了**传播控制问题**。我的设计准则是：
> 1. Agent 间传递的每个中间产物都要**可验证**
> 2. 验证放在**交接处**而非终点
> 3. 保持裁决者的**独立性**（异构模型 + 双盲）
> 
> 满足这些条件多 Agent 可以比单 Agent 更可靠；不满足，它就是幻觉的放大器。"

---

## 生活化比喻

把多 Agent 幻觉传播想象成**传话游戏**：

| 场景 | 结果 |
|------|------|
| **无验证的串行链路** | 第一个人说错，后面越来越离谱（幻觉雪球） |
| **带边界验证的并行架构** | 每个人独立验证，错误在交接处被捕获 |

**关键**：
- 无验证 → 错误累积
- 有验证 → 错误抑制

---

## 一句话总结

> 多 Agent 场景幻觉变多还是变少，**架构决定方向**。无验证的串行链路会**显著放大**幻觉；带边界验证的并行/评审架构可以**减少**幻觉。记住：**数量本身不是变量，拓扑和验证点位置才是**。
