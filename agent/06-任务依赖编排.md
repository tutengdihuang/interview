# 多 Agent 体系如何做任务依赖编排？

> 面向生产环境的多 Agent 系统设计 · 第 6 问

---

## 核心问题

多 Agent 体系如何做任务依赖编排？静态依赖和动态依赖如何处理？

---

## 核心结论

**静态依赖用显式 DAG，动态依赖用运行时规划，两者通常混合**。生产推荐形态是**分层编排**——高层 DAG 粗粒度分阶段，每个阶段内部可以是一个子编排器自主决定细节。兼顾可预测性与灵活性。

---

## 编排方式：三种模式

### 1. 静态编排：显式 DAG（流程可预知时）

**适用场景**：流程固定、依赖关系明确

**方法**：
- 把任务声明为**图节点**，依赖为**边**
- **拓扑排序**决定执行顺序
- 无依赖的分支**并行扇出（fan-out）**
- 汇聚点做**扇入（fan-in）**

**典型实现**：
| 工具 | 特点 |
|------|------|
| **LangGraph** | 状态图，适合 LLM Agent |
| **Temporal** | 持久化执行，适合长时间任务 |
| **Airflow** | 工作流编排，适合数据处理 |

**必备工程能力**：
1. **checkpoint 持久化**
   - 失败从断点恢复而非全量重跑
2. **超时/取消传播**
   - 上游失败时下游能感知
3. **重试策略**
   - 不同节点可配不同重试逻辑
4. **环检测**
   - 防止循环依赖导致死锁

**优点**：
- 可预测、可审计
- 易调试

**缺点**：
- 灵活性差
- 无法应对动态任务

---

### 2. 动态编排：运行时规划（流程不可预知时）

**适用场景**：开放性任务（研究类）

**方法**：
- **协调者先规划再执行**：
  1. 分析任务
  2. 产出计划
  3. 按计划生成带依赖关系的子任务
  4. 执行中根据中间结果**修订计划**（新增/取消分支）

**Anthropic 的实践**：
- 主控 Agent 用**扩展思考**做规划
- **计划持久化到 Memory**（防止上下文超 200k 被截断后丢失计划）
- 子 Agent 结果回来后决定是否补充研究

**优点**：
- 灵活性高
- 能适应动态任务

**缺点**：
- 可预测性差
- 调试困难

---

### 3. 分层编排（生产推荐形态）

**核心思想**：结合静态和动态的优点

**方法**：
- **高层 DAG** 粗粒度分阶段
- 每个阶段内部可以是一个**子编排器**自主决定细节

**例子**：
```
高层 DAG（静态）：
  阶段 1: 数据收集
  阶段 2: 数据分析
  阶段 3: 报告生成

阶段 2 内部（动态）：
  子编排器根据数据特点决定分析策略
  - 如果是结构化数据 → 统计分析
  - 如果是文本数据 → NLP 分析
```

**优点**：
- **兼顾可预测性与灵活性**
- 高层可控，底层灵活

---

## 关键设计点

### 1. 节点间状态强类型化

**方法**：
- 每个节点声明**输入/输出 Schema**
- DAG 的边就是**类型校验的边界**

**为什么重要**：
- 这是防"传话失真"的工程手段（对应第 2 题的硬性边界）
- 类型不匹配在编译期就能发现

---

### 2. 依赖不仅是"先后"

**依赖类型**：
| 类型 | 描述 | 例子 |
|------|------|------|
| **数据依赖** | B 需要 A 的产物 | 分析 Agent 需要检索 Agent 的文档 |
| **资源依赖** | 互斥使用某个工具/配额 | 两个 Agent 不能同时调用同一 API |
| **人工节点** | human-in-the-loop 作为一等公民节点 | 关键决策需要人工审批 |

---

### 3. 失败语义

**问题**：上游失败时下游如何处理？

**策略**：
| 策略 | 适用场景 |
|------|---------|
| **跳过** | 下游任务依赖上游成功 |
| **降级** | 下游可以用默认值替代 |
| **阻塞** | 必须等待上游恢复 |

**关键**：需要在编排层**显式声明**，而非隐式处理

---

## 面试加分项

1. **类比数据库事务的隔离级别**：
   - 谈子任务失败传播策略
   - 不同隔离级别对应不同的失败处理策略

2. **指出协议层趋势**：
   > A2A / MCP 等协议层标准正在把"跨进程编排"变成与"进程内编排"同构的问题。

---

## 生活化比喻

把多 Agent 任务编排想象成**建筑工程管理**：

| 编排方式 | 建筑类比 |
|---------|---------|
| **静态 DAG** | 按图纸施工（流程固定） |
| **动态编排** | 根据现场情况调整方案（灵活应变） |
| **分层编排** | 总体进度计划 + 各工种自主安排（兼顾可控与灵活） |

**关键设计点**：
- **强类型化** = 工人交接时必须验收工程质量
- **依赖类型** = 材料依赖、设备依赖、人工审批
- **失败语义** = 上游延误时下游是等待、跳过还是降级

---

## 一句话总结

> 任务依赖编排的核心是：**静态依赖用显式 DAG，动态依赖用运行时规划，生产推荐分层编排**（高层 DAG + 阶段内自主）。关键设计点：**节点间状态强类型化、依赖类型多样化、失败语义显式声明**。
